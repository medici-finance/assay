# Local perf-v3 contract

This version is implemented for local library users; integration and human acceptance remain
separate. Existing `ASSAY_TELEMETRY=1` without a selected profile keeps the producer's old
schema. `ASSAY_PERF_PROFILE=tool|workflow` or its parsed flag selects v3 only with that exact
telemetry switch. Empty or `off` falls back to legacy; an invalid profile disables v3.
No profile sends anything or changes an operation's authority or result.

All attribution, including syntactically valid attribution, is self-asserted and
unauthenticated. A role or work label must never become an identity proof or drive a gate,
budget, custody, claim or completion decision. Those remain with their existing authenticated
operational owners; a local performance record grants no authority.

`ResolveContext(ContextInput)` reads only the documented named environment keys and the
parsed values supplied by the adapter. `Value.Present` distinguishes absent from empty.
Flag values replace environment values, including explicit empty clearing. Repeated work
flags replace the entire environment list. Invalid values become `invalid` coverage with
no copied input. Context getters return copies. `NewID` uses 128 random bits, encoded as
32 lowercase hex characters; `IDValid` checks that encoding. IDs are caller supplied except
for the fresh invocation ID. No Git, branch, process ID or native harness search occurs.

`BeginSelected(probe, mark, phaseRoster, context)` uses the same interval and CPU semantics
as v2. `Session.SelectContext(context)` selects once, allowing an actual parser to supply
context before effects. `BeginObservation(probe, roster, context, kind)` takes its own caller-boundary mark
and disables whole-process CPU for concurrent handler/client/provider intervals.
`Finish` returns one `Record`, then the existing best-effort writer appends it. Do not call
`Finish` more than once per invocation. A nil session is safe. `deskkit.PerfRunMeasured`
passes a session explicitly to a parser callback; no global attribution or request sink is
used. Adapters own their existing effect boundaries and credentials.

## Wire shape and bounds

A v3 line uses the v2 interval fields unchanged, `schema: perf-v3`, and one additional
`v3` object. v1/v2 reject that object and keep their exact frozen field sets. Unknown keys,
invalid enums, missing coverage and profile-incompatible fields fail decoding. Writer and
decoder independently validate hand-built records, even when the resolver is bypassed.

| v3 field | Meaning |
|---|---|
| `profile` | `tool` or `workflow`. |
| `attribution` | Fresh `invocationId`; optional `sessionId`, `agentId`, `parentAgentId`, `parentInvocationId`, `deskRole`, `role`, `work`; required `coverage`. |
| `observationKind` | `process-summary`, `service-client`, `service-handler`, `provider-work`. A record has one kind. No request-detail kind duplicates process aggregates. |
| `requests` | At most 64 unique groups of actual own transport attempts. |
| `requestCoverage` | `missing`, `measured`, `unsupported`, `failed`. Complete seams call `ObserveRequests`, including observed zero. Drops stay failed. |
| `requestDrops` | Invalid/excess groups discarded; a nonzero value requires failed request coverage. |
| `query` | Optional bounded client/handler observation, described below. |

Attribution coverage lists every optional field exactly once. States are `measured`,
`missing`, `invalid`, `unsupported`. Tool profile requires all workflow fields absent and
all their coverage unsupported; its top-level role is `none`. Workflow `role` is assigned
execution function (`coordinate`, `implement`, `review`, `verify`, `triage`, `investigate`,
`other`), independent of `deskRole` (`the-desk`, `worker-desk`, `pr-review-desk`,
`verify-desk`, `intake-desk`). Missing role stays absent with missing coverage and the
shared top-level role is `none`.

Work has at most eight references, at most one primary. The whole input is at most 4096
bytes. Repository identity is `owner/name`, bounded to 100 characters each, excluding
path traversal. Issue identity includes `forge` (`github` or `gitlab`), lowercase DNS
`instance` (at most 253 bytes), repo and positive signed-32-bit issue number. A brief uses
repo and qualified `cell:repo:stream:number` (lowercase label components at most 40 bytes,
positive number at most nine digits), with optional lowercase hyphenated `briefUuid`.
Kinds cannot carry each other's fields. Duplicate locators are invalid.

One `--perf-work` flag contains one JSON object, for example:

```json
{"kind":"brief","repo":"example/project","brief":"demo:project:delivery:7","primary":true}
```

A second flag can link its issue:

```json
{"kind":"issue","forge":"github","instance":"github.com","repo":"example/project","issue":42}
```

`ASSAY_PERF_WORK` is a JSON array of the same objects. `--perf-work=` clears it. Arbitrary
strings, unknown keys, raw URLs, issue zero, multiple primary subjects and mixed brief/issue
fields are invalid. Two issues numbered 42 in different repositories or instances stay
separate. These qualified locators are identifiable local data, never anonymous telemetry.

## Request observations

`Session.ObserveRequest(RequestObservation)` receives only bounded typed metadata for an
actual completed own attempt; no URLs, response bodies, GraphQL text/variables, keys,
credential material or free-form errors are representable. Fields:

- Class: `provider`, `authentication`, `service`.
- Origin: `direct`, `service-passthrough`, `refresh`, `poll`, `repair`, `unknown`.
- Protocol: `rest`, `graphql`, `http`, `local`.
- Resource: `core`, `search`, `graphql`, `complexity`, `authentication`, `service`, `unknown`.
- Outcome: `2xx`, `3xx`, `304`, `4xx`, `5xx`, `error`, `cancelled`, `timeout`.
- Duration coverage: `measured`, `missing`, `unsupported`, `failed`; only measured has
  nonnegative `durationMs`, timed by the adapter through body EOF/close or terminal error.
- Optional nonnegative bytes; absence is unavailable.
- Points: coverage (`measured`, `estimated`, `unknown`, `unsupported`, `failed`, `missing`),
  unit (`github-points`, `gitlab-complexity`, `none`), optional nonnegative value. Only
  measured/estimated have a value; estimates require bounded label-shaped method/version.
  Non-provider traffic cannot have points. Units remain distinct. Shared quota gauges have
  no field here and cannot become charges.

RequestStats groups by class/origin/protocol/resource/outcome and point coverage/unit/method/
version. It preserves attempts, point samples, duration coverage counts, sum/max and 32
mergeable log2-ms bins: 0ms, 1ms, 2–3ms, 4–7ms, up to the last overflow bin. Missing durations
are never inserted as zero. Bytes preserve a measured sample count. Duplicate group keys
in hand-built records are rejected. Overflows of the group bound increment drops and leave
failed coverage. Estimates never merge with measured points; missing cost is never zero.

## Query/cache observations

`SetQuery` accepts a fixed operation (`query`, `source-query`, `mirror-read`, `refresh`,
`poll`, `repair`, `other`), client logical calls and transport attempts, and handler own
provider-attempt coverage. Only a client counts logical queries; handler counts are separate.
A client cannot claim measured upstream attempts from a successful service response.
Handler measured zero requires a covered seam. Source is `hit`, `miss`, `stale`, `bypass`,
`unavailable`; coalescing is `none`, `leader`, `waiter`, `failed`, `abandoned`, `unavailable`.
Result is `ok`, `partial`, `stale`, `denied`, `error`, `cancelled`, `timeout`, `unknown`.
Optional opaque diagnostic/parent IDs require workflow consent. They do not authorize sending
headers: only an admitted typed service protocol with consent at both ends may propagate
links, owned by its service integration. No actual service or propagation is implemented here.

## Local readers and export boundary

`ReduceV3` deduplicates by install/invocation before filters. Exact replay counts once;
conflicting replay identities are exposed and excluded completely. Missing install/invocation
is invalid. `SelectV3` returns exactly the set `ReduceV3` aggregates; a reader that buckets v3
records (by day, by tool) selects over the whole input first, then buckets the kept records. Work/session/agent/deskRole/role grouping or filtering requires workflow permission.
Default tool grouping exposes no raw workflow references. v1/v2 remain separate report groups.
Only process summaries contribute own-process wall/CPU; phases, children, handlers, refreshes
and request durations are never added into elapsed time. The client/server views of one query
are not two logical calls; shared refresh points are never copied per waiter. Cache coverage,
missing server data and incomplete request seams remain visible.

`deskperf report --json` adds `perfV3` only when v3 data or conflicts exist. Attribution reads
use `--perf-profile workflow` (or the named environment value), `--group-by`, and optional
session/agent/desk-role/assigned-role/typed-work filters. Legacy `--role` retains its old
meaning and excludes v3 records; use `--assigned-role` for the workflow-aware v3 filter.
These never make provider calls. `ASSAY_PERF_PROFILE=workflow` grants reader permission
as well as selecting producer disclosure: a shell or agent inheriting it can print work and
agent/session identifiers by explicitly choosing a workflow grouping or filter. This output
is identifiable local diagnostic data. Reader permission does not authorize publication or
export; the separate aliasing and export-consent boundary still applies.

Files retain seven UTC days, 0700 directories and 0600 regular files. Before appending, v3
checks its existing directory and direct sink files for symbolic
links and refuses non-regular sink files. This is a best-effort `Lstat`-then-open check,
not atomic protection against a concurrent process running as the same operating-system
user replacing a file between those operations. The future perfdata importer must independently
obtain
workflow consent and alias raw local references before spool, preview or upload. There is
no sender, alias mapper, spool, service, new credential read or operational accounting here.

Request summaries retain `observationKind` in every reduced request group. A reporter must
keep these kinds separate; matching aggregate labels across kinds do not prove that attempts
are disjoint. Empty work arrays clear attribution with missing coverage; JSON null is invalid.
