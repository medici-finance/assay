# Issue 4437 — one selected-closure validator

Resolution claim: `brief --check-verified` and `verifyclosure` call
`checkSelectedClosure`; both share `failFirstClosureChecks` with flip lint.
Risk-bearing rows require a current discriminating Base witness with acceptable
base provenance. Both explicit checks require non-empty applicable Verify rows
and a human stamp for human-classed rows. Corpus lint keeps its transition scope;
CLI resolution, exit codes, attribution and landing authorization stay in their
existing adapters.

Evidence: the three-entrypoint cases in
`TestBriefInfoFailFirstMatchesFlipLint` cover missing/not-selected Base cells,
green/unproven bases, invalid ancestry, passing red bases, latest reruns,
brief-wide risk, ordinary non-risk rows and unplaced Verify rows.
`TestClosureAdaptersAgree` covers empty rows and human-row stamps. These cases
fail against the old sidecar checker and pass through the shared validator.

This is an implementation claim for independent review and human merge.
