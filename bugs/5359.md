# Issue 5359 — CI forge reads recover after an observed quota reset

The read-only REST client and four PR corroboration CLI reads share a bounded
CI wait budget. A positive quota refusal waits until the provider reset and
retries the same read once using its original credential environment. The
provider error remains visible when the read cannot recover; explicit
credential values are redacted from CLI diagnostics. Permission failures,
missing quota evidence, repeated denial and an exhausted budget remain errors.

Offline regression tests cover primary and secondary quota headers, cancellation,
permission errors, a repeated denial, oversized or missing reset data, a shared
wait budget, REST versus GraphQL quota selection, credential substitution attempts
and immediate non-CI behavior. The feature is source-level until released and
adopted by consumers; it does not claim that any running workflow was upgraded.
