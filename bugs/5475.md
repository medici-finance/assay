# Issue 5475 — historical brief reads use the tracking snapshot

Reconciliation now selects a v2 cross-repository run's tracking-source for the
brief-version read after the existing selected-run closure and verifier
provenance checks. The source SHA remains the witness identity. The selector
requires consistent literal current-run attestations, full source/tracking IDs,
a matching source prefix, and the current tracking repository and brief path.
Same-repository/legacy reads retain their source-revision behavior.

When the selected run binds nothing, a cross-repository attestation line
anywhere in Evidence (fenced, quoted, indented, commented or from an older run)
makes the read unknown instead of falling back to the source revision; a
source-revision read is only correct for a brief with no such record.

Offline two-repository regressions cover valid and duplicated attestations,
stale versions, missing history, wrong repository/path/source, malformed or
conflicting metadata, quoted/older-run metadata and legacy compatibility. The
quoted and older-run cases also run with the foreign source object present
locally, so they fail on the selector and not on a missing object. The old
reader is observed red for the ordinary cross-repository case and for the
case where a foreign source object is locally available while tracking history
is missing. The fixed reader preserves the version mismatch demotion.

The source change must be released and adopted before installed consumers use it.
