# Issue 3342 — protected-table closure accounting

Resolution claim: closure readers share one immutable-history evaluator. A
supplemental row receives an explicit author-added disposition, never acceptance
pass credit. Every original row remains owed. The delivery snapshot, exact
baseline and original re-derivation table must agree; ordinary row labels cannot
exempt original acceptance. Existing independent verifier attribution remains.

Evidence: the protected closure regression builds real squash and merge histories,
then checks original-row pass, command/expect edits, missing/duplicate/quoted/fenced
provenance, missing objects, changed tables, original failure/absence, and false
supplemental pass claims through the closure and audit entrypoints. The unfixed
code rejects the valid supplemental case and accepts false pass credit.

Consumers: brief closure, witness audit, closure CLI, verified flip, reconciliation
fold, coverage observation and lint share the evaluator; fail-first and row-strength
lint read the original table. Coverage carries the validated original definition
revision explicitly, reads its real Expect, and preserves the witness's execution
revision and content applicability. Invalid provenance supplies an explicit held
claim. Evaluator generation 2 identifies this observation contract extension.
Flip and reconciliation retain full protected context through the shared run
adapter while ordinary records remain isolated to the selected run. Direct
consumer regressions exercise the actual flip, fold, lifecycle overlay and
closure/audit/lint agreement; refused flips leave the README stamp untouched.
Marker classification and validation use one normalized view, with selected-run
normalization explicit. Ordinary isolation tests remove the whole witness row and
assert the missing-witness audit, preserving parser and source controls.
Operator production guidance lives in docs/protected-paths.md.
Follow-up regressions retain multiple complete runs and refuse failed, incomplete
or ambiguous current runs without borrowing earlier witnesses or provenance.
The delivery must lie on the observed HEAD first-parent chain, not merely be a
reachable ancestor; local immutable provenance does not authenticate forge
delivery identity. Two-parent histories require the pre-delivery main acceptance definition to match
the divergence baseline before any supplemental disposition. Both existing
mutation controls are re-anchored and retained.
