# Issue 4431 — pre-flip fail-first validation agrees with flip lint

Resolution claim: `statusgen brief --check-verified` and the fail-first lint gate
used by `deskevidence flip` both call `failFirstClosureChecks`. The shared
validator checks the latest witness, risk selection, Base state, base ancestry,
brief presence at base, and unplaced Verify rows against the protected acceptance
plan. The selected closure check does not grandfather inherited closures; lint
retains its existing transition scope and degraded-history notices.

Evidence: `TestBriefInfoFailFirstMatchesFlipLint` exercises both entry points
with missing and not-selected Base cells, green and unproven base runs, head and
unrelated bases, valid red runs, an older base holding the brief, ordinary reruns,
brief-wide risk, non-risk rows, and unplaced Verify rows.
`TestBriefInfoFailFirstDoesNotGrandfatherSelectedClosure` preserves the distinction
between inherited lint scope and explicit closure acceptance.
