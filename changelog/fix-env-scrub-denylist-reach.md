### Changed
- `statusgen verifyrun`: an admitted row's environment is now built from an allow-list instead of a deny-list. An inherited variable reaches the row only when it is the search path, the account and shell names (`USER`, `LOGNAME`, `SHELL`), the bare `CI` flag, a locale or terminal setting, a Go toolchain setting, a proxy or trust-root setting, a Windows system location, or one of the two delivery coordinates. Every other variable is dropped, so a credential pointer in a family nobody named (another forge's or tool's, an agent socket, a runtime directory, a Windows profile location, a CI runtime variable such as `GITHUB_ACTIONS`) no longer reaches a row by default. A listed proxy or module proxy whose URL carries a user name is dropped too. The existing named refusals still apply first. A Verify row that relied on another inherited variable under admission now sees it unset; on GitHub Actions that includes `GITHUB_ACTIONS`, so code inside an admitted row that detects CI from it treats the run as not-CI.
- `docs/verify-row-strength.md` gains "What an admitted row can reach": the same-user reach that remains (files by path, the checkout's git config, the account's home, same-user local endpoints, other processes' environments) and a design note for a credential-less runner. Nothing there widens what a row can reach.
