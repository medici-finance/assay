### Changed
- `statusgen verifyrun`: an admitted row's environment is now built from an allow-list instead of a deny-list. An inherited variable reaches the row only when it is the search path, the account and shell names (`USER`, `LOGNAME`, `SHELL`), the bare `CI` flag, a locale or terminal setting, a Go toolchain setting, a proxy or trust-root setting, a Windows system location, or a delivery coordinate (`ASSAY_DELIVERY_SHA`, `ASSAY_DELIVERY_BASE_SHA`, or the unprefixed `DELIVERY_HEAD`/`DELIVERY_BASE` pair, each only while it holds a full commit id). Every other variable is dropped, so a credential pointer in a family nobody named (another forge's or tool's, an agent socket, a runtime directory, a Windows profile location, a CI runtime variable such as `GITHUB_ACTIONS`) no longer reaches a row by default. A listed proxy or module proxy whose URL carries a user name is dropped too. The existing named refusals still apply first. A Verify row that relied on another inherited variable under admission now sees it unset; on GitHub Actions that includes `GITHUB_ACTIONS`, so code inside an admitted row that detects CI from it treats the run as not-CI. The unprefixed pair is kept so the consumer-diff rows that read it (desk-tools briefs 46-53, 55-57, 59 and 61-65) still see the delivery instead of failing at their own `test -n`.
- `docs/verify-row-strength.md` gains "What an admitted row can reach": the same-user reach that remains (files by path, the checkout's git config, the account's home, same-user local endpoints, other processes' environments, and on Windows the user's own `TEMP`/`TMP`) and a design note for a credential-less runner. Nothing there widens what a row can reach.
