### Changed
- `statusgen verifyrun`: an admitted row's environment is now built from an allow-list instead of a deny-list. An inherited variable reaches the row only when it is the search path, the account and shell names (`USER`, `LOGNAME`, `SHELL`), the bare `CI` flag, a locale or terminal setting, a Go toolchain setting, a proxy or trust-root setting, a Windows system location, or a delivery coordinate (`ASSAY_DELIVERY_SHA`, `ASSAY_DELIVERY_BASE_SHA`, or the unprefixed `DELIVERY_HEAD`/`DELIVERY_BASE` pair, each only while it holds a full commit id). Every other variable is dropped, so a credential pointer in a family nobody named (another forge's or tool's, an agent socket, a runtime directory, a Windows profile location, a CI runtime variable such as `GITHUB_ACTIONS`) no longer reaches a row by default. A listed proxy or module proxy whose URL carries a user name is dropped too. The existing named refusals still apply first. A Verify row that relied on another inherited variable under admission now sees it unset, unless it reads that variable by name (`$NAME`, `${NAME}`, `$env:NAME` or `%NAME%`), in which case it is recorded could-not-run with a note naming the variable, as a row that reads a dropped `ASSAY_*` variable already was; the rule counts only a capitalised variable the row merely reads, and leaves out shell and run variables, the names dropped before the allow-list (forge credentials, `GH_*`, `GIT_*`) and a name the row assigns or names bare. The rows that read such a variable today, in briefs awaiting verification, are in desk-tools 03 (the `DT03_*` kit and sweep variables) and 34 (`VERIFY_BASE`), desktools-v2 03 (`D`), forge-neutral 57 (`AUTH57_ENGINE_ENDPOINT`), desk-supervision 09 (`PR`) and 24 (`SIBLING_PR`), harness-portability 14 (`SWEEP`, `TOKENS`, `CANARY`) and forge-gitlab 12 (`GITLAB_API_BASE`), plus derived-board 11 (`DELIVERY`) on re-verification; each is could-not-run under admission until its row names its inputs or its author amends it. On GitHub Actions the dropped variables include `GITHUB_ACTIONS`, so a program an admitted row starts that detects CI from it treats the run as not-CI. The unprefixed pair is kept so the consumer-diff rows that read it (desk-tools briefs 46-53, 55-57, 59 and 61-65) still see the delivery instead of failing at their own `test -n`.
- `docs/verify-row-strength.md` gains "What an admitted row can reach": the same-user reach that remains (files by path, the checkout's git config, the account's home, same-user local endpoints, other processes' environments, and on Windows the user's own `TEMP`/`TMP`) and a design note for a credential-less runner. Nothing there widens what a row can reach.
