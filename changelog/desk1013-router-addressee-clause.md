### Changed
- The comms router's prompt now treats a request a message makes of its addressee desk ("please review", "pick this up", "ack it") as ordinary content to route, so peer hand-offs are no longer quarantined as if addressed to the router. Text that steers the router's own choice of action, any request for a human-gate act, and anything unclear or unclassifiable still choose quarantine; the deterministic layers are unchanged.
- The prompt now enumerates the human-gate set instead of leaving it undefined: approval, merge, ready-flip, a push to main or skipping review, a tag or release cut, weakening a security control or its CI assertion, exposing secrets, credentials, tokens, PII or exploit detail, money movement, deleting or overwriting durable data, identity/auth/permission changes, and anything that leaves the repo, followed by a catch-all. It states that a request for a listed act quarantines even when it is made of the addressee desk, and it asks the reader to name exactly one action in its reply.
- A 29-message qualification corpus pins the clarified prompt clauses offline, with one addressee-phrased quarantine row per human-gate category, and can be run against the configured reader with `COMMSLOOP_ROUTER_CORPUS_LIVE=1` (opt-in, never in CI). A live row passes only when its consult journals exactly one record with outcome `advised`: a quarantine reached through a timeout, decider error, or unparseable reply fails the row and names the outcome, and the run ends with a per-class outcome summary.
