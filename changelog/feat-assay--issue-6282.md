### Fixed
- `scanloop` now cuts its scan worktrees under the sanctioned worktree prefix that `deskwt add` itself targets (the tmp base on POSIX, with the leaf prefix `deskwt` requires there; `<repo-root>/.claude/worktrees` on Windows) instead of beside `--root`, so a scan worktree the lane retains after a failure can be removed with `deskwt remove`. `deskwt`'s prefix list is unchanged. The prefix rule now lives in one shared function that `deskwt` and `deskdispatch` call, and `scanloop` places its worktrees using the same shared constants. On a POSIX host without the tmp base (a stock Linux), the default is refused up front and names `--worktree-base`. On Windows, running from the main checkout is refused with guidance, because the sanctioned prefix there sits inside the checkout being scanned. `--worktree-base` still overrides the default.
- A coalescing scan pass no longer exits 6 when an earlier pass's retained scan worktree still holds the carrier branch. If that worktree is a scan worktree, is clean and sits exactly at the remote carrier tip, the pass carries on in it. A worktree with the old pre-move name is adopted only at the old location beside `--root`. A dirty, diverged or foreign worktree refuses the pass (exit 5) with the reason named and is left untouched. A reused worktree is removed at the end of the pass, and that removal also deletes its gitignored files.
- `scanloop` writes the derived scan PR title and body into a private, randomly named `0700` directory it creates for each carry and removes afterwards. They no longer sit at a predictable name beside the scan worktree in the shared tmp base, where another local account could plant a symlink or a file of its own there first.
