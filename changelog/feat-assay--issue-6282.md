### Fixed
- `scanloop` now cuts its scan worktrees under the sanctioned worktree prefix that `deskwt add` itself targets (`tracker-intake-scan-<pass>` under the tmp base on POSIX, `<repo-root>/.claude/worktrees` on Windows) instead of beside `--root`, so a scan worktree the lane retains after a failure can be removed with `deskwt remove`. `deskwt`'s prefix list is unchanged; the rule now lives in one shared function that `deskwt`, `deskdispatch` and `scanloop` all call. On Windows, running from the main checkout is refused with guidance, because the sanctioned prefix there sits inside the checkout being scanned. `--worktree-base` still overrides the default.
- A coalescing scan pass no longer exits 6 when an earlier pass's retained scan worktree still holds the carrier branch. If that worktree is a scan worktree, is clean and sits exactly at the remote carrier tip, the pass carries on in it. A dirty, diverged or foreign worktree refuses the pass (exit 5) with the reason named and is left untouched.
