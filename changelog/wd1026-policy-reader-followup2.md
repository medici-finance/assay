### Fixed
- Brief frontmatter keys `implementer`, `blocked-until`, `verify-lane` and `in-repair` read an inline ` # comment` as part of the value again, as the work loops did before the shared parser, so `in-repair: no # note` keeps a brief in repair and `blocked-until: "" # note` keeps it deferred instead of making it dispatchable. That comment-kept reading is used only where its comment-cut form is the value the YAML parser reads; any other line shape for those keys is refused as a frontmatter disagreement, as before. The author-is-not-runner checks in fanoutloop and verifyloop match the `implementer` value both as read and with a trailing comment and any surrounding quotes cut, which is the value the YAML parser reads, and refuse when either names the runner, so a quoted implementer followed by a comment is refused too. This corrects the earlier note that the shared parser never reads a policy key differently from the line readers it replaced: `gate`, `exec-tier` and `effort` keep the comment-cut reading, because their earlier readers disagreed, and deskdispatch now reads `brief`, `exec-tier`, `effort`, `deliverable_repo` and `homed-in` from their own key only, never from a quoted sibling key whose text starts with the same name.
