### Changed
- The release image publisher now pushes every image by digest first, under a `staging-<version>` tag in its own repository, and attaches the version tags only after every push, including the verify-runner index, has succeeded. A failure during the pushes therefore leaves no version tag behind, and the same version can be published again instead of being burned.
- A version tag that already exists no longer stops the release before the build. After the pushes it is compared by digest: a tag that already names the digest this run pushed is left as it is, so a re-run whose rebuilt images have the same digests completes, and a tag that names any other digest still refuses the release before any tag moves. Each attached tag is read back and must name the pushed digest.
