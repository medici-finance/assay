### Added
- `loopadmin/journal`: the loop-admin execution journal on the cell's PostgreSQL coordination database, in its own `loopadmin` schema with forward-only migrations. Launch intent and its receipt commit in one transaction before a child starts, duplicates reconcile by stable request ID, a lost receipt holds as unknown instead of relaunching, and a missing or mismatched operator incarnation holds the journal paused until the operator activates a rotated incarnation with a confirmed execution-group stop. The module now depends on the pinned `pgx` driver and `goose` migration runner; a new guard refuses any embedded database engine in its closure.

### Changed
- The one process runner moved from `tools/desk/internal/cellprocess` into the `loopadmin` module as `loopadmin/process`, so the shared loop-admin supervisor and `cellctl` launch through the same code. A runner now exists only with an injected launch custodian and refuses to launch without one; `tools/desk/internal/cellrunner` binds the managed Go-cache custodian, and `cellctl`'s cadence, scratch, cache, comms and Git maintenance paths launch through it unchanged. The process-launch audit now scans `loopadmin/` as well, and the runner's exec-site entry is re-keyed to its new path.
