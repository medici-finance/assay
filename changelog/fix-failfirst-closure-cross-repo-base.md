### Fixed
- The fail-first closure gate (lint, `brief --check-verified`, `verifyclosure`) no longer refuses every valid cross-repository closure by looking the base up in the tracking clone. When the selected PASS run binds a literal cross-repository attestation, its fail-first base is resolved in the deliverable checkout configured for `source-repo=` (`DESK_ROOTS` or `--sibling-root`) and must equal the deliverable merge-base exactly: the merge-base of the attested `source=` commit and `origin/main` there. An older ancestor and any later commit are refused. When that merge-base is the source itself (`origin/main` already holds the change), every base is refused, the source included, matching `verifyrun`'s refusal of a cross-repository run whose merge-base is HEAD. An unconfigured checkout, two configured checkouts whose names differ only in letter case, an unresolvable merge-base or an unbound attestation stays a PROBLEM; same-repository runs are unchanged. The cross-repository anchor also applies the brief identity checks the brief-version read uses: the attestation's `repo=` must be the brief's own repository and `brief=` its repository-relative path, or the closure stays blocked. When the attestation itself is refused, the PROBLEM asks for a run that records a binding attestation rather than a checkout or `--base` change.
