### Fixed
- `statusgen verifyrun` in container-netns mode now records a Verify row that exits non-zero with no captured output as could-not-run, not fail, when the verify-runner image's module cache lacks requirements of the tree (#5766). A row that sends its `go test` output to a file or to /dev/null left nothing to name the missing module, so an environment fault was recorded as an observed failure. The reason names the gap and says the row's output was not captured. No row moves toward pass: exit 0 rows, rows with output naming no missing module, the unshare lane and runners without the baked-roots manifest keep their verdicts.
