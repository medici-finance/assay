### Fixed
- `deskflip` and `deskpost ready` now check GitHub's own merge verdict right after a ready flip, because ready should mean mergeable per the forge. If the PR's merge state is `BLOCKED` or `DIRTY`, they return it to draft once, post one comment naming the state and the head sha, and exit 5. If the return to draft fails, they say so and exit 6 without retrying. While the state reads `UNKNOWN` they re-read it for up to 30 seconds. If it is still `UNKNOWN` then, or cannot be read, the PR stays ready with a could-not-check comment and a could-not-verify notice. `CLEAN`, `HAS_HOOKS`, `UNSTABLE` and `BEHIND` leave the PR ready.
- The forge seam gains `ConvertToDraft` (GraphQL `convertPullRequestToDraft` on GitHub; the `Draft:` title prefix on GitLab). Only this post-flip check calls it, and it is not a verb of its own.
- The post-flip check reads the PR's draft flag with its merge state. GitHub reports a draft as `BLOCKED`, so a read that still shows the PR as a draft is treated like `UNKNOWN`: re-read, and never a revert. Still a draft at 30 seconds is could-not-check.
- The revert comment carries a hidden marker naming the head. `deskflip` gains a `not-reverted` condition: a trusted comment with that marker for the current head stops the flip as could-not-check (exit 6) and names the comment, so a reverted head is not flipped again on every tick. A new head clears it.
