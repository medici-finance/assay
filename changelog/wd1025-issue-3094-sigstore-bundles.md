### Added
- Releases now carry SLSA build provenance. The release job attests every published asset (binaries, tarballs, the Cursor bundle, the tool-validation pack, the image references and `checksums.txt`) with `actions/attest-build-provenance` on the public Sigstore instance, after `checksums.txt` is final and before the tag is pushed, and publishes the bundle beside each asset as `<asset>.sigstore.json`, the file `deskinstall` already fetches and verifies. Only the `release` job holds `id-token: write` and `attestations: write`. The release refuses to publish when any asset lacks its bundle, when a bundle does not name the asset's exact sha256, or when a bundle has a shape `deskinstall` would refuse, such as a Rekor v2-only log entry. The release notes no longer say the pipeline carries no provenance attestation, and they show how to check a bundle with `gh attestation verify`.
