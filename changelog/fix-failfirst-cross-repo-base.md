### Fixed
- `statusgen verifyrun --fail-first` now runs a cross-repository (version 2 receipt) fail-first on both lanes. The base must be the deliverable merge-base exactly, in place of the brief-held check; any other base is refused, and so is a run whose deliverable merge-base cannot be resolved. In the container lane `--history-pack` imports history for a brief that the receipt binds outside the home.
- A `--base` that cannot be checked against the merge-base of HEAD and origin/main (no origin/main in the clone) is now refused on every run, and a cross-repository run whose deliverable merge-base is HEAD itself (post-merge, or the container lane) is refused with exit 2 before any row runs.
- An unadmitted run whose brief does not resolve under the root now refuses a base that is HEAD itself (exit 2, before any row runs, with or without `--base`): with origin/main at HEAD such a run used to record a red on the changed tree, for example from a git-ignored file only the checkout holds, and earn fail-first credit.
