### Changed
- The optional local Laya provider now enforces the recorded activation policy at both boundaries: CPU only, with no CUDA, MPS or device fallback, and kept disabled until a reviewed read-only artifact bundle and a network-denying sandbox exist. The Go advisor refuses any backend other than the exact string `cpu` before a process starts, and its response check separately refuses a non-CPU requested or actual backend or any stated fallback. The child environment hides CUDA devices and inherits nothing from the caller. A test fails if any production file names the advisor. The Python adapter refuses non-CPU backends before reading artifacts or calling the runtime, refuses device failure instead of falling back, refuses unknown packet or policy keys, and requires approval to be the boolean `true`. The CPU-fallback option is removed from the advisor and from the request protocol. Both mutation scripts now run an unmutated control first and report a count, and the Go script's per-run timeout outlasts the fixture's 10-second hang so the timeout mutant ends in a named test failure. No artifact bundle, loader, sandbox or real smoke is delivered.
