### Added
- The disclosure sweep has a second, registry-independent stage: a shape stage that refuses to certify a tree carrying an absolute per-user home directory, a numeric-id forge noreply email, an SSH remote whose host is an alias rather than the forge host, or a tilde-prefixed home-relative working root, whether or not the value is in any token list. Certify is the AND of the token and shape stages, so a token-clean, shape-red tree does not certify, and the shape stage never relaxes the token stage. The stage reports checked-clean, checked-failed or could-not-check, failing closed on an empty tree, a walk error, an allow file that does not load, or a rule that misses its own built-in positive control. Documented examples are reviewed per-file exceptions in `.leakshape-allow.yaml` at the repo root: each entry names one file, one shape, the exact values it permits and a reason, an unlisted value still fails, and an entry that no longer matches is reported as stale and fails the gate. Hits are reported as path:line and shape without echoing the matched value. The gate runs in the existing disclosure-sweep CI job, and a `muhar` spec (`leakshape-mutations.json`) re-proves each rule red-first.
