### Added
- The disclosure sweep has a second, registry-independent stage: a shape stage that refuses to certify a tree carrying an absolute per-user home directory (the users-directory prefix in any case, or the tilde-account form), a numeric-id forge noreply email, an SSH remote whose host is an alias rather than the forge host, either as an `ssh://` URL (any case) or in scp form within the three scp rules' grammar in `leakshape.go` (the git user in any case, with any path; any other user, when the path reaches a `/` or ends in `.git`; no user, when the host has at least two characters and the path is relative, has at least two segments, a first segment holding a non-digit and a `.git` suffix in any case; other scp spellings, such as a userless remote without `.git`, with an absolute path or with a single segment, or a non-git user with neither a `/` nor `.git`, are out of scope and certify clean), or a tilde-prefixed home-relative working root, whether or not the value is in any token list. Certify is the AND of the token and shape stages, so a token-clean, shape-red tree does not certify, and the shape stage never relaxes the token stage. The stage reports checked-clean, checked-failed or could-not-check, failing closed on an empty tree, a walk error, an allow file that does not load, or a rule that misses its own built-in positive control. Documented examples are reviewed per-file exceptions in `.leakshape-allow.yaml` at the repo root: each entry names one file, one shape, the exact values it permits (by SHA-256 digest, so the allow file carries no shape itself and is swept like every other file) and a reason, an unlisted value still fails, and an entry that no longer matches is reported as stale and fails the stage's own state, not only the gate. Hits are reported as path:line, shape and the value's digest, without echoing the matched value. The gate runs in the existing disclosure-sweep CI job, and a `muhar` spec (`leakshape-mutations.json`) re-proves each rule red-first.
