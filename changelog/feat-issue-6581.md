### Fixed
- `deskevidence` no longer refuses an Evidence landing, an outcome-record landing or a `flip` because a brief the write does not touch shows a could-not-check PROBLEM from a known producer only in the after-write lint. The known producers are the acceptance-transition repository-authority and human-authority reads (such as an origin-authority or `--acceptance-forge is required` read), in both the legacy and the chained `link N` record forms. All three new-PROBLEM gates attribute lines by brief key with the parser the outcome closure gate already uses, and print each excused line as a NOTICE on stderr. Still refused: any line on what the write touches (its own brief, or every brief of a stream whose board README it writes), any new PROBLEM that is not a known producer's could-not-check wherever it lands, including a could-not-check from a producer not yet on the list, every new line for a path that names no brief or stream, and every new line while a stream's frontmatter name differs from its directory.
- When `deskevidence` refuses a landing for introduced statusgen PROBLEM lines, it now prints the before-landing PROBLEM set beside the introduced lines on stderr, so a line that changed wording shows as a change and not only as an addition.
