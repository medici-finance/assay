### Fixed
- `verifyrun` no longer marks an admitted Verify row could-not-run when the row binds a scrubbed name itself: every read is a non-empty default (`${ASSAY_X:-/work}`, `${ASSAY_X:=/work}`, `${ASSAY_X-x}`, `${ASSAY_X=x}`) or follows the row's own `NAME=value`, `export NAME=value` or `NAME=value cmd`. The scrub is unchanged, so the row still never sees an inherited `ASSAY_*` value; a bare read, an empty default, `${NAME:?}` and `${NAME:+x}` with no earlier binding of the row's own are still refused with the same note (#7134).
