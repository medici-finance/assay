### Fixed
- GitLab project provisioning (`deskfleet provision` and `deskgitlab`) now provisions the board-push credential `STATUSGEN_PUSH_TOKEN` itself: a dedicated project access token, scope `write_repository` only, role Maintainer, stored as a masked and protected CI/CD variable and read back by its flags. Where the forge cannot mint project access tokens it records a failure naming the manual step and never falls back to the board-writer's token; an existing variable is a no-op; a minted token whose variable write fails is reported by id and left in place.
- The protected-`main` read-back now checks every push entry instead of only the first, and fails when the board-writer's per-user push entry is absent after the forge accepted it; restoring a prior rule restores all of its entries.
