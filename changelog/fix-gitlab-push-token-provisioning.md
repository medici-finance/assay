### Fixed
- GitLab project provisioning (`deskfleet provision` and `deskgitlab`) now provisions the board-push credential `STATUSGEN_PUSH_TOKEN` itself: a dedicated project access token, scope `write_repository` only, role Maintainer, stored as a masked and protected CI/CD variable and read back by its flags. Where the forge cannot mint project access tokens it records a failure naming the manual step and never falls back to the board-writer's token; an existing variable is a no-op; a minted token whose variable write fails is reported by id and left in place.
- Both reads of protected `main` now classify every push entry (role, user, group, deploy key) instead of reading only the first. The read-back prints them all and fails on any entry outside the intended set, or when the board-writer's per-user push entry is absent after the forge accepted it. A restore re-applies a prior rule's user and role entries; a rule holding a group, deploy-key or unrecognised entry, which a restore cannot reproduce, is refused before anything is deleted, with a named manual step. A deploy-key entry is never treated as a role grant.
- `deskgitlab --pat-expiry-days` is now bounded to 1-365 days, as `deskfleet` already was.
