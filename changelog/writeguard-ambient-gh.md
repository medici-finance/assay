### Added
- `writeguard` refuses a Bash call that runs `gh auth token` (or asks `gh auth status` to print the token) while `DESK_LOOP` or `DESK_SESSION` is set in the hook's environment, naming `desktoken <role>` as the only sanctioned credential path. It judges the executed forms listed in `docs/write-policy.md` (a closed set of wrappers and runners, shell scripts, the pipe stage immediately before a shell, heredocs into a shell, quoting and escapes), with its own scan's work bounded linear in the command's length, and lists the forms it does not judge. A scan that cannot finish (nesting past eight levels, or past the work budget) is refused outright. A `<<` the scan cannot place as a heredoc or a shift, where the heredoc's delimiter line exists, is refused too. The shared quoted-span masking that runs before it is not covered by that bound (#4854). Outside a desk session the hook stays silent, other `gh` use is untouched, and malformed hook input still fails open.
