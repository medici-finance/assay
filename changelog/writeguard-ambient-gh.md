### Added
- `writeguard` refuses a Bash call whose text holds a word of the gh CLI's token read (`auth`, `token`, `oauth_token`, `git-credential`, or `gh` with `status`, anywhere, quoted or not, after decoding escapes) while `DESK_LOOP` or `DESK_SESSION` is set in the hook's environment, naming `desktoken <role>` as the only sanctioned credential path. The guard does not parse the shell; the match is linear in the command's length. Prose naming one of those words is refused too (an accepted false refusal): pass a commit message, PR body or search pattern through a file (`-F <file>`, `--body-file <file>`, `grep -f <file>`). Coverage is accidental or habitual ambient token reads by a cooperating session; deliberate evasion is left to other layers (`docs/write-policy.md`). The shared quoted-span masking that runs before the match is not bounded (#4854). Outside a desk session the hook stays silent, and malformed hook input still fails open.
