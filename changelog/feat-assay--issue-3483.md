### Fixed
- `deskevidence --outcome-record` now accepts a cross-repository brief whose `## Context` `files:` list names its deliverables as `../<sibling>/<path>`. Before, every such brief was refused with "unsupported Context files: path". A sibling path is never read from the tracking tree. The receipt covers it with the run's existing `repo-source:<owner>/<sibling>` commit input, so any change to the deliverable repository wakes the receipt.
- The accepted shape is narrow. It allows exactly one leading `../`, then a literal repository name (no glob or brace), then a canonical path. Every other path containing `..` is still refused, and so is a sibling that the run's cross-repository source binding does not name, or any sibling in a same-repository run. The wake planner reports a sibling declaration as could-not-check, never unchanged, unless the receipt pins that sibling's source commit.
