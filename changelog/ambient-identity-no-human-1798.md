### Fixed
- `deskroster preflight`'s `ambient-identity` check no longer needs a human `gh` login for a desk to boot. "No usable ambient human identity" (`gh` not logged in, or an App/integration token that answers 401/403 on `/user`) is now the clean state; before, the real probe reported both as could-not-check, so the only green state was a logged-in blessing human, which is the one state where a tool fall-through acts as the maintainer. A human login, the blessing login included, is now a non-blocking WARNING notice naming the login. A bot/App slug stays checked-failed. `gh` missing or unrunnable (exec failure, timeout, a server or rate-limit answer) stays could-not-check. The transport half, where every credential source git consults for the landing push URL must be the minted App token, is unchanged. The remediation now starts with clearing the ambient credential and never recommends logging a human in. It also explains that an empty `GH_CONFIG_DIR` is not enough on its own: `gh auth token` still returns an OS-keyring login from an empty config dir, and a verb shim whose `gh` wrapper hands that to `gh` as `GH_TOKEN` brings the human back. Exporting `GH_TOKEN` as the role's minted App token closes both paths.
