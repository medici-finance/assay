### Fixed
- statusgen's held scan now reads statusgen verifyrun's own execution witness as a results table that can supersede earlier holds. A witness row's `sha256:<12 hex>` Output digest no longer counts as a note, nor does a fail-first witness row's `Base` cell in the exact form verifyrun writes, and the `sandbox=unshare` or `sandbox=container-netns` token after `exit=` counts as a neutral detail. The tool's trailer lines written directly under a witness table (`Verification-Attestation:`, `Tree-Digest:`, `Container-Image:`, `Admission-Bracket:`, each matched field by field) no longer read as an unkeyed row. Before this, a later witness that re-ran every row clean never covered an earlier held row, `BLOCKED` bullet or `VERIFY: BLOCKED` heading, so `verifyflip` refused briefs whose latest entry was a clean `VERIFY: PASS`. The scope rules themselves are unchanged. A digest or Base cell alone never makes a row clean. Any other sandbox token, a digest outside an Output column, of another length, in emphasis or in upper case, any other text in a Base column, a trailer under a hand-written table, a trailer with text appended, and a non-blank line after the trailer run all still refuse.
