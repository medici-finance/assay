### Fixed
- `verifyloop` and `deskrebaseline` now run the same command statusgen lifts from a Verify Command cell: the `cmd:`-marked command, else the first code span. Before this, they ran the whole cell under `sh`, so a cell such as a `false` span followed by a colon and prose recorded a pass. A cell statusgen refuses as prose-led, comment-led or blank is now refused by both executors too (in `deskrebaseline`, by the rename-proof re-run as well as the behaviour probe), and one shared table of cells holds both modules to the same verdict.
- statusgen, `verifyloop` and `deskrebaseline` now refuse a Verify command that is a shell no-op (`:`, or a cmd.exe `REM` / `::` remark), marked or not, recording it could-not-run with the remedy "replace the no-op with the command that performs the check".
- The `prose-led-command` rule text (the enforcement-status table, the author-brief rule table and the closed-brief summary notice) no longer tells a marked comment to add the `cmd:` marker. It names both remedies: mark the real command, or replace a comment or no-op.
