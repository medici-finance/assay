### Fixed
- `statusgen reconcile --backfill` without `--apply` no longer claims to write nothing when `--report` is also given: its table output says the drift report was written (and that no stream README was) instead of "read-only", and the README, the `--backfill` flag help and the code comments now say "writes no stream README; writes the drift report only with `--report`".
- `wouldApply` in `statusgen reconcile --backfill --json` is now present only when the run could look (PR list and raw pull list both read, and a `docs/streams` board found). A run that could not look (offline, no `--repo`, an HTTP error, a refused connection, no board under `--root`) omits it, so `[]` always means "looked and found nothing".
- The pr-review-desk carve-out B reproduce step now binds the `wouldApply` comparison to the entry's own `readme` and `id`, so a byte-identical row in another stream's README is not matched, says to read `[]` together with `lookedAt`, and calls the `--token-file` content the reviewer role's own credential, used for reads only.
