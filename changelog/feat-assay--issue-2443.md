### Fixed
- `statusgen reconcile --backfill` without `--apply` no longer claims to write nothing when `--report` is also given: its table output says the drift report was written (and that no stream README was) instead of "read-only", and the README, the `--backfill` flag help and the code comments now say "writes no stream README; writes the drift report only with `--report`".
- `wouldApply` in `statusgen reconcile --backfill --json` is now present only when the run could look (no whole-run refusal: the PR list, the raw pull list and every fold read made, and a `docs/streams` board found). A run that could not look (offline, no `--repo`, an HTTP error, a refused connection, a failed fold read, no board under `--root`) omits it, and where `--apply` would refuse it carries only `wouldRefuse`, so `[]` always means "looked and found nothing". The table output labels held rows by the run's mode, so a run without `--apply` never prints the `--apply` label.
- The pr-review-desk carve-out B reproduce step now binds the `wouldApply` comparison to the entry's own `readme` and `id`, so a byte-identical row in another stream's README is not matched, says to read `[]` together with `lookedAt` (and a `wouldRefuse` key as could-not-look), compares `readme` relative to the `--root` worktree, and calls the `--token-file` content the reviewer role's own credential, used for reads only.
