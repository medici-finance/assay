### Fixed
- `deskreply`, `deskwt` and the shared origin-slug helpers (`OriginRepoSlug`, `RepoSlugForDir` and the preflight landing slug) now refuse to decide a repository from `origin` when config the repository-local reader does not merge could change it: an `include`/`includeIf` directive, or, with `extensions.worktreeConfig` enabled, a worktree-scope `include`/`includeIf`, `url.<base>.insteadOf` or `remote.origin.url` entry. `deskreply` and `deskwt` exit 6; the best-effort slug helpers return no slug. One worktree-scope `remote.origin.url` shape is still accepted: an empty reset followed by exactly one URL that names the same repository as the shared `origin`, which is the pin a worktree transport repair writes. These readers and the work-source reader's `ScopedRemoteURLs` also refuse while command-priority config (`GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG`) or `GIT_DIR`, `GIT_COMMON_DIR` or `GIT_WORK_TREE` is set, as the origin snapshot owner already does. `extensions.worktreeConfig` is now read with git's own boolean spellings only (`true`/`yes`/`on`/`1`, `false`/`no`/`off`/`0`, any case); `t`, `f` and other values refuse. A worktree-scope config file in a form git accepts but the reader cannot parse now refuses with the worktree-scope message rather than a generic unreadable-origin one. The origin-read guard test now counts reads per function (a second read inside an allowed function fails), fails on an allow-list entry whose reads are gone or fewer, and also catches a read reached through a method value, a method expression or a package-level function literal.
