### Fixed
- `deskreply`, `deskwt` and the shared origin-slug helpers (`OriginRepoSlug`, `RepoSlugForDir` and the preflight landing slug) now refuse to decide a repository from `origin` when config the repository-local reader does not merge could change it: an `include`/`includeIf` directive, or, with `extensions.worktreeConfig` enabled, a worktree-scope `include`/`includeIf`, `url.<base>.insteadOf` or `remote.origin.url` entry. `deskreply` and `deskwt` exit 6; the best-effort slug helpers return no slug. One worktree-scope `remote.origin.url` shape is still accepted: an empty reset followed by exactly one URL that names the same repository as the shared `origin`, which is the pin a worktree transport repair writes. These readers and the work-source reader's `ScopedRemoteURLs` also refuse while command-priority config (`GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG`) or `GIT_DIR`, `GIT_COMMON_DIR` or `GIT_WORK_TREE` is set, as the origin snapshot owner already does. The origin-read guard test now also fails on an allow-list entry whose caller is gone, and also catches a read reached through a method value, a method expression or a package-level function literal.
