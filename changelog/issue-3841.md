### Fixed
- statusgen's held scan now supersedes earlier Evidence entries as wholes once the final entry carries a live strict `VERIFY: PASS` and re-ran every row key of every earlier entry clean: their prose, entry-level `VERIFY: BLOCKED` lines, held or could-not-check notes that name no row or name a row absent from every keyed table, and holds in fenced code or wholly inside an HTML comment are dropped. A comment counts only where the renderer opens one: `<!--` at three spaces of indentation or fewer and no tab, ended by the first `-->` or `--!>` from its first byte, so `<!-->` and `<!--->` close on their own line. After a `--!>` end, the rest of the HTML block up to `-->` renders live and stays read. Partial coverage still refuses: an earlier key the final entry did not re-run, or re-ran to a failure, an earlier results row that cannot be aligned or keyed, or an earlier entry with no keyed row keeps every entry read. So does an earlier entry that records a row in a table the scan cannot key, even inside an HTML comment (another shape, no separator row, no leading pipe, a blockquote, an HTML table, including one nested in a results table's cell, or a line continuing a results table), or an HTML block that leaves a tag, a quoted attribute value or a comment open at the end of a line, except inside a top-level block the page is sure to run on past it, which hides what follows on the page. Any line in a blockquote, a list item or under leading whitespace that holds a tag start or a fence also keeps every entry read: this over-refuses (an inline tag in a list item, an indented sample) by design. So does an entry that leaves an HTML element open: every non-void element an entry opens outside fenced code must be closed later in that same entry, in nesting order, by a close tag the page surely applies to it (not in a code span, a comment, an attribute, a link or image, math or a table, not escaped, and in the opener's own paragraph unless both sit in HTML blocks that run to a blank line), and the final entry may hold none open across a line end. An opener of a raw-text or foreign element refuses even when closed. This over-refuses by design. Any carriage return left after the brief reader's line-ending rewrite ends a line on the page and turns whole supersession off from that line on; the brief reader now runs that rewrite once, so such a carriage return reaches the scan. A hold in any other HTML block is always read.
