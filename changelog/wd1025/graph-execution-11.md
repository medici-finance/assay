### Changed
- The optional local Laya provider boundary now encodes the owner's recorded activation policy: CPU only, disabled until a reviewed read-only artifact bundle and a network-denying sandbox exist. A CUDA request, and the CUDA-to-CPU fallback behind it, is refused before any process launches unless a separate CUDA approval is supplied (`AllowCUDA` on the Go advisor, `allowed_backends` in the Python policy). MPS stays unqualified. Mutation scripts cover the new check, and the Go mutation runner's per-run timeout now outlasts the test fixture's hang so the timeout mutant is reported as caught.
