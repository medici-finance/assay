### Fixed
- statusgen's held scan now treats an Evidence row keyed `3 (Verify 3, negative)` as the same Verify row as a later run's bare `3`, so a later strict `VERIFY: PASS` that re-ran row 3 clean supersedes the older annotated row. Before this, the annotation made the keys differ and `verifyflip` kept reading the old row as live. The key is shortened only when every number in the annotation is the row's own number. It is never shortened for a lettered key (`3a`), nested parentheses, text after the annotation, or a number that names another row or a date. It is also left as written when the same number shows up with two different annotations anywhere in the Evidence, or in two forms within one entry, because those may be sub-rows.
- The held scan no longer reads `could-not-check` as a row's disposition when the row's Result cell is recording what the product printed, such as `PASS: … a could-not-check mission section`. This applies only when all of the following hold: the table has an Exit column and every Exit cell of the row is clean; the Result cell opens on PASS, passed or ok; an article or possessive comes right before the marker and an ordinary word (not a disposition noun or a hold reason) comes right after it; the line has no struck text; and the row has no BLOCKED, FAIL, SKIP, UNRUN, deferred, pending, awaiting, waiting, not run or no-runner word. `HELD` is never excused this way.
- A summary such as `Rows: 2 of 2 required rows passed; 0 could-not-check.` is now read as a zero count instead of a held disposition. This applies only when both counts are the same and above zero.
