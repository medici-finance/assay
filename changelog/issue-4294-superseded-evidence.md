### Fixed
- statusgen's held scan no longer treats a one-line prose paragraph that contains an unescaped `|` (for example a quoted `go test -run "A|B"` pattern) as a table it cannot key. Before this, one such line in an earlier Evidence entry stopped a later full `VERIFY: PASS` from superseding every earlier entry, so `verifyflip` refused on an old `VERIFY: BLOCKED` heading. The exemption covers only a line that GFM can never read as part of a table: at column 0, with no blockquote or list marker, not starting with `|`, holding no carriage return, and with a blank line directly before and after it. A two-line paragraph, a line next to a delimiter row, a row-shaped line, and any line in a container still count as tables the scan cannot key. Supersession still needs the last entry to be a strict full PASS that re-ran every earlier row clean, and the last entry's own text is still always read.
