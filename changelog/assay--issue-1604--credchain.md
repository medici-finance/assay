### Changed
- The `ambient-identity` preflight check's credential-chain half now matches how git itself resolves the credential for a push: `credential.<url>` patterns with no host (`""`, `/`, a path, a scheme-only URL) apply the way git's partial-URL fallback applies them; every URL `git remote get-url --push --all` lists is judged, not only the first; a netrc `machine` entry for the host (or a `default` entry) reads red, since curl answers from it before any helper runs, with netrc keywords matched in any letter case and a keyword read after `login`/`password`/`account` outside a matched entry, as curl does; and a helper passes only when it IS the desk's App token helper over the minted token file (`deskkit.AppTokenHelper`, which `deskwt role-init` now builds from too), not merely a command that mentions that file, and the helper value is matched untrimmed, as git reads it (a leading blank makes git run it as `git credential-…`, which answers nothing). The detail names the command git would actually run. A push URL git cannot normalize or with an empty host, a pattern git would skip as unparseable, or a netrc file that exists but cannot be read is could-not-check, never clean.
