### Changed
- The `ambient-identity` preflight check's credential-chain half now matches how git itself resolves the credential for a push: `credential.<url>` patterns with no host (`""`, `/`, a path, a scheme-only URL) apply the way git's partial-URL fallback applies them; every URL `git remote get-url --push --all` lists is judged, not only the first; and a helper passes only when it IS the desk's App token helper over the minted token file (`deskkit.AppTokenHelper`, which `deskwt role-init` now builds from too), not merely a command that mentions that file, with the helper value matched untrimmed, as git reads it (a leading blank makes git run it as `git credential-…`, which answers nothing). The detail names the command git would actually run.
- The netrc read is a state-free scan (driver ruling on arbiter packet #1622, option 1): it reads red whenever any token in the file — an unquoted token split on any whitespace byte, or a quoted token with its escapes unescaped — equals the push host or the keyword `default`, ASCII case-insensitively, wherever that token sits (a comment, a macro body, or a login/password/account value included, not only a recognized keyword position). This covers every netrc reader libcurl has shipped, including releases after 8.10 that a position-aware model (rounds 1-2 of this PR's review) still read green for, at the cost of a false red when the host or `default` appears only as an unrelated word elsewhere in the file.
- A push URL git cannot normalize or with an empty host, a pattern git would skip as unparseable, or a netrc file that exists but cannot be read, that curl would refuse (an unterminated quote) or that holds a NUL byte is could-not-check, never clean.
