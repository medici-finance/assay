### Changed
- The `ambient-identity` preflight check's credential-chain half now matches how git itself resolves the credential for a push: `credential.<url>` patterns with no host (`""`, `/`, a path, a scheme-only URL) apply the way git's partial-URL fallback applies them; every URL `git remote get-url --push --all` lists is judged, not only the first; and a helper passes only when it IS the desk's App token helper over the minted token file (`deskkit.AppTokenHelper`, which `deskwt role-init` now builds from too), not merely a command that mentions that file, with the helper value matched untrimmed, as git reads it (a leading blank makes git run it as `git credential-…`, which answers nothing). The detail names the command git would actually run.
- The netrc read is a state-free scan (driver ruling on arbiter packet #1622, option 1): it reads red whenever any token in the file — an unquoted token split on a boundary byte, or a quoted token with its escapes unescaped — equals the push host or the keyword `default`, ASCII case-insensitively, wherever that token sits (a comment, a macro body, or a login/password/account value included, not only a recognized keyword position), at the cost of a false red when the host or `default` appears only as an unrelated word elsewhere in the file.
- The state-free scan runs three tokenizations, not one, because the token STREAM each reader sees depends on the reader on two independent axes: the byte set that ends an unquoted token, and whether one extra byte is skipped after a token closes. Precisely, the scan now covers: the pre-8.11 state machine and the 8.11-8.12 reader that drops whole-line comments as it loads the file (narrow boundaries, with the skip); curl-8.13 through curl-8.20, which end an unquoted token at any byte <= 0x20, and — where the platform's `char` is signed — at any byte >= 0x80 too, not only the six `isspace` bytes (wide boundaries, with the skip; a `machine\x01HOST` or `default\x01login` netrc entry used to fuse into one uncompared token and read green — SR-1614-6); and the curl-8.21+ grammar lexer (narrow boundaries, no skip). It reddens if any of the three finds a match. A reader this scan has no tokenization for — an unbuilt libcurl release, a distribution patch, or a non-libcurl netrc reader — stays could-not-check where it cannot be observed directly, not a claim of coverage.
- A raw or escaped newline byte inside a quoted netrc token now always ends the quote as unterminated, matching curl's line-based reading: previously a quote opened on an inert line (a `#` comment, or a `macdef` body) could silently absorb a real `machine`/`default` entry on the following line into the same "token," hiding it from the scan instead of comparing it (SR-1614-6). That shape now reads could-not-check rather than green.
- A push URL git cannot normalize or with an empty host, a pattern git would skip as unparseable, or a netrc file that exists but cannot be read, that curl would refuse (an unterminated quote, including one that only becomes unterminated because it crosses a line) or that holds a NUL byte is could-not-check, never clean.
