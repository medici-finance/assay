### Fixed
- `deskflip` can now flip a PR whose `Security-Review: fail` was cleared at the same head, when the fail rested only on the PR body. The fail must declare `Blocked-On-Body: <finding-id> <digest>`, and a later `Security-Review: pass` from the same reviewer at that head must carry `Body-Reread-Digest:` equal to the live body's digest. The forge must also record a body edit after the fail. An unmarked security fail still blocks until a new commit, and so does a later unmarked fail. `deskboard` makes the same decision through the same shared function.
- Rule 2 of `reviewer-approved` now routes a security fail to the security lane before either correctness exemption. Before this fix, rule 2 let a correctness APPROVE that cited a green run, or that documented a body edit, clear a security fail carrying `Blocked-On-Check:` or `Blocked-On-Body:`. Only the separate `security-verdict` condition still stopped the flip. Rule 2 now refuses on its own.
