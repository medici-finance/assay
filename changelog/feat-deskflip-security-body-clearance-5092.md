### Fixed
- `deskflip` can now flip a PR whose `Security-Review: fail` was cleared at the same head, when the fail rested only on the PR body. The fail must declare `Blocked-On-Body: <finding-id> <digest>`, and a later `Security-Review: pass` from the same reviewer at that head must carry `Body-Reread-Digest:` equal to the live body's digest. That pass counts only on a COMMENTED or APPROVED review, the same states `deskpost ready` accepts for a security pass; a dismissed or pending one clears nothing. `deskflip` and `deskboard` read one shared list of those states, and `deskpost ready` keeps its own copy, which a test pins to the shared one. The forge must also record a body edit after the fail. Neither the fail nor the pass may also carry a correctness `Verdict:` line; a body that speaks for both lanes is never cleared this way. At `deskflip`, an unmarked security fail standing as a CHANGES_REQUESTED at the head still blocks until a new commit, and so does a later unmarked fail; `deskpost ready` does not apply that rule. `deskboard` makes the same decision through the same shared function.
- Rule 2 of `reviewer-approved` now routes a security fail to the security lane before either correctness exemption. Before this fix, rule 2 let a correctness APPROVE that cited a green run, or that documented a body edit, clear a security fail carrying `Blocked-On-Check:` or `Blocked-On-Body:`. Only the separate `security-verdict` condition still stopped the flip. Rule 2 now refuses on its own.
