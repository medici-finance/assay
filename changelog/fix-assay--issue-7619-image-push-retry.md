### Fixed
- The release image publisher now retries a push a bounded number of times (three attempts, waiting 15s then 30s) when the registry answers with a transient error, so one registry hiccup after approval no longer burns the version. The retried errors are a missing blob (`unknown blob` or `blob unknown`), a 5xx status, a 429 rate limit (`toomanyrequests`), a connection reset, an `i/o timeout` and a TLS handshake timeout. Auth and permission refusals (including 401 and 403), existing-tag refusals and every other failure still stop the release on the first attempt, even when a transient marker appears in the same message. When the retries run out, the original registry error is what surfaces. The runner image index push takes the same retry.
- When the image publish fails part-way, the release log now lists every image reference, with its digest, that was pushed before the failure.
