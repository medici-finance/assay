### Added
- `statusgen verifyrun --open-bracket --roster-copy <file>` gives the container-netns lane a roster, so a Verify row that runs `statusgen --lint` inside the container no longer refuses its configuration. The open step reads the host roster through the owner-checked loader, writes only the keys statusgen reads (trusted identities, repository set, product keys; no credential or any other key) to a new 0600 file outside the home, records its digest in the receipt as `roster`, and prints the flag that mounts it read-only at `/run/assay-roster/roster.env`. Before any row the container run refuses a missing, read-write or different copy, and otherwise gives each row's fresh HOME the copy as its config-home roster (#6904).
