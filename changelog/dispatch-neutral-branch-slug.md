### Fixed
- `deskdispatch` no longer puts another repo's short label into a public repo's branch name. When the target's roster entry is `:public` and the item key's repo label (its first `--` segment) names a different repo, the default branch is now neutral: `feat/<stream>-<NN>` for a brief claim key, else `feat/item-<hash>`. Workers name their changelog fragment after that branch, so the label and issue number stay out of the public tree as well. `--branch` still wins, the claim key is unchanged, and the worker kits now tell the worker to name the fragment after the branch it was given, never the raw item key.
