### Added

- `execution-profile/v1`, an extension of the shared runner protocol: an adapter declares qualified harness, model and backend profiles, each bound to its qualification evidence, with resume and restart preservation stated per dimension (files, conversation, process memory, descendants, pending interactions) and unknown kept apart from unsupported. A request pins one profile by digest and names what it needs; anything the profile does not promise is refused before Start, by the client and again by the adapter. The adapter's execution report is checked at acceptance, so a substituted backend or a partial restoration is refused. Spec `spec/loop-admin-execution-profile-v1.md`, schema `schemas/loop-admin-execution-profile-v1.json`, reference implementation and fixtures in `loopadmin`, and a new conformance kit case.
