### Changed
- The statusgen workflow's `model-autoflip` job now runs `statusgen --auto-flip-model --check` and tells its exit 2 (a candidate left REFUSED or COULD-NOT-CHECK) from exit 1 (a misconfiguration). Exit 2 writes a `::warning::` annotation and a job-summary line with the flipped, REFUSED and COULD-NOT-CHECK counts, so a run that flips nothing no longer reads as a plain success. The job stays green unless the repository variable `ASSAY_AUTOFLIP_STUCK_FAILS` is `true`. Exit 1 still fails the job, and so does an exit 2 that printed no REFUSED or COULD-NOT-CHECK line, since a Go runtime panic also exits 2. Lands with a maintainer's workflow push; the staged twin carries the same step.
