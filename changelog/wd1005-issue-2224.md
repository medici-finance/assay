### Added

- `ask-decision`: the fifth part of a decision item is now **Act** — the runnable act (a fenced `sh`
  block that runs top to bottom, or a fenced `url` block for a browser step) followed by the
  post-act check. An `sh` block opens with a zsh comment guard
  (`[ -n "${ZSH_VERSION-}" ] && setopt interactive_comments`), since interactive zsh otherwise runs
  `#` lines as commands; carries one plain-text comment per step, with no shell metacharacters;
  marks values only the human has with `# fill:`; and reads every secret with `read -rs` in its
  first step, stopping before any change when a read comes back empty. The block defines the act as
  one function run in a subshell: pasting it only prints, and the driver acts by calling it with
  `live`, so a live run never carries over to the next act's paste. Only the desk-authored block is
  the act — one posted by a desk role's own App identity and not edited since by any other account;
  a block copied from a comment or an untrusted issue is never run, and an agent never runs an Act
  block. `worker-desk`, `verify-desk` and `the-desk` point at that one definition for the
  `BLOCKED-ON-HUMAN` report and the verify-gate card.
- `skillslint`: a hard `ACT-BLOCK` check holds every act block under `plugins/` to the zsh guard and
  the plain-text comment rule (exit 1 on a violation, exit 2 when it finds no act block at all).
- `deskfile new` refuses (exit 5) a human-only hand-off — label `human-only`, or a body whose first
  non-blank line opens with `BLOCKED-ON-HUMAN` — whose body carries neither a ` ```sh ` nor a
  ` ```url ` fence. Fences are matched the CommonMark way: a run of three or more backticks or
  tildes, indented at most three columns from its margin or list item, so an `sh` fence quoted
  inside another block, or indented four columns into code, does not count.
  `--force-new --reason` is the only bypass, and it also waives the dedupe search and the
  blocker-evidence gate; the audit line records `act-gate=bypassed:force-new`.
