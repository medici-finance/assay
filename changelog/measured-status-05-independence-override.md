### Added
- `statusgen --lint`: the committer-identity independence check keeps its hard failure for a same-identity author/verifier pair, and now has one recorded way through it for a legitimate post-verification re-touch. A brief may carry `independence-override: "human:<name> YYYY-MM-DD <reason>"` in its frontmatter. It is honored only when the name is a current human who is not the brief's author, the brief is outside any declared fixture corpus, the committed line was last written by a commit whose git author email differs from the identity it excuses (read from the commit itself, so a `.mailmap` entry does not change it), the date is not later than that commit, and the Evidence section has not changed since that commit. An override committed or last edited under the excused identity's own author email is refused, as is an uncommitted, stale, postdated or malformed one, and the failure says why. An honored override is reported as a notice. These checks read git metadata, which the committer sets, so they do not prove the named human authorized the override: that binding is `statusgen --corroborate`, which checks the `human:<name>` on an added override line like any other human stamp, and only where it runs on the change that adds the override.
- Brief frontmatter schemas (v1, v2, v3) type `independence-override` as a string, matching the validator.
