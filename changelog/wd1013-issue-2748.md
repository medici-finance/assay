### Added
- `deskdispatch --cross-repo` dispatches a brief that is homed (tracked) in one repo but whose PR opens in another. The brief still resolves to its home repo through its item-key prefix or brief-v2 id, and `--repo` names where the PR opens. `--repo` must be published in the alias registry and must be `--root`'s origin. Without the flag, the existing HARD FAIL is unchanged. The flag is refused when the brief declares `deliverable_repo`/`homed-in`, when no tracking alias is named, or when `--repo` is the tracking repo itself. Every refusal happens before the claim, the token mint and the worktree.
- A new PR-body link trailer, `Cross-repo-brief: <alias>:<stream>/<NN>`, names a brief homed in another repo. Its value is the same item key `deskdispatch` accepts, so the review and verify lanes can hand it straight back. `deskpr create` and `deskpr edit` accept it when the alias is registered in `--root`'s registry and is not that registry's own `self`; neither tool looks for the brief file under `--root`. It is one link per body, so a second one, or one next to a `Brief:`, `Issue:` or `Authors:` line, is refused. The security lane's brief-risk term fails closed on it (risk-classed, unverifiable), because the brief's gate cannot be read from this repo. Existing `Brief:` trailers mean exactly what they did before.
