### Fixed
- `statusgen verifyflip` and the reconcile fold no longer pass a verifyrun witness row whose hold sits inside fenced code. The witness check reads table rows inside a fence and credits such a row by its first state word, while the held scan skipped the fence, so a fenced row reading `HELD pass exit=0` flipped. The same held for every other line the held scan skips while the witness check still credits it as a witness row. On the flip read any such skipped witness row is now read for holds. A witness row whose marker word only a stripped HTML comment forms (a comment inside the word, which the held scan reads as two pieces) is refused the same way on the flip read. The verify-gate card and close-verify, which run no witness check, are unchanged.
- The held scan's rule 7 (double-quoted output, flip read only) no longer reads a span on a line that carries HTML comment syntax anywhere (`<` or `-->`): a comment opening in another cell or on an earlier line and closing beside the quote hid a quote from the cell's own check. It also no longer reads a span from a quote beside a C0 control or DEL byte, which renders as nothing and turned an inch mark (`5\x01"`) into a quotation mark. Nor does it read a span on a line that starts while inline markup from an earlier line of the paragraph is still open, since that markup's closer can hide the line's opening quote. Nor does it read a span over a region holding a `[` (a reference or footnote label, whose definition elsewhere renders the label as a link or a number) or a `$` (a math span, which renders as typeset math). Such a hold is refused on every read.
