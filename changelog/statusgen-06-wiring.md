### Added
- CI now runs the findings-register transition check: `statusgen --corroborate` in its own `corroborate` job of `assay-statusgen.yml` (statusgen/06 deliverable 7, #1855). No PR-authored code runs in that job. The guard binary is built from the merge commit's base parent, with a job-local Go toolchain and caches and the pinned `gh`, and the PR tree is read only as data. Before building, the job checks that this parent is the merge-base of the base branch with the merge commit, so the guard compares against the commit it was built from, and that the event's base sha is its ancestor. A base retarget re-runs the job, and a retarget during a run fails it. It runs on PRs that touch `docs/streams/findings/`, and fails closed when the base cannot be read or tied, or no human-login map is configured. Residual: under `pull_request` the workflow file itself comes from the PR, so a PR that edits `assay-statusgen.yml` can change this job; that edit is caught by human review of workflow changes, not by the job.
