### Fixed
- Verifier runs now use a declared Git environment: `verifyloop` sets `GIT_CONFIG_GLOBAL` to the null device, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_COUNT=0` and `GIT_TERMINAL_PROMPT=0`, and removes inherited `GIT_CONFIG`, `GIT_CONFIG_PARAMETERS`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_SSH_COMMAND`, `GIT_ASKPASS` and `SSH_ASKPASS`, on the runner it spawns, on every Verify row it runs and on its own Git calls; `deskdispatch --kit verifier` prints the same `unset` and `export` lines in the verifier prompt. An operator `includeIf` no longer reaches the repository-authority read, so `statusgen --lint --acceptance-forge` reaches a verdict in the verifier lane instead of `could-not-check ... an include may affect authority`. The authority reader is unchanged and still refuses an include that may affect authority; the verifier home's identity, credential and remote keys belong in the clone's own config, never in an `include.path` file. See `references/desk-shell.md` §"Verifier Git environment".
