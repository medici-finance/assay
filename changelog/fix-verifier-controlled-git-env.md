### Fixed
- Verifier runs now use a declared Git environment: `verifyloop` sets `GIT_CONFIG_GLOBAL` to the null device, `GIT_CONFIG_NOSYSTEM=1` and clears injected configuration on the runner it spawns and on every Verify row it runs, and `deskdispatch --kit verifier` prints the same `export` line in the verifier prompt. An operator `includeIf` no longer reaches the repository-authority read, so `statusgen --lint --acceptance-forge` reaches a verdict in the verifier lane instead of `could-not-check ... an include may affect authority`. The authority reader is unchanged and still refuses an include that may affect authority; the verifier home's identity, credential and remote keys belong in the clone's own config, never in an `include.path` file. See `references/desk-shell.md` §"Verifier Git environment".
