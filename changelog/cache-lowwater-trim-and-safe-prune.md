### Added
- A managed cell Go cache is now trimmed to a low-water mark: once its size passes the high-water mark (75% of the budget, the margin the lock-free admission pre-check needs) or it is under pressure with consumers live, compiler-cache entries are removed oldest first until it is at or under `CELL_GO_CACHE_LOW_WATER_PERCENT` (default 60%), so the next launches admit without the lock instead of every build re-triggering a trim. No entry younger than `CELL_GO_CACHE_TRIM_MIN_AGE` (default `2h`, never below `2h`) is ever removed, the floor is re-checked at removal, and a trim the floor stops short is reported with its shortfall in the report's `low_water_trim` object. Default policies serialize exactly as before.
- With consumers live, a trim now removes compiler-cache entries down to the 2h safety floor on every pass that finds the cache above the high-water mark. Before, a trim under live consumers ran only under pressure and took only entries past the 24h trim age, so this narrower margin now applies on routine passes, not only under pressure. When the module cache alone holds the cache above the low-water mark, the trim does not chase the target: it takes only entries past the trim age and reports the shortfall as untrimmable.
- `cellctl cache <cell> wipe` with live consumer records now trims toward zero: it removes every compiler-cache entry older than the safety floor (default `2h`), where before it removed only entries past the 24h trim age. `mod/`, `gopath/` and whole roots stay protected, as before.
- `deskwt add --lock-session <id>` locks the new worktree for a live session as its final, verified step, rolling the worktree back if the lock cannot be taken.
- `deskwt prune --min-idle <dur>` tunes the new activity gate (below).

### Fixed
- `deskwt prune` now holds a worktree that git shows activity in within `--min-idle` (default `1h`): every unlocked candidate, including those `--reap-dead-sessions` would take, is held while its root directory or the files git rewrites as a session works (`HEAD`, `index`, `logs/HEAD`, `ORIG_HEAD`, `FETCH_HEAD`) were touched inside that window, and unreadable evidence holds the tree. This is a recency check on what git writes, not proof that no session is using the tree: a session that only reads files or runs tests in a clean tree, with no git operation and no file created or deleted at its top level, for longer than `--min-idle` is not seen. Such a session should lock its tree (`deskwt add --lock-session`).
- The prune singleton is keyed on the repository's shared git directory, so sweeps started from the shared checkout and from its worktrees no longer run concurrently over the same repository.
