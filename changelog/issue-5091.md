### Fixed
- The release workflow tests again check that every mutation harness and every `deskmerge` shard in the release test matrix runs exactly once, uploads its report and keeps its verdict gate. A harness step or the test job that tolerates failure, a surviving mutation that exits successfully, a shell override, an excluded leg, a disabled or non-failing report upload, and a publishing job that stops waiting on the test job are each refused, and a setting kept only in a comment counts as absent. They also check that the `artifacts` and `release` jobs bind their fixed runner labels with no expression, that the publisher's runner label matches exactly (a label that merely contains it, or appears only in a comment, is refused), and that the native arm64 job downloads every build artifact and fails on an empty upload. A new `tools/release/ci_step_test.py` checks from outside the image contract suite that CI still runs it on the `rest` shard, fails the shard when it fails (no shell override, no excluded shard) and stops it within 15 minutes, and that the Go regression test still discovers every release suite.
