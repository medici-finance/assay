### Added

- `statusgen verifyrun --rule51` writes the rule-51 witness itself (#4823). In an admitted host run, a Verify row whose command is exactly a repo-wide `statusgen --lint` (no `--diff-base`, nothing else) and whose Expect is a clean exit still runs as authored and keeps its offline result. When that result is red, the run also runs `--root . --lint --acceptance-forge` under the run's verifier read credential and stamps the witness with the forge state and exit code, the output hash, the version that ran, the credential class and digest, and a digest binding the stamp to the row. `verifyrun --check` and the closure gate (`brief --check-verified`, which `deskevidence` runs) credit the row only when that stamp binds, the forge run exited 0 with `LINT: PASS`, the pin is a release tag and the tree is clean. The coverage library reaches the same verdict through the same function, so `--coverage`, the model auto-flip and the reconcile fold agree with the closure gate. A prose or hand-table citation is never credited, and every other refusal is unchanged.
- `deskevidence --remove-superseded <record> --superseded-by <newer>` removes a verify-outcome record that a newer record for the same brief supersedes. The removal is one pinned, conditional forge commit under the same identity, attestation and public-repo gate as `--outcome-record`. It refuses any path that is not an outcome record, a record that is not superseded, and a newer record for another brief.
