### Changed
- `muhar` now builds most mutants once per worker instead of once per mutant: eligible in-function edits are compiled together as a mutant schemata (a `-overlay` tree with an environment-selected switch per mutant), so a mutant costs a link and a test run instead of a full compile and vet. Verdicts, the `Totals:` line, `-shard`/`-j` semantics and exit codes are unchanged; a mutant the schemata run does not catch is re-run the classic way before it is reported NOT CAUGHT, and any mutant that does not fit (outside a function, labels, compile errors, a red schemata baseline) runs exactly as before. Schemata notes go to stderr only.
