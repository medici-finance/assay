### Added
- `muhar -select` (opt-in): coverage-guided test selection. After the baseline, muhar records one coverage profile per top-level test and runs each mutant against only the tests that execute the function it mutates, plus an optional `select.always` list in the spec for tests that catch a mutant without executing it (source-text reads, golden files). Before any mutant runs, muhar proves on pristine source that every test passes alone (a test that does not breaks the run) and that every distinct narrowed set passes as a whole (a set that is red runs its mutants on the full command). The positive control runs under selection too, and a mutation that cannot be attributed to one function body (a non-Go or uninstrumented file, a signature or package-level edit, an added or removed declaration) runs the full command. One residual is stated rather than closed: a narrowed run changes which tests run before each selected test, so shared state that a dropped test sets or clears (a lazily set default, a registry, a mutation's own leak) can steer a selected test into or away from the mutated code, and `-select` can report CAUGHT for a mutant the full command lets survive. That is why the flag is opt-in, and a gate enables it only after a parity run against the full sweep on its spec, re-run whenever the suite or spec changes. A spec that uses `-race` works under `-select` (the coverage build switches to atomic mode, which the go command requires). With `"schemata": true`, a mutant whose suite `-select` narrows runs the classic way and the rest keep schemata; on the deskkit spec that pair is slower than schemata alone, so a gate should use one or the other. On the CI specs it gave identical reports and cut total wall time by 17% in a local run (deskkit 25%, deskmerge 22%; the small specs are a few seconds slower from the pristine proof); CI is not switched over here. Baseline, exit codes, the `Totals:` line and `-shard`/`-j` are unchanged.
