### Fixed
- `statusgen verify-gate-close` (and the implemented-gate sign-off card) now take the verifier date and runner from the latest `**VERIFY: PASS**` run under `## Evidence`, selected exactly as `verifyflip` selects it (narrowed to the latest entry heading when the span holds an earlier entry's rows), instead of the first Date/Runner table. A brief whose first run failed and a later run passed is stamped with the passing run. Where that run's Runner cells lack `@ sha`, the stamp is read only when every row agrees on one date and one Runner cell; otherwise the close refuses.
- The one-step `implemented` close path now refuses, matching `verifyflip`, when the latest unstruck verdict is not the strict `**VERIFY: PASS**` (a later FAIL, BLOCKED or any other word, or a non-strict PASS), when the Evidence section has an unterminated `<!--`, when Date/Runner rows follow the PASS line, or when live content follows the PASS under a protected table. The implemented-gate sign-off card is no longer raised for a record the close refuses on any of these grounds.
