### Added
- `statusgen --corroborate --pr N` gains a findings-register transition lane: for a PR that touches `docs/streams/findings/`, every caution-removing move of a finding's `resolved` / `affects` / `ack` / `parked-until` since the PR merge-base needs a human named in the entry's authorizing key to have approved or approved-by-comment on that PR. An anchor already on the entry no longer authorizes a later change by itself. Whether a PR touches the register is read from the local tree against the merge-base, so a forge file listing that stops short (it caps at 3000 files) cannot hide a touched entry. An unresolvable merge-base with a listing that cannot be shown complete, or an unparseable touched entry, fails closed.

### Fixed
- `statusgen --corroborate` resolves the PR merge-base only from the fully-qualified `refs/remotes/origin/<base>`, with no short-name or bare-branch fallback, so a tag named `origin/main` or a local branch named `main` can no longer make the PR its own base. The ref must exist EXACTLY (`git show-ref --verify`) and merge-base runs on its object id: with the ref absent, git would otherwise expand the full name to a ref such as `refs/tags/refs/remotes/origin/main`. The offline register guards and the other `merge-base` reads of `refs/remotes/origin/main` (register-ID grandfathering, stream-cap, unrun gate) resolve it the same way. The findings-register lane reads the tree from the repository top level whatever directory it runs from, refuses a base the PR's tree is identical to while the forge lists changed files, treats only a missing entry file as a deletion, and prints entry text on one report line.
