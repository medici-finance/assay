### Fixed
- `deskevidence` now requires the Evidence section a landing adds to be one a Markdown renderer and the lint read the same way, before it checks or stamps any on-behalf-of principal. Inside a table, added lines must be `|`-led rows under a header with a delimiter row a renderer accepts, and a line that closes a table without a blank line must show no App-run or on-behalf-of text; a line after a blank line or a heading starts no table and is not read for that text. Only the cell the lint reads as Runner may show as an App-run Runner cell. A Runner cell that shows as App-run once its HTML, entity, emphasis, code-span or escape markup is removed, its link, image or autolink syntax is read as the text a renderer shows, or a closed comment is hidden, must also read as App-run to the lint, and an App-run Runner cell may not hold link, image or autolink syntax. A bracketed `[text]` that opens no link is also read as a shortcut reference link, and a cell is read for a login and tag by its structure rather than by folding the characters it knows: when its text up to the lint's cut (extended over spaces inside a tag) holds a bracketed tag of exactly three letters or digits, as `[bot]` does, or a wider tag beside any character outside the ASCII login alphabet, it is read as App-run, so a character in that text that no rule names fails closed, while text whose letters are all CJK, such as `【東京都】`, is not read as a login. Each reading is also read with every character that renders as nothing (marks, default-ignorable, control, format, private-use and unassigned code points, and the blank braille pattern, raw or as an entity) dropped, and with every leading word that holds no ASCII letter or digit skipped, whatever its characters are and whether or not they render, since such a word cannot be a login (the leading words are also read as a renderer shows them, each by itself, a word it replaces with a glyph, such as `:name:`, read as one symbol, while the rest of the text stays as written; a text holding an HTML tag with a quoted attribute value is also read with every such value emptied, since a `>` inside quotes ends no tag; a text with two or more runs of `$` a renderer can take as math delimiters (not an escaped dollar sign, one written as an entity or one in a code span, found before entities are decoded, with code spans found both by a loose match and as CommonMark pairs backtick runs of the same length) is read beside the text as written, with the text before the first run kept: once with each run and everything before it dropped, once with every run dropped and the text between them read as math, and once for each two adjacent runs from each place a control word, a brace or white space ends, that text read as math with its markup removed, a bracket, brace or bar control word read as its character (an escaped bar `\|` as a bar, never a bracket), a character code (`\unicode`, `\char` or `\mathchar` with its code) read as the character it names and, beside that, as a control word the tool does not name, each control word the tool does not name read once more alone as an opening and alone as a closing bracket and each two of them as a bracket pair, each with the argument after it both shown and taken into the bracket, and its white space both kept and dropped, and the runs are also paired from the left, inside code spans too, so no reading depends on which runs a renderer pairs; the text after a line break or block element tag is read as a line of its own; the text of a raw HTML element a sanitizer can drop, and apart from it the text of an element a renderer hides by default, such as `<rp>` or one with a `hidden` attribute (after white space, a slash or a closing quote), is read both kept and dropped: once with each ruby fallback, data list or dialog dropped to its own closing tag and each element with a `hidden` attribute after white space dropped to the next closing tag, and once without the first such element, the first two and so on, each dropped both to the first closing tag after it and to the closing tag that matches it, counting nested elements of the same name; and every trim takes any Unicode white space), so that text starts at the word a reader takes for the name, and a word in parentheses on a line that closes a table is read too. So a Runner, headerless, outside-section or no-section cell that shows as App-run under any of these readings is refused. Cells are located at the same bytes in the landed line whatever characters an HTML comment on that line holds. Rows added directly after a note line land when they are exactly as wide as the table's header and its Runner column is the last, since both readings then take the same Runner cell. Headings shown as Evidence outside the one section the lint reads (ATX, setext or HTML, with entities decoded and link syntax read as its text) take no new rows. Rows outside that section may not show as App-run. The checks are rules held by the tool rather than a full Markdown parse; each reading only adds to the others, except that a later backtick run can close a code span and take the runs of `$` inside it out of the CommonMark reading, as a renderer does, and the lint-way read of the landed section stays the last check. A text reached by several readings is read once, and the readings of one cell or line may read at most 128 MiB of text, each hidden-element reading charged before the next is built and each hidden element's end found by reading only as far as that end: their number grows with the line breaks and hidden elements a text holds, times the places a math span's text can start, times the control words and pairs of control words in it, and past the cap the text is refused rather than read with fewer readings. A raw HTML table or heading tag outside the Evidence section is looked for outside code spans found both ways. Nothing is written when a landing is refused.
- The `--brief-path` merge now puts a blank line before an appended block that opens with a table header, so a witness table appended after an attestation line starts its own table.
