### Fixed
- A pull request that adds or changes a brief's `ruling:` link (or the `decision-issue:` it points into) now has that link resolved on the forge by the decision-gate PR lane, whatever the brief's gate or status and with or without a status move. The cited comment must be unedited, sit on the recorded decision issue, name the brief, and come from a login the human-login map names as the driver; a link that cannot be resolved is refused, never skipped. The ruling resolver also now requires the comment author's account type to read `User`: any other type is refused `bot-author`, and a payload with no type is `unresolvable-link`. The staged `assay-statusgen.yml` corroborate step now also runs when a pull request touches a decision record or a `ruling:` line, not only a findings entry.
