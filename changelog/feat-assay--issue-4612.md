### Changed
- `statusgen verifyrun`: an admitted run's Verify rows no longer inherit the forge credential variables `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and `GITHUB_ENTERPRISE_TOKEN` from the invoking environment, so a row that runs the forge CLI no longer picks one up by accident. This removes ambient inheritance only; it does not keep a credential from a row that looks for one. The invoking process keeps the variables, so verifyrun's own forge reads are unchanged, and a row running as the same user can still read that process's environment (for example with `ps -E` or `/proc/<pid>/environ`). A forge CLI's or git credential helper's stored login under `HOME`, `XDG_CONFIG_HOME` or `GH_CONFIG_DIR` also stays reachable (#4612).
