### Fixed
- The hotfix overlay's root-ownership checks (`statusgen` and the desk tools) now trust a file owner only in the initial user namespace: unless `/proc/self/uid_map` and `/proc/self/gid_map` both show the identity mapping `0 0 4294967295`, the check refuses as could-not-check instead of passing a caller-owned file that reads as uid 0 under `unshare --map-root-user`. The maps are read beneath a verified procfs root with `openat2(RESOLVE_NO_XDEV)`, so a file bind-mounted over either map is refused too. The check:ci network-off helper gets the same check as every other invocation, so a hotfix there runs the pinned fallback. The refusal is reported as `hotfix could-not-check: file owners unverifiable`, not as "not root-owned". On Linux, a kernel without user namespaces (no map files) or without `openat2` (before 5.6) is could-not-check; non-Linux platforms keep the existing behavior (#6768).
