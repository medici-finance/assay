### Added
- desk-tools brief 29 is authored (authoring only, human-gated): `verifyloop verdict --unsigned-out <file>` runs a brief's check/check:ci rows and writes the canonical, unsigned verdict-v1 payload to a new file, printing its sha256, without resolving, opening or reading any key, so the rows can run in a fenced container that never holds the verifier key and the host signs afterwards. The brief states the trade plainly: the key never leaves the host, but the row commands share the container with the composer and so control the payload; the host-side binding confines a forged payload to the repo, head and time window the host dispatched. It extends `deskverdict sign` with `--expect-sha256`, `--expect-repo`, `--expect-head` and `--not-before` (each refused before any key is read), a regular-file-only payload read, and an exclusive `.out` write that never follows a link, and it writes down the host's compose-to-sign contract. Its Verify rows prove the mode never opens a key at any location the key resolver consults (`VERIFIER_PEM`, `$ASSAY_CONFIG_HOME`, `~/.config/assay`), that the host-signed result is byte-identical to today's combined path, and that the signer refuses a mismatched, linked or non-regular payload.
