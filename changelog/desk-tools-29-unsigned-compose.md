### Added
- desk-tools brief 29 is authored (authoring only, human-gated): `verifyloop verdict --unsigned-out <file>` runs a brief's check/check:ci rows and writes the canonical, unsigned verdict-v1 payload to a new file, printing its sha256, without resolving, opening or reading any key, so the rows can run in a fenced container that never holds the verifier key and the host signs afterwards. The brief states the trade plainly: the key never leaves the host, but the row commands share the container with the composer and so control the payload; the host-side binding confines a forged payload to the repo, head and time window the host recorded when it dispatched the run. The composer prints the digest only, never a repo, head or ready-to-run sign command. It extends `deskverdict sign` with optional `--expect-sha256`, `--expect-repo`, `--expect-head`, `--not-before` and `--not-after` (each refused before any key is read), and on every `--payload` call a regular-file-only payload read that neither follows a link nor blocks on a FIFO, a check that the payload's directory is not a link and no other user can write it, and an exclusive `.out` write that never follows a link. It writes down the host's compose-to-sign contract: the host passes all five flags, taking repo, head and both time bounds from its own dispatch record and only the digest, printed exactly once, from the composer. Its Verify rows prove the mode never opens a key at any location the key resolver consults (`VERIFIER_PEM`, `$ASSAY_CONFIG_HOME`, `~/.config/assay`), that the host-signed result is byte-identical to today's combined path, and that the signer refuses a mismatched, linked, non-regular or exposed-directory payload without hanging.
