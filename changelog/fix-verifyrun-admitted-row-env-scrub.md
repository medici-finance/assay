### Fixed
- `statusgen verifyrun`: an admitted row no longer finds the invoking user's stored forge login or a role credential through its environment. Before a row's shell starts, the run now removes `HOME`, `XDG_CONFIG_HOME`, `DESK_LOOP`, `CELLCTL_GH_AMBIENT`, an inherited row-read socket variable and every `GH_*` and `ASSAY_*` variable, whatever their case. Two named `ASSAY_*` variables are kept: `ASSAY_DELIVERY_SHA` and `ASSAY_DELIVERY_BASE_SHA`, the delivery coordinates the container verify runner exports, matched by exact name and only while each holds a full commit id. It also drops a `GIT_CONFIG_GLOBAL` that points anywhere except the null device. Each row gets a fresh, empty `HOME` and `TMPDIR` of its own under the run's scratch directory, removed when the row ends. The run hands its read-only credential path to a row that passes `--acceptance-forge` after this removal, as before. `statusgen rowread` inside an admitted row now forwards its request over a socket in that scratch directory. The run answers it in its own process, under the read role the row no longer has. The rowread verb's closed read set still applies, and an unreachable run gives could-not-check. This removes the pointers, not the files: a row runs as the same user and can still open a file by an absolute path it already knows, and variables outside the removed set (the Windows profile ones among them) pass through. Containment remains a runner that holds no credential but the verifier's own. Verify rows that called `gh`, `desktoken` or any other `ASSAY_*` setting (a test database DSN among them) directly from the admitted environment now get neither. Such rows must use `statusgen rowread` or run outside admission.
