### Fixed

- A cellctl shell suite whose `mktemp -d` fails no longer deletes the directory it was run from (#6161). The 18 suites under `tools/cellctl/tests/` and `tools/desk/cmd/cellctl/testdata/hotfix-e2e.sh` resolved their scratch directory as `T="$(cd "$(mktemp -d …)" && pwd -P)"` and then set `trap 'rm -rf "$T"' EXIT`. On bash 3.2 (the macOS system bash) `cd ""` succeeds, so a failed `mktemp` left `T` at the caller's working directory and the trap removed it. Each script now assigns `mktemp`'s output, checks it is a non-empty directory, resolves it, and exits 1 before the trap is set if any step fails. The Go tests that run these suites (`TestDownShellSuite`, `TestRoleContextShellSuite` and the regression floor's shell runner) now run them from a throwaway working directory. `TestScratchTrapNeverResolvesCwd` fails on any shell file in the tree that reintroduces `cd "$(mktemp …)"` ahead of a removing trap, and `TestScratchTrapFailClosed` runs a fixed suite with `mktemp` shimmed to fail from a directory holding a sentinel, under every bash on the host.
