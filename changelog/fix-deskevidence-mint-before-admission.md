### Fixed
- `deskevidence` lands Evidence rows and outcome records again. Since v1.0.33 every landing, including `--dry-run`, exited 5 with "refusing to reach the forge with no minted verifier token": pre-work admission reads the dispatcher's attestation record from the forge, and it ran before the verifier token was minted, so the tool's own custody step refused the read. The landing now mints the token and resolves its forge first, then runs admission through that same forge, so admission and the write use one forge under one minted token. Admission still runs before the landing reads the evidence file or the branch and before any write, no check is skipped or made optional, and there is still no fallback to an ambient identity. One visible change: a landing that admission or a later local check refuses (for example a `--root` that is not the dispatched verifier home, or an oversized file) now mints a token before it is refused; refusals that need only the command line, or an outcome record's own bytes, still refuse without minting.
