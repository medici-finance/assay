### Fixed
- The scan-override audit identity (`deskkit.OverrideIdentity`) now resolves to the accountable roster login instead of the raw OS account name: the new `ASSAY_OS_USER_LOGIN_MAP` roster key (`osuser:login` entries, an extension key — a malformed or off-roster value empties only that map, never the roster) binds a machine account to a trusted-human login, with the human-name map and the trusted-login set as further resolution steps. Resolved rows carry the observed OS account as `<login>(os:<account>)`; an OS account nothing resolves still produces an audit row under a clearly-marked `os:<username>` fallback — the identity label degrades, the audit write never blocks.
