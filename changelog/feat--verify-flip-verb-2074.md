### Added
- `statusgen verifyflip --brief <stream>/<NN> --sha <sha> --runner <login> [--dry-run]`: the sanctioned `implemented → verified` board flip for a `gate: model` brief (#2074). The Verified stamp is derived from the latest recorded strict `**VERIFY: PASS**` and that run's Date/Runner cells, never typed. It refuses (exit 1) on a verdict, sha or runner mismatch, a non-strict or quoted PASS, `gate: human`, any `risk: yes`, `irreversible`, a held or failing Evidence line, a Verify row without a passing execution witness, or a rewrite that would touch anything but the row's Status and Verified cells. It also refuses a Verify row classed `gate:human` (or of an unknown class), Date/Runner rows recorded after the PASS, a date that is not `YYYY-MM-DD` or is after today, a witness from an earlier run, a README that is not a regular file, and a PASS marker or Date/Runner row that `git blame` does not own to the roster's bound verifier or a roster human. No roster, a shallow clone or an ambiguous brief file is could-not-check (exit 2). `Reviewed` is never touched. An `on-behalf-of human:<name>` qualifier stays in the Evidence and is left out of the stamp, because `verify-gate-close.yml` is the only writer of `human:` stamps.
- `deskevidence flip --root <worktree> --brief <stream>/<NN> --sha <sha> [--dry-run]`: wraps `statusgen verifyflip` and lands the flip as a LOCAL commit on the worktree's branch. Both author and committer are the verifier App's bound bot identity, so the draft PR carrying the flip passes the publish-identity gate unchanged. It refuses on main/master, on a detached HEAD, when changes are staged, when the README differs from HEAD, when the branch already holds commits the publish-identity gate would refuse, when the result fails the verified-closure check, or when the change is more than one README line. It also refuses if the COMMITTED flip introduces any `statusgen --lint` PROBLEM, and takes that commit back. Nothing is pushed. The existing Evidence landing on main is unchanged.

### Changed
- `statusgen brief --check-verified` now refuses a verified closure of a brief with a Verify row classed `gate:human` unless the Verified cell names a `human:<name>`.

### Fixed
- The `git blame` reader behind the Evidence-actor lint now counts a line as content when text precedes two or more HTML comments on it (for example `text <!-- a --> <!-- b -->`). Before, the second comment reset the verdict and the line's author dropped out of the attributed set. `statusgen verifyflip` no longer reads that filtered set at all: it checks every file line behind the PASS marker and its Date/Runner rows, one by one.
