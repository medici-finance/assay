### Fixed
- `verifyflip` and the protected-table closure audit now accept one verification run whose rows carry the commit in two forms: the container bracket's 12-hex tree token and a host transition run's full 40-hex HEAD. The shorter form must be at least 12 hex and an exact, same-case prefix of the run's longest sha, and every other part of the Runner cell (login, `+dirty`, on-behalf-of, identity source) must read the same. The closure audit also asks git to resolve the short token, and it must resolve to exactly the run's full sha. A different commit, an 11-hex or 7-hex abbreviation, a substring or suffix, an upper-cased token or a different login still refuses.
- A host `verifyrun --rows` run, and the container bracket's open step, no longer stamp `+dirty` when the working tree's only change is to the brief's own `## Evidence` section, for example a container witness block inserted before the host run. Any other change still reads `+dirty`: an untracked file, a second changed path, an edit outside Evidence, a new section heading, a carriage return, or an unmerged brief. A transition run keeps the strict clean-source check, so run it on a committed tree before opening the container bracket.
