### Added
- A verifier run now carries a run-bound prerequisite record: the root revision, the desk-tools build against its pin, the host runtime, App capability evidence, the sibling checkouts the brief declares and the pinned instruments its runner-executed Verify rows call. The record is read from local materialized state only; nothing is fetched, minted or probed live.
- `deskdispatch` records that world on the run it prepares: the verifier dispatch (and `--attest-verifier` recovery) admit the brief's prerequisites against the verifier home at the run's attested source and persist them with the attestation. A prerequisite that cannot be read stops the dispatch as could-not-check with no prompt emitted, and a record is never silently replaced by a different one.

### Changed
- Evidence admission and the executor's attestation check recheck that record: a source, desk-tools build, runtime, sibling or instrument that moved after dispatch refuses the run before any Evidence is written. This applies to every run `deskdispatch` prepares, including the items `verifyloop plan` lists.
- A run `deskdispatch` prepares is marked as requiring that record before its stamp is issued. If the prepare-step admission is held or could not check, the retained run has a stamp and no record, and both row admission and Evidence admission refuse it until `deskdispatch --attest-verifier` recovery re-admits and binds it. A run prepared by an earlier build carries no mark and keeps the earlier behaviour: with no record there is nothing to recheck.
- `verifyloop plan` holds an item whose prerequisites are missing as `environment could-not-check` (or `environment hold` when an input contradicts its pin) before any Verify row is spent, keeps both distinct from a code FAIL and from a successful empty scan, and skips a root with unreadable prerequisites with that exact reason while healthy roots keep their coverage. The loop's own root is admitted at the plan's `--sha` when that is a full sha.
- Instruments are recorded and rechecked by the digest of their bytes, not by the path PATH resolved them to.
- The seventh envelope check (`run-prerequisites`) makes some roots could-not-check or skipped that were previously admitted: a root checked from an unstamped development build against a pinned desk-tools, and a host with no pinned asset for a pinned instrument. Install the pinned build, or pin the host, to clear it.
