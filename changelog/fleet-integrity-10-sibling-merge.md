### Added
- `statusgen`'s board-honesty detector gains a seventh phantom class, `sibling-merge-unreconciled`: a `todo`/`in-progress` brief whose deliverable lands in a sibling repo (`homed-in:`, `deliverable_repo:`, or a `../<basename>/` path prefix, resolved through `docs/streams/graph-repos.yaml`) can now be checked against that sibling's own first-parent git history — reading both the commit subject and body, so an id named only in a commit's body or trailer is still caught. A match is a NOTICE (never a PROBLEM) naming the sibling, the short sha, the subject and which key matched — a prompt to read the merged change Task by Task, never proof of delivery. A checked-failed `todo` row is held out of Next-up (`MergedElsewhere`, the `homed-in`/`HomedElsewhere` shape) and listed in STATUS.md's "Merged in a sibling repo — check before dispatch" section; an `in-progress` row is surfaced but never excluded. A structured `delivery:` claim in the brief's own frontmatter acknowledges a specific merged PR — `covers: partial` releases the hold, `covers: full` with the cell still unlanded keeps it with a quieter NOTICE. New `statusgen phantoms --class sibling-merge-unreconciled --root R` verb: exits 0/1/2 without touching the regen/`--lint` path, for a CI row or desk sweep that wants a red signal narrower than the whole board-honesty family. Sibling checkouts resolve via the existing sibling-checkout convention, an overridable `--sibling-root <owner>/<repo>=<path>` flag (repeatable), or the `DESK_ROOTS` environment variable already used by the desk tools.
