### Fixed
- A `ruling:` link may name a GitLab issue note (`https://<gitlab-host>/<group>[/<subgroup>...]/<project>/-/issues/<N>#note_<ID>`) when the roster binds the repository to GitLab. The host must be the configured GitLab host and the project the record's own. Online, the note is read through `deskread` and held to the same author, account-type, edit, record-naming and decision-issue rules as a GitHub comment. The note read does not report the author's account type yet, so for now every GitLab ruling is refused as `unresolvable-link` and the record stays unruled; it resolves once `deskread` reports that type. An unreadable note is refused too.
- `statusgen reconcile` (and so `deskreconcile`) reads a GitLab-hosted repository's merge requests, their file lists and its open issues' labels through `deskread`, instead of the GitHub API, which answered `HTTP 404: Not Found`. A merged MR with a `Brief:` trailer now witnesses `implemented`. The `--token-file` help no longer implies a GitHub credential is needed on GitLab.
