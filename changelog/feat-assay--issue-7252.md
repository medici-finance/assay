### Fixed
- A `ruling:` link may name a GitLab issue note (`https://<gitlab-host>/<group>[/<subgroup>...]/<project>/-/issues/<N>#note_<ID>`) when the roster binds the repository to GitLab. The host must be the configured GitLab host and the project the record's own. Online, the note is read through `deskread` and held to the same author, edit, record-naming and decision-issue rules as a GitHub comment, so a `gate: human` brief on a GitLab-hosted repository can be ruled and advanced. An unreadable note is refused.
- `statusgen reconcile` (and so `deskreconcile`) reads a GitLab-hosted repository's merge requests, their file lists and its open issues' labels through `deskread`, instead of the GitHub API, which answered `HTTP 404: Not Found`. A merged MR with a `Brief:` trailer now witnesses `implemented`. The `--token-file` help no longer implies a GitHub credential is needed on GitLab.
