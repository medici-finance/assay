### Changed
- `deskversion`, `deskmigrate`, `deskaudit` and `deskdisable` now parse their command lines with the shared Cobra adapter. Help and version print to stdout, exit 0, and run before any roster, configuration, activation, kill-switch or file read. Every documented form still works, including the Go-flag single-dash spellings (`deskversion -root D`, `deskmigrate -from vX -to vY -dry-run`, `deskdisable C -root D`). A bare `deskversion` still runs the marker read; a bare `deskmigrate`, `deskaudit` or `deskdisable` still exits 5.
- Parsing now comes before every other check, so a parse error exits 5 even where the old binary answered something else first. Two command lines the old binary refused with exit 5 now act: `deskdisable --yes C` (also `-yes C`, and any flags before the component such as `--root D --yes C` or `--cascade a,b --yes C`) disables the component and removes its files, and `deskaudit recover --` runs the recovery, which rewrites the audit log and writes a `.corrupt-` quarantine file. Both are listed again in their own bullets below. For `deskversion` and `deskmigrate`, an unknown flag, a missing flag value, a stray positional word or a missing `--from`/`--to` exits 5 before the verb-activation check; where activation is off or cannot be determined, these used to exit 6 (for example `deskmigrate --bogus`, `deskmigrate -from v0.1.0`, `deskversion --root` with no value, `deskversion -- extra`).
- `deskaudit` with the kill switch on (`DESK_TOOLS_DISABLED=1`): an unknown flag or verb, a stray argument, a bad `tail N`, `completion` and `__complete` now exit 5 instead of 3, and write no disabled-audit entry (for example `deskaudit recover extra`, `deskaudit --bogus`, `deskaudit -- recover`, `deskaudit tail x`). The real verbs (`recover`, `tail`, `tail N`, also with `--`) still exit 3.
- `deskversion` and `deskmigrate` no longer echo the effective roster config or run the activation check for help or version: `--help` and `-h` used to exit 5 or 6 after that echo or check, and now exit 0. A stray positional word is now refused with exit 5. Before, it was ignored and the read ran (`deskversion version` was a marker read).
- `deskaudit` help moved from stderr to stdout. `deskaudit tail --help` and `deskaudit recover --help` print the verb's help; they used to be refused as a bad argument. The refusal message comes in the adapter's form with a pointer to `--help`. `--` now ends the flags as usual: `deskaudit recover --` and `deskaudit tail -- 3` run the verb, and `deskaudit --version extra` prints the version and exits 0. All three used to be refused with exit 5. Of these, only `deskaudit recover --` writes: like `deskaudit recover`, it rewrites `audit.jsonl` and moves any malformed lines to an `audit.jsonl.corrupt-<ts>` file.
- `deskdisable` accepts flags before the component and answers `C --help`, `C -h`, `C --version` and `-version`. These used to be refused with exit 5. That includes the confirming flag: `deskdisable --yes C` and `deskdisable -yes C`, which used to exit 5 with `expected a component id first` and change nothing, now disable the component, exactly as `deskdisable C --yes` always did. A script that relied on the old refusal as a safety net must now treat `--yes` before the component as live. `--dry-run` before the component (`deskdisable --dry-run C`) previews and writes nothing. Help and version win over `--yes`: `deskdisable C --yes --help` and `deskdisable C --yes --version` now print help or the version, exit 0 and disable nothing, so a script that appends `--help` to a `--yes` line succeeds without acting. `deskdisable help` and `deskdisable version` still print help or the version, but no longer accept a trailing flag: `deskdisable help --dry-run` and `deskdisable version --dry-run` now exit 5, where they used to print help or the version and exit 0.
