### Changed
- `deskversion`, `deskmigrate`, `deskaudit` and `deskdisable` now parse their command lines with the shared Cobra adapter. Help and version print to stdout, exit 0, and run before any roster, configuration, activation, kill-switch or file read. Every documented form still works, including the Go-flag single-dash spellings (`deskversion -root D`, `deskmigrate -from vX -to vY -dry-run`, `deskdisable C -root D`). A bare `deskversion` still runs the marker read; a bare `deskmigrate`, `deskaudit` or `deskdisable` still exits 5.
- **Newly accepted spellings (the rule).** The old binaries read the command line by hand and refused anything they did not recognise with exit 5. The Cobra adapter accepts more spellings, and every one it accepts now reaches the verb. That covers flags before the component or the verb, `--`, a boolean flag given a value (`--help=false`, `-h=false`, `--version=false`, `--yes=true`) and the adapter's `--perf-*` flags (`--perf-role`, `--perf-work`, `--perf-profile`, `--perf-session-id`, with `=value` or a separate value). Where the verb writes, the spelling now writes. Measured on binaries built from `main` and from this branch, on a fixture where each verb can act:
  - `deskdisable` (needs an explicit `--yes`; disables the component and removes its files): `--yes C`, `-yes C`, `--yes=true C`, `--root D --yes C`, `--cascade= --yes C`, `--dry-run=false --yes C`, `--yes -- C`, `--perf-role x C --yes`, and `C --yes` followed by `--help=false`, `-h=false`, `--version=false` or `--perf-role x`
  - `deskaudit recover` (rewrites `audit.jsonl`, writes an `audit.jsonl.corrupt-<ts>` quarantine file): `recover --`, `recover --help=false`, `recover -h=false`, `--help=false recover`, `recover --perf-role x`, `--perf-role x recover`, `recover --perf-role=x`, `recover --perf-work=x`
  - `deskmigrate` (applies the selected migrations, for example `ensure-line` writes `docs/UPGRADING.txt`): `--from A --to B` with `--help=false`, `-h=false`, `--perf-role=x`, `--perf-work=x` or `--perf-role x`, after the flags or before them
  - Read-only: `deskaudit tail` now reads the log for `tail --`, `tail 3 --`, `tail --help=false` and `tail --perf-role x 3`. `deskversion` reaches its marker read for `--help=false`, `-h=false`, `--perf-role=x` and `--perf-role x`; with no pin file it now exits 6 where it exited 5. `deskdisable --dry-run C` previews and writes nothing. Spellings that used to refuse and still do: `deskdisable C` and `C --yes=false` (no confirmation), `deskdisable -- C --yes` and `C -- --yes`, `deskaudit -- recover`, `deskaudit recover extra`. Not re-measured with a real dependent: `deskdisable --cascade a,b --yes C` (it refuses on both binaries when no `a` or `b` manifest exists). If a script relied on a refusal as a safety net for any of these spellings, it no longer has one. The kill switch (`DESK_TOOLS_DISABLED=1`) still stops every `deskaudit` and `deskmigrate` form above (exit 3, no write) and `deskversion`; `deskdisable` has never checked it. The single-dash `-help=false` and `-version=false` count as boolean values too: both act on `deskdisable` and `deskmigrate`, and `-help=false` acts on `deskaudit recover` (`deskaudit recover -version=false` stays refused).
- **Tightened (now refused).** `deskmigrate --from A --to B extra` and `... -- extra` used to apply the migration; they now exit 5 and write nothing. `deskversion extra` and `deskversion -- extra` now exit 5 (they were a marker read). `deskdisable help --dry-run`, `deskdisable version --dry-run`, `deskdisable help C --yes` and `deskdisable version C --yes` now exit 5.
- **Known hazard: a `--perf-*` flag swallows the next word, even a flag.** The adapter's `--perf-*` flags take a value, so `--perf-role --dry-run` consumes `--dry-run` as the role. On `deskmigrate`, which has no confirming flag, `deskmigrate --from A --to B --perf-role --dry-run` (also `--perf-work`, `--perf-profile -dry-run`, and with the pair first) used to exit 5 and now exits 0, prints `apply:` and writes: a preview is turned into a write. `deskdisable C --perf-role --dry-run --yes` acts too, but it needs an explicit `--yes`. The kill switch still stops `deskmigrate` (exit 3, no write). The parser is the shared adapter in `tools/desk/internal/cli`, outside this change; the fix, refusing a `--perf-*` value that starts with `-`, is tracked in #5073. The same swallowing applies to `--help` and `--version`: `deskaudit recover --perf-profile --help`, `deskmigrate --from A --to B --perf-role --help` and `deskdisable C --yes --perf-role --help` all exited 5 on `main` and now act (the first rewrites the audit log), so a line that asks for help can act. Until #5073 lands do not pass a `--perf-*` flag to `deskaudit recover`, `deskmigrate` or `deskdisable` without a value.
- Parsing now comes before every other check, so a parse error exits 5 even where the old binary answered something else first. Command lines the old binary refused with exit 5 now reach the verb, and for `deskdisable`, `deskaudit recover` and `deskmigrate` that means they act (see "Newly accepted spellings" above). For `deskversion` and `deskmigrate`, an unknown flag, a missing flag value, a stray positional word or a missing `--from`/`--to` exits 5 before the verb-activation check; where activation is off or cannot be determined, these used to exit 6 (for example `deskmigrate --bogus`, `deskmigrate -from v0.1.0`, `deskversion --root` with no value, `deskversion -- extra`).
- `deskaudit` with the kill switch on (`DESK_TOOLS_DISABLED=1`): an unknown flag or verb, a stray argument, a bad `tail N`, `completion` and `__complete` now exit 5 instead of 3, and write no disabled-audit entry (for example `deskaudit recover extra`, `deskaudit --bogus`, `deskaudit -- recover`, `deskaudit tail x`). The real verbs (`recover`, `tail`, `tail N`, also with `--`) still exit 3.
- `deskversion` and `deskmigrate` no longer echo the effective roster config or run the activation check for help or version: `--help` and `-h` used to exit 5 or 6 after that echo or check, and now exit 0. A stray positional word is now refused with exit 5. Before, it was ignored and the read ran (`deskversion version` was a marker read).
- `deskaudit` help moved from stderr to stdout. `deskaudit tail --help` and `deskaudit recover --help` print the verb's help; they used to be refused as a bad argument. The refusal message comes in the adapter's form with a pointer to `--help`. `--` now ends the flags as usual: `deskaudit recover --` and `deskaudit tail -- 3` run the verb, and `deskaudit --version extra` prints the version and exits 0. All three used to be refused with exit 5. `deskaudit recover --` writes, as the "Newly accepted spellings" bullet above says.
- `deskdisable` accepts flags before the component and answers `C --help`, `C -h`, `C --version` and `-version`. These used to be refused with exit 5. That includes the confirming flag: `deskdisable --yes C` and `deskdisable -yes C` used to exit 5 with `expected a component id first` and change nothing; they now disable the component, exactly as `deskdisable C --yes` always did. `--dry-run` before the component (`deskdisable --dry-run C`) previews and writes nothing. Help and version win over `--yes`: `deskdisable C --yes --help`, `C --yes --version` and `C --yes -version` print help or the version, exit 0 and disable nothing (they exited 5), so a script that appends `--help` to a `--yes` line succeeds without acting. `deskdisable help` and `deskdisable version` still print help or the version, but no longer accept a trailing flag: `deskdisable help --dry-run` and `deskdisable version --dry-run` now exit 5, where they used to print help or the version and exit 0.
