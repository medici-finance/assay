### Added
- `ask-decision` Reply shape now carries the exact command for the recommended option, ready to paste: a ruling is `t="$(gh auth token --user <driver-login>)" && [ -n "$t" ] && GH_TOKEN="$t" gh issue comment <N> -R <owner>/<repo> --body '<ruling text>'`, and an act the driver performs is the matching `gh` command behind the same prefix (a merge pins the reviewed head with `--match-head-commit <sha>`). The command fails closed: if the driver's token cannot be read, nothing runs, so a ruling never posts under an exported App token or whichever account is active. When no single command expresses the option, the skill says so instead of inventing one.
- `assay-inbox.sh --walk` / `--html` render a `command:` line in Reply shape. It is derived only when the issue's author is trusted (roster), exactly one visible option carries the standalone `(recommended)` marker (no other option mentions "recommend", and no negated form such as `(not recommended)` counts), and a phrase visible on the rendered page names that option's letter (a "How to answer" quoted phrase, or a fork-test `default:` naming its own `option:` letter). An Options block, phrase or default inside an HTML comment or a Markdown link-reference definition, a phrase carrying a Unicode format character, or a `<placeholder>` template is never used. The text is single-quoted for the shell, with the login taken from `DRIVER_LOGIN` when that is login-shaped. Otherwise the line reads `command: not derivable — desk to fill`. `deskinbox walk` / `html` read no roster, so they always print the not-derivable line.
