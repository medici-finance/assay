### Added
- `verifyloop verdict --unsigned-out <file>` runs the Awaiting queue's check/check:ci Verify rows, composes ONE canonical verdict-v1 payload over them and writes it UNSIGNED to a new file, printing one line that carries only its sha256. It resolves, opens and reads no key (not `--pem`, which it refuses alongside `--dry-run` and `--window`; not `VERIFIER_PEM`; not any config-home `verifier-app.pem`), never prints a fenced verdict body, and on any non-zero exit leaves no file of its own and prints no digest. The rows can therefore run in a fence that never holds the verifier key; signed on the host, the result is byte-identical to the combined path's body for the same rows.
- `deskverdict sign` gains `--expect-sha256`, `--expect-repo`, `--expect-head`, `--not-before` and `--not-after`. Each is optional, each one passed is checked before the signer key is resolved, and a mismatch, or an empty or unparseable value, is a refusal (exit 5) with nothing on stdout.
- The host contract for a split run, stated in `verifyloop` usage: the host writes its own dispatch record (repo, head sha, dispatch time) before starting the fence and runs the composer with `--repo`/`--sha` from it; signs only after the composer exited 0 with exactly one `sha256=` value and the fence has fully exited; passes all five binding flags, taking repo, head and both time bounds from its own dispatch record and only the digest from the composer; takes the signed body from stdout, never from a `.out` the fence could write; and signs only a payload moved by rename into a directory the composing uid cannot write. The binding bounds a forged payload to the run the host dispatched; it does not prevent a hostile row from inventing results within it.

### Changed
- `deskverdict sign`, on every `--payload` call with or without the new flags, now refuses (exit 5) a payload that is not a regular file (a link, FIFO, device or directory) or, on unix, sits in a directory that is a link, is writable by group or other, or is not owned by the signing user. It opens the payload without following a link or blocking on a FIFO and reads it once. It creates the `.out` sibling exclusively and never writes through a link, so an existing or unwritable `.out`, which used to be overwritten or skipped with a note (exit 0), now exits 5 with the signed body on stdout only.
