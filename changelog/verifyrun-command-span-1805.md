### Added
- Verify rows can name their command explicitly: in a Command cell that mixes prose and code spans, a code span starting `cmd:` (for example `` `cmd: go test ./pkg/ -count=1` ``) is the command. `statusgen verifyrun`, the check:ci re-execution lane, `newbrief`, the row lint, `verifyloop` and `deskrebaseline` all take the first `cmd:` span. A cell whose first span is already its command needs no marker. A cell without the marker lifts exactly what each tool lifted before, so no existing row changes command or verdict. A marker counts only where the rendered brief shows it as code: one between escaped backticks, or in a cell whose prose carries raw HTML, a comment, a link or an image, is ignored, so hidden text cannot replace the command a reader sees.
- `statusgen --lint` NOTICEs a prose Command cell whose first code span is a mention rather than a command, such as a function name, a file, an `owner/repo`, or a word ahead of the real command (`prose-led-command`). It also NOTICEs a cell that carries two `cmd:` markers (`cmd-marker-ambiguous`). It NOTICEs a marker that replaces a command-shaped first span (`cmd-marker-overrides-command`) and a `cmd:` span that is not honoured (`cmd-marker-not-honoured`). All four are advisory, so main stays green.

### Fixed
- The check:ci verdict re-execution lane now runs the command lifted from the Verify cell, not the raw cell text. Before, the shell read the cell's backticks as command substitution.
- `verifyloop` and `deskrebaseline` now honour the `cmd:` marker. Before, they ran the whole prose cell.
