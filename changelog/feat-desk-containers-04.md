### Added
- `containers/desk-run.sh <desk-name>` starts one of the five desk images interactively from a desktop: it validates the desk name and the PEM and env-file locations (refusing, naming the override or the default location and never printing back a path you supplied, rather than falling back to other credentials), mounts the PEM read-only and passes the env-file per the runtime credential contract, and never prints a credential value. The default PEM is per desk (`<config>/assay/<desk-name>.pem`), so two desks on defaults never mount the same file; the launcher mounts the file it is given and does not decide which App the desk acts as. An override given empty (`--pem ""`, an empty `ASSAY_DESK_PEM_FILE`, and the env-file equivalents) is refused, not read as unset. `--dry-run` prints the exact `docker run`; `--attach` starts an existing desk container again into a new shell with its work volume and refuses `--pem` and `--env-file`. The launcher suite runs in CI.
