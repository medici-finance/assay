### Fixed
- `deskflip` checks-green, `deskautolane` merge checks-green and `deskpost ready` now read the check suites at the head, not only the check-run rollup. A suite with no conclusion and zero runs never appears in the rollup but still holds the forge's merge gate, so a green rollup flipped or merged a head the forge reported `BLOCKED`. Such a suite now holds checks-green as could-not-check (exit 6), as do a failed or short suite read. A later suite of the same app AND the same workflow that concluded with runs supersedes a stuck one; a later suite of another workflow, or a suite whose workflow is unknown, supersedes nothing. An installed app that never reports at the head is ignored.
- New read-only forge method `CheckSuitesAtHead` (GitHub: `commits/{sha}/check-suites`, plus `actions/runs?head_sha=` to name each Actions suite's workflow, read only when an Actions suite is unconcluded and needing `actions: read`, a failed read failing closed; GitLab: no suite concept, answers an empty set with no request).
