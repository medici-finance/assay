### Fixed
- `pr-monitor.sh` and `inbound-monitor.sh` no longer poll with the ambient `gh` login. Each repo is now read under its own installation token, minted inside the poll with `desktoken <role> --repo <owner>/<repo>` (the role comes from `$DESK_LOOP`) and handed to that single `gh` read only. A mint that fails, or a loop with no role, reports `MONITOR-DEGRADED: <repo> token mint FAILED (...)` for that repo, keeps its previous state, makes no `gh` call and exits 2; it is never shown as an empty result and never falls back to the ambient login. Installs without `desktoken` on `PATH` see every repo degraded (inbound can still name an owner's token with `--token-file`). The minted token is read from its custody file once, checked, and that same value is what `gh` receives, so another session re-minting the shared cache mid-cycle can no longer hand `gh` an empty token.
