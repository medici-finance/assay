### Fixed
- `statusgen --scan-issues` and `--transcribe-scan` now re-derive a reactivated placeholder's `gate:` and `labels:` from the live issue when it reopens (or loses an excluded label), instead of carrying the retired file's stale frontmatter forward — a reopened issue that gained a risk label now comes back `gate: human` rather than staying `gate: model`. Only a stored gate that is exactly `model` takes the live derivation on reactivation; any other stored value (human quoted, commented, padded, mixed-case or folded, or implied by stored risk labels, as the reader decodes it) stays human, a `labels:` flow list wrapped over indented lines is replaced whole, the dry run prints the gate a reactivation will write (a stored human gate shows as `gate:human`), and a reactivate built without the live issue is refused.
