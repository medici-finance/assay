### Fixed
- `deskflip` and `deskpost ready` no longer revert a ready flip on a `BLOCKED` read alone. GitHub works out that merge state for whoever reads it, so a role App that is not allowed to merge reads `BLOCKED` on a change its maintainer can merge. On a non-draft `BLOCKED` read, both verbs now read the merge requirements that look the same to every reader: no merge conflict, the review decision, and every required check at the head (classic branch protection, rulesets, and the checks the rollup marks required). Any unmet requirement reverts the flip, and so does a requirement read that fails, with the comment naming each one. When every requirement is met, the change stays ready with one could-not-check comment. `DIRTY` still reverts. A head an earlier release reverted on a `BLOCKED` read alone can be flipped again, and its new flip is judged on its requirements.
