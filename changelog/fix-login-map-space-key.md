### Fixed
- An `ASSAY_HUMAN_LOGIN_MAP` (or `ASSAY_FORMER_HUMAN_LOGIN_MAP`) entry whose name has a space between its words, such as a GitLab display name, no longer refuses the whole roster: that one entry is not applied and the config echo names it in a `NOTICE`, while every other entry and key still loads. The human it names gets no mapping, so a write that needs their neutral name still refuses. A name containing any other whitespace character (a no-break space, for example) is refused the same way instead of being mapped. A space directly before the colon (`ada :login`) still refuses the whole roster, and entries are still separated only by a comma, semicolon, line break, space or tab.
