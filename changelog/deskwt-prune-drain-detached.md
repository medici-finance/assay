### Fixed
- `deskwt prune` now drains a clean, unlocked worktree whose HEAD is the `origin/main` tip — including the detached-at-main shape reclaim flows leave behind — once it is past the one-hour fresh-worktree safety window and carries no uncommitted, untracked, or git-ignored content; anything else is still held.
- `deskwt prune` clears stale worktree registrations whose directory survives but whose `.git` file is gone (previously immortal when locked: `git worktree remove` refuses them and `git worktree prune` keeps them). Clearing is registration-only — the directory is left on disk — and gated: the usual scope gates apply, an admin HEAD must name a valid branch resolving to a commit or a detached commit proven on `refs/remotes/origin/main`, and a locked registration clears only after `--reclaim-stale-locks` proves the lock stale; the default sweep never retires a lock.
- Failed registration clearing and unverifiable lock reclamation attempt to restore original locks. A restoration failure stops later pruning, reports could-not-check, and leaves surviving registrations for operator recovery.
