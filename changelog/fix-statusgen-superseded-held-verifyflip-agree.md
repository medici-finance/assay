### Fixed
- `statusgen verifyflip` and `statusgen brief --check-verified` now read a latest PASS run's Runner cells the same way (#6767). A run recorded twice, once in the verifyrun witness table (`(forge-identity)`) and once in a hand Expected/Observed table naming the model (`(<model> verifier)`), reads as one runner when both name one login, one sha and the same principal. Another principal, a conflicting identity source or a cell that is not a clean qualifier list still refuses, and `--check-verified` now refuses it too instead of admitting it. A superseded HELD or COULD-NOT-CHECK line followed by a later full PASS no longer stops the model autoflip once that PASS run carries a passing execution witness for every Verify row, the check verifyflip already makes. On that read, a hand restatement row whose clean outcome carries a neutral note reads clean beside the tool's clean row for the same key, and a one-line bullet in the latest entry, such as a RISK-VALUE line, is read as prose even when it contains a `|`.
