### Fixed
- `deskwt prune --reap-dead-sessions` now reaps a dispatched home whose dispatch claim has been released, even if its agent left a bare `git worktree lock` on it. Before, no roster beacon could ever prove such a lock stale, so these homes piled up without bound. The existing safety gates still decide: the tree must be clean (untracked files included), every commit must be on the remote, and the tree must be idle past `--min-idle` (#6847).
- A dispatched home whose claim is still held, or whose claim listing cannot be read, is now held by every `deskwt prune` arm and refused by `deskwt remove`, locked or not. An unlocked home of a live run no longer reads as unowned (#6847).
- `deskdispatch` now records where a run's claim was taken (`assay.claimRepo`, `assay.claimStore`) in the home, and `deskwt` reads the claim only there. A key missing from this checkout's listing proves a release only for the repository and store the claim was taken in, so a cross-repository verifier's live claim no longer reads as released. A home recording no namespace (made before this change), a non-forge-ref store or a different repository is held and reported as could-not-check; `deskwt remove` refuses it (#6847).
- `deskwt` re-reads the claim just before it removes a released home and keeps the home if the claim was re-acquired or the re-read fails. The claim listing now runs with a scrubbed git environment, batch-mode ssh and a timeout (#6847).
- The claim listing keeps a claim key that contains `/`, exactly as the claim tool lists it, so such a held claim holds its home instead of reading as released. One sibling worktree entry that cannot be inventoried no longer makes the claim check hold every other tree: the run key is read from the tree's own entry, and a tree whose own entry cannot be confirmed is still held (#6847).
- `deskwt remove` accepts a bare-locked home whose claim has been released. Its clean and pushed checks still apply (#6847).
- `deskdispatch` now removes the home it just created when a later step aborts and the claim release succeeds. It does this through `deskwt remove`, so all of that verb's gates apply. A resumed worker's home, a verifier's home and a home whose attestation failed are kept (#6847).
