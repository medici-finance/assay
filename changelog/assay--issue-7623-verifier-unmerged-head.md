### Added
- `deskdispatch --kit verifier --target-change N --target-head SHA` names an unmerged change head for a pre-merge verifier pass. The target is inert for now: every one is refused until a credential-less, contained runner exists, because a host-lane Verify row runs as the desk's OS user with every same-user credential in reach. Behind that refusal, admission is off by default (the repository must opt in on the roster key `ASSAY_VERIFIER_PREMERGE_REPOS`) and needs, at exactly that head, the reviewer App's approval and its security lane's `Security-Review: pass`. The head branch must be in the base repository, the author must be a trusted role App or accountable human, and the author must not be the verifier, reviewer or dispatching desk. A moved head voids the run at every use point, and an unreadable forge is could-not-check. A pre-merge run never lands Evidence and is never credited; the merged-main verification is still owed.
