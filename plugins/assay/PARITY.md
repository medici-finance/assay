**[`SOURCES.yaml`](./SOURCES.yaml) is authoritative for provenance.** It records
per file whether it is `canonical:` (the home), `files:` (still ported — two
today, `dailies` and `intake-desk`), or `unported:` (authored here, never had a
source), with porting history in `notes:`. **If this file and `SOURCES.yaml` disagree, `SOURCES.yaml` wins.**
The division is: **`SOURCES.yaml` declares the home, PARITY.md explains the
history.** For *why* something was changed or dropped, this file wins; nothing
in the manifest carries that.

Check the state rather than reading it off the page — `make plugin-drift`
reports coverage + drift (advisory: exit 0 even with drift present, but still
exit **2** on a coverage failure, which is a hard error in both modes;
`make plugin-drift-strict` exits 1 on any drift). Post-flip it reports
`DRIFT (behind 2) across 2 origin(s)`: the five flipped rows and the two
`unported:` rows carry no origin and so are never compared, while `dailies` and
`intake-desk` remain pinned and do drift. Note also that neither mode runs in
CI — the workflow for `tools/plugindrift` exercises the offline coverage
accounting test, not the network drift check — so this is a command somebody has
to run, not a gate that reddens a pull request.

Re-sync procedure — still the procedure IF a future brief ports a file back into
`files:` (it is not needed while the flip stands):

1. Run `make plugin-drift` first — it tells you which files actually moved and by how many commits.
2. Re-fetch each drifted row's source path at the source repo's current `main`.
3. Diff headings first (`grep -E '^#{2,3} '`) — section-level adds/drops are the cheapest drift to
   spot. **Then diff the bodies of the sections that survived.** A heading diff is blind to a rule
   deleted, softened or re-scoped *inside* a retained section, and that class has already shipped
   here twice (see [Known-behind](#known-behind--cleared-by-the-flip)): a `git -C` scoping guard
   turned into a bare command, and a mergeability precondition on the ready-flip lost entirely. Both
   sat under headings the heading diff reported as present.
4. Port the deltas and re-apply the intentional changes below.
5. **Update `SOURCES.yaml`** — `commit`, `blob` and `as-of` for every re-ported entry. Do not hand-edit
   `blob`; read it back from the source
   (`gh api repos/<repo>/contents/<path>?ref=<commit> -q .sha`). **Then re-run `make plugin-drift` and
   confirm every entry reports `in-sync`.** This step is part of a re-sync, not optional cleanup: skip
   it and the manifest is pinned to a commit the bundle no longer matches, which is worse than no
   manifest — the checker would report `in-sync` against a stale baseline.
6. Update this file to match — the as-of date in this section, the canonical-files table, and the
   [Known-behind](#known-behind--cleared-by-the-flip) section.
7. Bump the plugin version and record the new as-of date + drift-check result in `RELEASE-NOTES.md`.

**Adding a skill to the bundle** (not a re-sync): the checker asserts coverage before it checks drift
— every `skills/*/SKILL.md` must be declared in `canonical:` (either canonical-here, or still pinned
via a `source:` block) or in `unported:` with a reason, and it exits 2 on a file in neither. So a
skill ported from upstream and added without a manifest entry fails the check rather than passing
unnoticed; a skill authored here goes in `unported:` and says why it has no source. Today: **5
canonical-here** (the flipped skills — 0 `files:` rows remain for them), **2 still pinned** via
`source:` (`dailies`, `intake-desk` — added by later briefs, out of scope for this flip), **2
unported** (`adopt`, `market-intelligence` — both authored in this repo), **0 unaccounted**. `dailies`
was added under assay-selfcontain/10; `intake-desk` under education/04, Phase 0 ruling 2 — see the
file-mapping table below and [education/04 — intake-desk scrub](#education04--intake-desk-scrub) for
the difference between them: dailies is a straight re-port, intake-desk is not.

## education/04 — intake-desk scrub

**Ported on 2026-08-12, from `medici-finance/assay` `.claude/skills/intake-desk/SKILL.md` @
`1c317782` (blob `d624efb5`).** Unlike every row above (rows 1–6, all straight re-ports per the
assay-selfcontain/08 snapshot), this row is a **scrubbed** port — it is expected to report
`behind`/diff against its recorded source blob in `SOURCES.yaml`, and that diff is the scrub, not
staleness. Phase 0 ruling 2 (`docs/education-plan.md`, human:<name>, 2026-08-11) requires this: the taught
five-desk pipeline (`intake-desk → worker-desk → pr-review-desk → verify-desk`) is not installable
whole without its front door, so intake-desk joins the four desk-role skills already in the bundle
(rows 2, 3, 5, 6 — `the-desk`, `worker-desk`, `pr-review-desk`, `verify-desk`) — but as house
material entering the **public** bundle for the first time, it carries the same scrub-before-shipping
gate the #623 track applied to those four originally (leaksweep + independent Security-Review before
any public copy; leaksweep is necessary, not sufficient).

**What changed, and why:**

- **House repo slugs → generic phrasing.** The source names a specific set of owned repos (a
  primary tracker repo, several product/tooling repos, several report/deck repos) by slug, in the
  boot-sequence "owned-repo set" enumeration. The port replaces the enumeration with the general
  shape (a project-local owned-repo list, kept in sync with the scanner's own coverage) — an adopter
  has no such repos and the concrete list is meaningless to them; the shape survives, the slugs don't.
- **Internal issue numbers dropped.** The source cites roughly two dozen internal issue numbers as
  evidence for specific rules (coverage gaps, claim-key collisions, a close-on-merge lesson, and so
  on). None of those issues exist in a fresh adopter's tracker, so each citation is replaced with the
  rule it was evidence *for*, stated plainly (e.g. "a fix merged with a cross-reference marker
  instead of a closing one never auto-closes the issue" survives; the issue number that taught it
  does not).
- **Persona reference genericised.** The source excludes a named persona from this skill ("the
  persona belongs to `the-desk` only"); the port keeps the exclusion but drops the name, matching the
  de-personalisation the four desk-role skills received at v0.1.0 (now superseded in *their* bundled
  copies per the "Known-behind" section below, but still the right call for material entering the
  bundle for the first time).
- **A named trust-anchor identity genericised.** The source's trust-gate paragraph names a specific
  account whose blessing unlocks quarantined inbound items. The port describes the mechanism (a
  blessed identity, configured per-project — see the roster/trust primitive in the adoption runbook)
  without the name.
- **The superseded self-dispatch step is NOT ported**, per the brief's explicit instruction. The
  source's issue-lane step 2 carries both the **rule** (`F-desk-emits-briefs`: this desk emits
  placeholders only; fanning workers out against them is `worker-desk`'s job, not this desk's) and a
  large block of **now-superseded mechanics** "retained for reference" (the claim protocol, a worker
  prompt template, a research-dispatch rule, review-verdict evidence handling). The port keeps the
  rule — stated as plainly as the source states it — and drops the retained-for-reference mechanics
  entirely: they duplicate `worker-desk`'s own contract, they are not this skill's to teach, and
  porting them risks exactly the softened-guarantee failure mode this brief's `exec-tier-why` calls
  out (an adopter reading dispatch mechanics inside *intake-desk* could reasonably conclude this desk
  still dispatches). `grep -n "self-dispatch\|DISPATCH"` against the ported file returns nothing.
- **House-internal backlog section dropped.** The source's closing section ("This desk owns
  finishing the issue-loop stream") is a to-do list of the source repo's own remaining work, keyed to
  specific brief numbers and a specific finding. It is not portable methodology and is not ported.
- **The hourly worktree-hygiene aside dropped.** The source's "Hourly hygiene tick" subsection names
  a specific incident, a specific script path in a specific sibling repo, and a specific abbreviated
  repo name. The substantive point (periodic worktree pruning prevents file-handle exhaustion) is
  already carried generically by boot step 0; the house-specific aside is not ported.
- **Config/token paths genericised.** `~/.config/<org>/*` token and App-config paths become
  `<token-path>` / "the project's own role-to-App config", matching the `$REVIEWER_TOKEN_PATH`-style
  placeholder convention `docs/adopting-assay.md` already uses for the reviewer App's token path.
- **`human:<name>` examples.** Every reference to the human decision-maker by name becomes "the
  human driver," matching the convention the four desk-role skills' original v0.1.0 port used (see
  change 11 below) for the same class of substitution.

**What did NOT change:** the five-exits table, the four desks' roles and hand-offs, the model-tier
gate and its rationale, the board-tool shape, the full issue-lane loop (minus the dropped dispatch
mechanics above), the full intake-lane loop and its routing test, the escalation-label and

### 12. Sub-section rule drops found and RESTORED — and the audit limit that hid them

Changes 9 and 10 were produced by a **heading-level** diff (step 3 of the re-sync procedure as it was

| Restored rule | Skill | What the drop did |
|---|---|---|
| **Scope the resync to your worktree with `git -C` — never bare `git reset --hard`** | verify-desk | The bundle shipped the bare form with a safety rationale reading "this worktree holds no local work, so a hard reset is safe". ## Verdict

**The bundle is the canonical home of the five method-text skills, and the consumers read them.**
Stated precisely, as of the harness-portability/02 flip (2026-08-11):

- **Five `canonical:` declarations with no `source:`, out of seven total `canonical:` rows.** The
  method-text skills (`author-brief`, `the-desk`, `batch-fanout`, `verify-desk`, `pr-review-desk`) are
  canonical-here — no upstream, nothing to drift against for those five. `adopt` and
  `market-intelligence` are authored here (`unported:`). `plugindrift` reports 0 behind, 0
  unreachable, 0 unaccounted for these seven files — which for them means *nothing was compared*,
  not *a comparison came back clean*. Repo-wide `--fail-on-drift` exits **1**, from the two pinned
  rows below.
- **Byte-current with the canonical bodies at the flip — a date, not a standing property.** The 02
  final re-sync ported the two deltas that had landed since `ff57ba34` (`batch-fanout` @ `46397cf`,
  `pr-review-desk` @ `83e61b4`) verbatim, with no intentional changes; the other three were already
  in-sync. Two days later that equality was gone: measured 2026-08-13 against
  `refs/remotes/origin/main`, all five flip targets read BEHIND their pre-flip pins by 1/8/18/6/12
  commits. Nothing re-establishes or re-checks the equality after the flip.
- **Consumers are one-directional.** the tracker holds no desk skill bodies (removed at the 08 consumer
  cutover; its CLAUDE.md breadcrumb names the home) and `~/.claude` holds thin pointers. This repo's
  `.claude/skills` copies are **not** declared consumers of the bundle and no check relates the two
  trees; today every one of the seven bundled bodies differs from its `.claude/skills` namesake.
  Any future check across them must be substitution-aware rather than a byte-diff — the bundle
  copies are deliberately scrubbed ports, and a byte-equality gate would undo the scrub.
- **`dailies` and `intake-desk` are NOT flipped — still pinned, still measured.** Both were added to
  the bundle by later, independent briefs (assay-selfcontain/10, education/04) after this flip's scope
  was set, and remain `files:` rows carrying a `source:` block against
  `medici-finance/assay`'s `.claude/skills/`. Being pinned, they still drift: measured
  2026-08-13 both report `behind` (`dailies` 1 commit, `intake-desk` **14**, up from 4 earlier the
  same day), which is why
  `plugindrift --fail-on-drift` still exits 1 repo-wide — the flip ends the port relationship for the
  five rows it names, not for these two. `dailies` is a straight re-port, byte-identical
  to its recorded blob. `intake-desk` (row 7) is a **scrubbed** port, not a straight re-port — see
  [education/04 — intake-desk scrub](#education04--intake-desk-scrub); expect it to report drift
  against its recorded source blob by design, and Independent Security-Review is required before it
  is treated as publication-safe. Bringing either row under a future flip, and re-applying the v0.1.0
  port transforms as reusable parameterisation, are the explicit follow-ups
  **assay-selfcontain/09** (parameterisation) and a later brief (dailies/intake-desk flip) — not this
  one.

These statements are what an adopter needs; none of them is "no silent behavior change."

## External marketplace pins (ui-craft/02, ruling #1024)

Provenance for plugins the house marketplace serves from an **external** repo — pinned in
`.claude-plugin/marketplace.json`, checked by `tools/plugindrift`'s marketplace check (same
vocabulary: in-sync / behind / moved / unreachable). Nothing external is vendored into this
bundle: the catalog carries a sha-pinned pointer, the code stays in the pinned fork.

| Plugin | Source | Pin | Mechanism | Intentional deltas vs upstream |
|---|---|---|---|---|
| `impeccable` | `medici-finance/impeccable` (fork of `pbakaus/impeccable`, Apache-2.0), subdir `plugin/` — the compiled Claude Code dist upstream's own marketplace serves | tag `skill-v4.0.4` = commit `9a949fb543d44cfb406f61bcab99d95d7f12cf1d` (sha is the pin; tag is the human name) | git-subdir catalog entry per the #1024 Option-6 ruling (2026-08-14) | none in the pinned tree. House-specific context lives OUTSIDE the pin as the overlay (`docs/brand/impeccable/`): brand-seeded PRODUCT/DESIGN, the ui-craft/01 detector ignore seed, slop-lint non-override |

Facts an adopter/re-pinner needs:

- **Two version tracks** (spike §0): `skill-v*` tags version the content; the npm CLI is
  versioned separately (`cli-v3.5.0` = `impeccable@latest`). `impeccable@4.0.4` does not resolve
  on npm; there is no `doctor` subcommand.
- **Marketplace auto-update stays OFF** for this catalog (the third-party default). Enabling it
  would silently undo the sha pin — re-pins are reviewed catalog PRs (ui-craft/04 cadence),
  surfaced by `plugindrift` as `behind` (upstream moved) or `moved` (tag re-pointed).
- **Security surface:** the pinned subdir ships node scripts and PostToolUse/Stop hooks that
  execute on every consumer machine (Node ≥ 22). Independent Security-Review of the fork at the
  pinned sha is the ui-craft/02 DoD item — a leaksweep pass is not that review.
