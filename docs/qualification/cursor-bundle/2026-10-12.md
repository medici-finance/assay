## Source and consumers

`plugins/assay` is canonical. `internal/cursorbundle` owns source selection,
placement/ownership, and versioned archive verification. Both deskinstall and
upgrade-assay consume it. The release and staged release workflows package,
checksum, and upload the same asset; dispatch stamping and post-release version
rolling regenerate self-hosted copies, while tag-push validation is read-only.
The image build continues consuming canonical plugin source, not root Cursor copies.

Runtime copies exclude canonical component declarations. `deskmanifest` optionally
reads strict declaration bindings; this repository retains its Claude declaration.
This changes neither launchers nor runtime roster-key activation. Tests cover absent
selection, malformed/unknown selection, missing evidence, dependency propagation,
and runtime trust invariance. Local-content preservation is preflighted, not a
cross-file transaction. Published SHA verification is integrity, not provenance.

## Review repair: HTTP archive size

Correctness review 5495599797 at `fe1028fa2d033239ddd0dd7546f8f68ff76eb187`
raised F-bundle-fetch-size: the metadata HTTP reader silently truncated archive
responses to 1 MiB even though the verifier accepts 16 MiB. Both CLI regressions
ran before changing that reader, using a local HTTP server and the production
HTTP client; the transport redirects only fixture asset requests to that server.
No release or production endpoint was contacted.

The repair separates metadata and archive fetchers. Metadata retains its 1 MiB
limit; Cursor HTTP acquisition, local acquisition and verification share one
16 MiB constant. Both readers consume at most limit+1 and explicitly reject
oversize responses instead of returning successful truncated bytes.

The two CLI tests now require real HTTP preview/apply/check to succeed above
1 MiB, verify exact placed support bytes, and reject over-limit responses in all
three modes without changing the adopter. Streaming boundary tests accept exactly
each limit and reject limit+1 without relying on Content-Length; 404 classification
and offline archive isolation remain covered. Metadata opt-in alone cannot enable
an archive request. Both CLI consumers explicitly enable both readers under their
existing --fetch option. The previous opt-in fixture now injects the archive
fetcher, preserving its announcement and no-network-by-default assertions.
