# Brief 02 — Standardize on rulesets, retire classic protection

## Context

files:
- `docs/streams/server-controls/readable-standardization.md` (planned) — the migration runbook +
  the deskflip readability contract this brief produces.
- `docs/streams/server-controls/README.md` — brief-table row (generated by statusgen regen).
- `changelog/server-controls-02-readable-standardization.md` (new) — highlight fragment.

facts:
- deskflip's checks-green gate reads required status checks from the rulesets API through the
  deskkit forge layer. On a classic-protection repo the rulesets read names no checks, so the
  gate reports could-not-check — the #1020 symptom.
- Two closures (DR-server-controls records the choice): (a) **standardize on rulesets**
  — migrate each classic repo to an equivalent ruleset, so one readable API covers every repo
  (chosen default, no widened grant); (b) grant the App **administration: read** and read the
  classic endpoint (`GET repos/{owner}/{repo}/branches/{branch}/protection/...`) as a fallback —
  kept only for a repo that cannot yet migrate.
- The **honest readability rule**: could-not-check is correct ONLY when BOTH sources (rulesets
  AND, where the grant exists, classic protection) are empty. A repo with a ruleset that names
  checks is readable and must not report could-not-check.
- The migration itself and the grant are repo-admin / permission acts; this brief writes the
  runbook and the readability contract, it applies neither.

## Task
1. Write `docs/streams/server-controls/readable-standardization.md` (planned): a **migration runbook** —
   for a classic-protection repo, the equivalent ruleset that reproduces its enforced settings
   (mapping each classic setting to its rulesets field), the read-back that proves the migration,
   and the order (add ruleset → verify equivalence → remove classic protection, never the reverse).
2. State the **deskflip readability contract**: it reads rulesets; could-not-check is emitted ONLY
   when every readable source is empty; a repo naming checks in a ruleset is readable. Specify the
   code boundary in `forge_github.go` (implementation is follow-up server-controls/02).
3. Document the **administration: read interim**: the classic endpoint, the grant it needs, and
   that this path is the fallback for a not-yet-migrated repo, not the default.
4. Cross-reference brief-01's audit as the input (which repos are classic) and DR-server-controls
   as the design rationale.
