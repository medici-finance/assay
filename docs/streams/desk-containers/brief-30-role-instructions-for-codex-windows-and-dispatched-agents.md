facts:
- **What exists.** `CELL_ROLE_CONTEXT` names one operator-owned JSON declaration (`{"version":1,"roles":{<role>:{...}}}`). Its `instructions` key is a file whose text is appended to the role window's system prompt (`--append-system-prompt`). It is not passed to agents the window dispatches. An agent definition with `inherit_instructions: false` (the shipped `builtin:lean-reviewer`) starts without the project's instruction files too, so today a rule that lives only in a role file reaches no dispatched agent at all.
- **Codex today.** A role whose resolved harness is not Claude Code and whose entry is non-empty is refused ("only the Claude Code binding exists"). The Codex argv already carries `-c` overrides from the model policy and ends with the role prompt as its last argument.
- **Custody.** The whole Claude binding travels inline on the command line, which the harness ranks above every settings file a session can write. The declaration and every file it names are refused when they lie under `<cell-dir>/worktrees/`, `<cell-dir>/memory/`, or a tree a `worktrees/` entry leads to. cellctl decides this by file identity, never by spelling: `refuseSessionWritable` (`tools/desk/cmd/cellctl/rolecontext.go:323-403`) resolves the path and compares it and each directory above it with every such place through `os.SameFile`, and fails closed when a place cannot be examined. Writing role rules into a role worktree's `AGENTS.md` (the resident-rules precedent) would put them where the session can edit them, so this brief does not do that.
- **The dispatch side.** deskdispatch assembles each prompt in `assemblePrompt` from the common clauses and one class kit, quoted verbatim, chosen by `--kit` from a closed set (`worker`, `worker-objective`, `review`, `verifier`). A shepherding run is a `--pr` run whose kit is neither `review` nor `verifier` (`workerResume`, `resume.go:42-43`), so it runs with `--kit worker` or `--kit worker-objective`. The kit vocabulary is already shared: `deskkit.DispatchKits()` (`dispatchrecord.go:115`), held equal to the kit map by `TestRecordKitsAgree`. The dispatch record is the closed schema `dispatch-record-v1`. It promises no free-text field, and `ValidateDispatchRecord` enforces that: every string is a fixed token, an identifier or a closed-vocabulary value. An absolute operator path is free text (it carries the account name), so the record may hold the digest but never the path. Its readers tolerate an additive key (`LatestUsageDispatch`: "Unknown fields are tolerated"), so a new nullable field stays under `dispatch-record-v1`. deskdispatch reads no `CELL_*` value today. cellctl already composes one key for it, `ASSAY_REPAIR_ADMISSION` (`deskkit.EnvRepairAdmission`).
- **Codex inline instructions are unverified.** The capability survey records no Codex flag or `-c` key that adds developer instructions inline, and none is assumed here: no key name in this brief is a fact about Codex. That has to be checked against the installed Codex at pickup (Task 2); it is not assumed here.
- **Risk answers and `deskkit`.** The new `deskkit` files hold one env-key name, a value parser that reuses the existing `DispatchKits()` (no new kit list), and the custody check moved unchanged from cellctl. deskdispatch also reads the existing `ASSAY_CELL_DIR`. They handle no credential, token or customer data and make no external write, so the four risk answers stay `no`. The control this brief adds is fail-closed (a refusal when the rules cannot be delivered), and no existing refusal is loosened except the Codex one, which is narrowed to keys that now have a binding.
- **Role names.** Declaration role keys are cellctl's role names. desk-tools/53 plans a rename of one of them and keeps role-keyed cell state readable; the two briefs share no ordering edge. <!-- graph: no edge desk-tools/53 — a role-name rename is read through the same keys either way -->

layering: No new component. The declaration's owner (`cellctl` role context) gains one key and one harness binding. deskdispatch gains one reader. What both sides share (the env-key name, the value grammar and the file-identity custody check) lives in `deskkit` beside the existing `DispatchKits()`, so neither binary restates it (Task 1, Verify 6 and 9).

design-fit:
  owner: cellctl role context (`tools/desk/cmd/cellctl/rolecontext.go`) owns the declaration; deskdispatch owns prompt assembly
  contract: none — the declaration schema is documented in docs/cellctl-role-context.md and has no semantic-owner row; the new key is additive under `version: 1`
  retires: [the blanket "non-Claude harness with a non-empty entry" refusal, narrowed to keys that have no Codex binding]
  weight: verbs +0, flags +0, refusals +5 (deskdispatch - file unreadable, digest mismatch, malformed value (an `ASSAY_CELL_DIR` that is unset, relative or names no existing directory included), file in a session-writable place by the shared file-identity check; cellctl - unknown kit name or a path the value cannot carry; the custody check itself moves, it is not added), record fields +1 (a nullable digest, no free text), rule-text lines +0 (the kits are unchanged; the quoted text is operator-owned and not shipped)
  why-add: The dispatch-time refusals cannot live in cellctl, which has finished by the time a window dispatches; deskdispatch is the only reader at that moment. Two removals were considered. Having cellctl write the text into each dispatched home was rejected, because homes are created after launch and a worktree is session-writable. Leaving the window to paste its own instructions into a dispatch was rejected, because the text would no longer be quoted verbatim or carry a digest. The record field is the only durable trace of which rules a dispatched agent ran under; the prompt is not stored. It holds a digest, never a path, so the record keeps its no-free-text promise. Recording nothing was considered and rejected, because the digest is what ties an agent's behaviour back to an exact file revision.
