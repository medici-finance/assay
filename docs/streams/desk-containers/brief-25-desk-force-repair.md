# Brief 25 — `cellctl desk --force`: repair a failed desk boot

## Context
files:
- `tools/desk/cmd/cellctl/cobra.go` — declare `--force` and `-y`/`--yes` on `desk` only (beside `--end-stale-lock-holder`), never on `up`
- `tools/desk/cmd/cellctl/desk.go` — route each known refusal through the repair table below when `--force` is set; refuse a per-run non-house `--kind` on a persisted house cell (see Liveness), with or without `--force`
- `tools/desk/cmd/cellctl/up.go` — `cmdUp` refuses a per-run non-house `--kind` on a persisted house cell before its reconcile preflight and before any `--set` persist, with or without `--set` (see Liveness)
- `tools/desk/cmd/cellctl/set.go` — a `CELL_KIND` change through `applyEnvKVs` (so `set`, `desk --set` and `up --set` alike) refuses unless the cell is stopped (see Liveness)
- `tools/desk/cmd/cellctl/git.go` — under `--force` only, `mergeRoleWorktree` hands its refusal back to the repair table instead of dying; without `--force` its message and exit code are unchanged
- `tools/desk/cmd/cellctl/repair.go` (planned) (new: the repair table, the per-row prompt, the repair log)
- `tools/desk/cmd/cellctl/repair_test.go` (planned) (new)
- `docs/cellctl.md` — the `desk` verb's `--force` / `-y` section
- `changelog/desk-containers-25-desk-force.md` (planned)

facts:
- **How a boot fails today.** Most refusals reachable from `cellctl desk` go through `die()`, which prints `cellctl: <msg>` and exits 3 (`main.go`). Two do not: the storage-admission refusal in `deskLaunch` exits 6 (`launch.go`, `exitWith(6)`), and the session-lock refusal exits 4 (`lock.go`, `exitWith(4)`). `--force` turns these refusals into a table of `{detect, classify, repair}` rows. A failure with no row stays exactly as it is today: same message, same exit code. Nothing in cellctl exits 5 today; this brief gives 5 one meaning (below).
- **What `--force` does not own.** Three repairs already have an owner, and `--force` neither duplicates nor overrides them:
  - **The reconcile preflight** (`reconcile.go`, landed in #2884 for issue #2880) runs before the lease on every `cellctl desk` in a house-kind cell. It proves an unfinished cadence checkpoint or orphan dead by pid and start time, and clears it on one `[y/N]` confirmation. It records a decision: "There is deliberately no --yes flag: clearing stays a human act." `--force` leaves the preflight exactly as it is: it runs first, unchanged, and `-y` never answers its question. Off a TTY it refuses as it does today, so `--force -y` off a TTY does not clear cadence state. That stays a human act.
  - **`cellctl reset`** owns an interrupted reset. Its executor stops every process in the cell scope, runs `worktree remove --force --force` and `RemoveAll` on the cell worktree directory, and in hard mode runs `clean -ffdx` and `branch -D`. Its marker records no mode. A re-run therefore cannot be made preserving from here, so the `.reset-in-progress` refusal is a `never` row.
  - **`deskwt`** owns git worktree pruning (common clauses: "Git worktree pruning remains with `deskwt`"). A registration whose directory is gone is a `never` row that names `deskwt prune`.
- **Three classes, decided per row in code, never by the operator:**
  - **safe** — runs without asking, on every cell kind:
    - re-fetch after a transient fetch failure, with bounded retries;
    - `cellctl cache <cell> clean` when storage admission refused (the exit-6 site). This cleans only the cell's own managed cache.
  - **destructive** — named and confirmed first, and only on a persisted house cell run with no per-run `--kind` (see Liveness):
    - ending a proven-stale role-lease holder;
    - rescuing a role worktree that will not merge main into an off-branch rescue ref under `refs/heads/rescue/`, moving it aside, and cutting a fresh one (one row, one prompt; below).
  - **never** — reported with the manual fix, no repair offered:
    - config and usage errors, model-policy refusals, comms config, shim generation, harness-specific failures;
    - a role lease or session lock held by a LIVE session (the exit-4 site, and a scrubbed cell's `has-session` refusal);
    - every destructive row on a cell whose persisted kind is k8s, scrubbed or container, and on any run that carries a per-run `--kind`, whatever its value;
    - an interrupted reset (`.reset-in-progress`): names `cellctl reset <cell>`;
    - a dangling worktree registration: names `deskwt prune`;
    - an unremovable `FETCH_HEAD`;
    - an unavailable explicit cockpit (`desk.go` refuses rather than replaces it, by recorded design): names `--cockpit tmux`;
    - anything the reconcile preflight refused;
    - a role worktree that is, or resolves through, a symlink (see Containment);
    - anything the table does not name.
- **Liveness comes before any destructive row.** A destructive row may run only once this invocation itself holds the proof that no live session owns the role. Today only a house run has that proof before the worktree step: `cmdDesk` takes the role lease (`cellcadence.AcquireRole`) before `deskLaunch`, and only when the run's kind is house. On a scrubbed run, the session lock (`takeSessionLock`, exit 4) and the `tmux has-session` check run in `scrubbedDeskLaunch`, after `deskLaunch` has already merged main into the role worktree. On a k8s run, nothing establishes liveness before that merge. A repair hooked to the merge failure could therefore commit or move a running desk's tree before the live-session refusal ever runs. The `live session` worktree lock that every boot takes records no pid, so this brief never reads it as a liveness signal in either direction. The lease is the proof.
  - **The gate keys on the persisted kind, never the run's kind.** The run's kind is not a property of the cell: `--kind` on `desk` (and `up`) replaces `c.Kind` for one run (`loadCellWithKind`), every kind shares the role worktree path `<cell>/worktrees/<role>`, and a scrubbed or k8s cell carries `CELL_ROOTS` whenever it was made with roots, so it loads as house under `--kind house`. A destructive row therefore runs only when the `CELL_KIND` line in cell.env itself reads `house` AND the run carries no per-run `--kind` (`c.KindOverride == ""`). The gate parses cell.env alone, with the same parser `loadCell` uses, into an environment that holds nothing from the process; it never reads `c.Env`, which falls through to the process environment when a hand-edited cell.env lacks the line. A missing or empty line means not house. This is the persisted-kind test `commsPreflight` applies to comms, made strict and read from the file: any `--kind`, even `--kind house`, makes every destructive row `never`. Every other run keeps today's merge refusal, and only the safe rows run.
  - **Closing the reverse path.** A live session in the shared role worktree that never took the lease would let a later `--force` run find the lease free. Three paths lead there, and this brief closes each where main can see it:
    - **A per-run non-house kind on a persisted house cell** (`--kind k8s`, `--kind scrubbed`, `--kind container`). `cmdDesk` refuses it as its first step, with or without `--force` and with or without `--set`. It dies with exit 3 and `cellctl: desk: a house cell runs as house; change the persisted kind with cellctl set <cell> --kind <k> on a stopped cell`. The refusal sits after `loadCellWithKind`, so a `--kind` whose own precondition fails at load (`--kind container` with no `CELL_CONTAINER_LAUNCHER`) still refuses with today's load message. It replaces today's `desk <house cell> --kind <k> --set`, which persists `CELL_KIND=<k>` (`desk.go` L203-L205): that persist path is refused on a house cell, and the line points to `cellctl set`, whose kind change has the stopped-cell check below.
    - **The same through `up`.** `up` does not launch k8s or house windows through its own `cmdDesk`: each window runs a child `cellctl desk ... --kind <k>`, and `up --kind <k> --set` persists `CELL_KIND=<k>` before any window starts, so the child would load a cell that is no longer house. `cmdUp` therefore makes the same refusal itself, with `up` in place of `desk`, as its first step: before its reconcile preflight, before any `--set` persist (`up.go` L413-L415) and before any window opens, so cell.env is byte-identical after the refusal. `up <house cell> --kind <k> --set` is refused the same way as on `desk`.
    - **A change of the persisted kind while a session is live.** `cellctl set <cell> --kind house` (or `CELL_KIND=house`), `desk --kind <k> --set` and `up --kind <k> --set` all write through `applyEnvKVs`. A `CELL_KIND` change there (a new value that differs from the file's current line) refuses with exit 3, nothing written, unless the cell is stopped by every liveness read main has: `statusLine()` reads `stopped` (no scrubbed session lock), `tmux has-session -t <session>` finds no cell session, and no role lease has a live holder other than this process (`deskkit.Diagnose`; a `desk --set` run that already holds its own lease is not refused by it). The message names `cellctl down <cell>`.
    - **Declared residuals.** Main records nothing for a session that holds no role lease, no scrubbed session lock and no window in the cell's tmux session: today a k8s-kind `cellctl desk` run directly in a terminal or under the herdr or orca cockpit, and a container-kind session. A kind change cannot see such a session. Sessions launched before the implementation ships are the second residual. `docs/cellctl.md` gives the operator rule for both: stop every desk of the cell (`cellctl down <cell>`, and close any desk started directly in a terminal) before changing `CELL_KIND`, and before the first `--force` run after a change or after upgrading.
  - **Trust model.** The persisted-kind gate guards against operator error, not a hostile session. A session running as the operator's user can already rewrite cell.env or run git in its own tree, so this gate grants such a session no new authority; the same holds for the comms preflight it mirrors.
- **Destructive here means "changes state the operator may want", never "loses it".** Each destructive repair preserves what it displaces, and the prompt names where it goes.
  - **The non-merging role worktree** is one row with one prompt, naming the rescue ref by its full refname and the aside path. When `mergeRoleWorktree` refuses, it has already aborted any merge it started, so the tree is as the session left it. The row never commits on, resets, or moves the role branch. It:
    1. Checks the rescue ref's name first: if `git show-ref --verify --quiet refs/heads/rescue/<role>-<UTC stamp>` finds it, or the aside path `<wt>.aside-<UTC stamp>` already exists, the row is refused before anything is written, objects included. The ref is always spelled with its full refname. A bare `rescue/...` passed to `update-ref` lands at `<git-dir>/rescue/...`, outside `refs/`: `rev-parse` still resolves it, but `for-each-ref` does not list it and `gc --prune=now` drops the commit it alone keeps (git 2.56).
    2. Builds the rescue commit off-branch. It seeds a temporary index from HEAD (`GIT_INDEX_FILE=<tmp> git read-tree HEAD`), stages the whole tree into that index, untracked files included (`git add -A` under the same `GIT_INDEX_FILE`), writes it (`write-tree`), commits it with the cell's commit identity (`commit-tree <tree> -p HEAD`), and points the new `refs/heads/rescue/<role>-<UTC stamp>` at it, create-only (`update-ref refs/heads/rescue/<role>-<UTC stamp> <commit> ""`), so a ref that appears between the check and the write is still never overwritten. The real index, the working tree and the role branch are untouched. A clean tree gets the rescue ref at HEAD.
    3. Runs `git worktree unlock <wt>`, then `git worktree move <wt> <wt>.aside-<UTC stamp>`, then `git worktree lock --reason "cellctl <cell>/<role> rescue aside"` on the moved tree. The aside tree keeps its files, index and branch exactly as they were. If `move` fails, the row re-locks `<wt>` with the boot's own `live session` reason, stops the boot with the move error, and names the rescue ref it already wrote by its full refname, so the role tree is never left unlocked.
    4. Cuts a fresh worktree at `<wt>` from the fetched main on a new `<cell>-cell/<role>-<stamp>` branch, with a plain `worktree add` and no `-f`.

    `move` keeps the aside tree a valid, registered, locked worktree, so nothing needs pruning and no registration dangles. A plain rename would leave a missing-but-locked registration that only `add -f -f`, `prune` or `remove` could clear. Because the rescue commit is never on the role branch, the session's untracked files (a stray `.env` or token file included) never reach a branch the desk keeps working on or later pushes. They exist only in the local `refs/heads/rescue/*` ref and the aside tree, both of which are never pushed.
  - **A lease holder** gets SIGTERM only, and only when `deskkit.Diagnose` proves it stale: it holds the lock but its recorded role child has exited, and it is the same cell, the same role, a `cellctl` command, and not the current pid. This is exactly the `--end-stale-lock-holder` path from `tools/desk/internal/deskkit/lockholder.go`; `--force` calls it and never re-implements it. Never SIGKILL.
- **Displaced state is kept until a human removes it.** `--force` never deletes an aside tree or a rescue ref, and no verb does it automatically. Rescue refs live under `refs/heads/rescue/`, so `for-each-ref` lists them and `git gc` keeps their commits. Brief 24's `cellctl gc` keeps any worktree with uncommitted changes or an unmerged, unpushed branch, so it leaves both alone. `cellctl reset`, a human act, does sweep them: its `RemoveAll` of the cell worktree directory takes the aside trees, and `--hard` runs `branch -D` on every `refs/heads/*` branch but main, rescue refs included (reset.go L358-L379 at main). `docs/cellctl.md` names the manual step: review, then remove the aside tree through `deskwt` and delete the ref by hand. It also states that rescue refs and the aside tree's branch are local recovery state that is never pushed: they can hold untracked files, so any of their content bound for a remote needs a secret check first. Adopting them into `gc` would be a follow-up to brief 24, not part of this brief.
- **A live session is out of scope.** A role lease or session lock held by a live, current holder means a desk is already running. `--force` does not end it, even with `-y`. It prints the holder and `cellctl down <cell>` as the manual step. Ending a running desk kills its in-flight agents and loses their unsaved work, and that loss cannot be undone. Whether `--force` should ever do that is a separate decision for the driver, not this brief.
- **Prompts.** One prompt per destructive repair, naming the failure, the action, and where the displaced state goes, e.g. `role lease held by pid 4121 (stale: cellctl desk, its role child 4130 has exited). End it with SIGTERM? [y/N]`. Default is No. Anything but `y`/`yes` declines, the repair is skipped, and the boot stops with today's message and exit code. Read the answer with the existing `readYes` and gate it on the existing fail-closed `isTTY`; do not add a second prompt reader or TTY check.
  - `-y` / `--yes` answers yes to every prompt in THIS table and prints each action it took. It never changes a `never` row, and it never answers the reconcile preflight.
  - **No TTY and no `-y`:** refuse before any destructive step, with exit 5 and the fixed line `cellctl: desk --force: a destructive repair needs a TTY or -y`. The fixed line is part of the contract. `cellctl desk` passes the harness's own exit status through (`runForeground`), so a harness that exits 5 cannot be told apart from this refusal by the code alone. `docs/cellctl.md` says so and tells scripts to match the line.
  - `-y` without `--force` is a usage error (exit 1).
- **Loop bound.** After a repair the boot step that failed is retried. Each row may fire at most once per invocation, and the whole run makes at most 5 repairs. A failure that repeats after its repair stops the boot, with the repair log printed. `--force` must never spin.
- **Repair log.** Every action, safe or destructive, gets one line on stderr and is appended to `<cell>/run/repair.log`. A line holds exactly these fields: UTC stamp, role, row id, action, displaced-state location. It never captures git or credential-helper output, because fetch-failure output can carry a token. `DRY_RUN=1` prints the plan, prompts nothing, and changes nothing.
- **Containment.** Every path a repair moves, renames or removes must resolve inside the cell's own worktree root. Check this with `resetDirectoryInside` (`reset.go`), the helper reset uses; this brief adds no second, weaker check. An error from the helper, or a path outside the root, is a `never` row: containment fails closed. The helper's symlink handling has an open defect (#2851). Until #2851 is closed, a role worktree path that is a symlink or resolves through one is `never`. Note that a deskwt-created role worktree is linked into the cell as a symlink (`launch.go`), so this case is common.
  - **Writes to the shared git dir.** The repository's common git dir is shared, as on every boot. A repair writes to it only additively:
    - the rescue commit's objects (blobs, tree and commit);
    - the new `refs/heads/rescue/<role>-<UTC stamp>` ref, always written by its full refname and create-only (`update-ref refs/heads/rescue/<role>-<UTC stamp> <commit> ""`): an existing ref is never overwritten, and a name collision is a `never` row refused before any write;
    - the fresh role branch, which is new by name;
    - the registration update that `git worktree move/lock/unlock/add` makes for this cell's own role worktree.

    Nothing else is written there: no existing ref moves (the role branch included), and nothing in it is deleted or pruned. The temporary index lives outside the git dir and is removed after `write-tree`.
- **No name clash.** `cellctl reset [--hard]` stays the cell-wide verb, and `--force` never calls reset's executor. `--force` exists today only on `cellctl set`, where it means something else; it is added to `desk` only.
- **Boundary with `cellctl doctor`** (brief 21, on main). doctor diagnoses every stuck state. Its fixes apply only through `doctor --apply <plan-id>`, on a TTY, with a confirm code. `--force` is the boot-path subset: it covers only the rows above, and only for this role. Two faults overlap, a proven-stale lease holder and storage over budget. For both, doctor names the same underlying action this brief uses: the existing stale-holder end and `cache clean`. Where both verbs cover a fault, the owner verb's action does the work and neither re-implements it. `--force` (with or without `-y`) never calls `doctor --plan` or `doctor --apply`, because doctor's apply path is interactive-only by design.
