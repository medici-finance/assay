## Context

files:

  the closed-brief scoping inside `unfailableRowNotices`.
- `statusgen/verifyrows_test.go` — one new `TestRuleFixturesGoRed` table entry and the new
  tests named in Verify.
- NEW `statusgen/testdata/verifyrows/gotest-run-vacuous/` (planned) — `README.md`,

- `statusgen/testdata/verifyrows/literal-pipe/docs/streams/literal-pipe/brief-02-green.md`
  — rows 1 and 2 gain the `--- PASS` assertion (Task 5).
- `statusgen/enforcementstatus.go` — one `lintRuleRegistry` entry, `StatusAdvisory`.
- `plugins/assay/skills/author-brief/SKILL.md` — the generated enforcement block only,
  rewritten by the sync command, never by hand.
- `docs/brief-rules.md` — rule 27.
- `changelog/<branch-slug>.md` — the per-PR fragment this repo enforces.

facts:
- **The Go fact (checked 2026-09-23):** `go test -run 'TestNoSuchName' -v ./...` prints
  `testing: warning: no tests to run` and `ok … [no tests to run]`, then exits 0. On this
  repo's `qualgen` module the row `cd qualgen && go test -count=1 -run 'TestRefix_RegressionOfLink_Counted' -v ./...`
  exits 0 today although no such test exists.
- **The shape that holds:** anchor the selector, send the output to a file, and chain a
  positive assertion on that test's line:
  `go test -count=1 -run '^TestName$' -v ./pkg/... > "${TMPDIR:-/tmp}/x.out" 2>&1 && grep -F -e '--- PASS: TestName' "${TMPDIR:-/tmp}/x.out"`.
  `-v` is what makes `go test` print `--- PASS:` lines. A missing test prints none, so the
  grep exits 1 and the row fails.
- **Where the rule plugs in:** `rowFindings(cmdCell, expect)` in `statusgen/verifyrows.go`
  is the single implementation every row rule runs through; `unfailableRowNotices` formats
  its output as `<path>: Verify row <N> [<tag>] <msg>` NOTICEs. `goTestRunPatterns(toks)`
  already extracts every `-run` / `-bench` / `-fuzz` argument in the `-run X`, `-run=X` and
  `--run=X` forms; `grepCalls(toks)` already returns each grep's patterns and its `-F` /
  `-E` / `-c` flags. Reuse both. Do not write a second tokenizer.
- **The fixture convention:** each rule owns a root under `statusgen/testdata/verifyrows/<shape>/`
  with a `brief-01-red.md` (every row carries the defect) and a `brief-02-green.md` (the
  same checks written correctly). `TestRuleFixturesGoRed` asserts the rule fires on EXACTLY
  the red row count and that the green brief is silent under EVERY rule.
- **Existing fixtures the new rule would hit:** the literal-pipe green fixture (`statusgen/testdata/verifyrows/literal-pipe/docs/streams/literal-pipe/brief-02-green.md`) rows 1–2
  (`go test ./statusgen/ -run Forged`, and the `Dora` / `Weekly` chain) carry a `-run` with no
  `--- PASS` assertion, so they would break that fixture's silence. The red literal-pipe rows
  may fire the new tag as well, which is harmless: the test counts only the fixture's own tag
  on red.
- **How much of the tree carries the shape (measured 2026-09-23 on main @ 2a5c230ef, by
  grep over the `## Verify` section of every `docs/streams/*/brief-*.md`, so approximate):**
  684 rows run `go test` with `-run` and contain no `--- PASS`. 451 of them are in 108 OPEN
  briefs (`todo` 213, `in-progress` 24, `implemented` 208, `blocked` 6). 233 are in 62 `done`
  briefs. An `implemented` brief is exactly the one whose rows a verifier is about to run.
- **Out of scope, recorded:** (1) `-bench` / `-fuzz` selectors, whose output does not use
  `--- PASS:` lines; (2) `go test -run` steps in `.github/workflows/*.yml` (five today:
  `forge-surface-control.yml`, `leaksweep-control.yml`, `pin-consistency.yml`, and two in
  `release.yml`), since the lint reads briefs, not workflows; (3) rewriting the 451 open-brief
  rows (the backfill) and promoting the rule to a PROBLEM, which happen after this brief, in
  that order.
- **Layers for the class:** this rule (authoring time, statusgen, reads the command TEXT);
  quality/17's regression gate (CI run time, a different tool, reads `go test -json` events);
  and review. Each fails for a different reason, so none is a copy of another.

## Task
1. Add the tag `ruleGoTestRunVacuous = "gotest-run-vacuous"` (planned) beside the other rule tags,
   and add it to `TestRuleTagsAreUnique`'s list.
2. In `rowFindings`, for every `-run` selector `goTestRunPatterns` returns (`-bench` / `-fuzz`
   are skipped), decide whether the SAME command asserts it:
   - an **assertion** is a grep call whose pattern contains `--- PASS`, and which is neither
     negated (`! grep …`) nor neutralised (`… || true`);
   - a **named selector** is one that, after stripping one leading `^` and one trailing `$`,
     is a plain Go test name (`Test` followed by letters, digits and `_`). A named selector
     needs an assertion whose pattern contains `--- PASS: <that name>`. Any other selector (a
     group token such as `Cadence`) needs at least one assertion;
   - each selector needs its own assertion: two named selectors and one grep is a finding
     for the selector left unasserted;
   - one finding per unasserted selector, whose message quotes the selector and gives the
     rewrite from the facts above. Put the named-selector anchoring advice in the message too:
     an unanchored `-run TestFoo` also runs any test whose name merely starts with TestFoo.
   The rule does not reimplement `rE2-literal-pipe`; a `\|` selector gets both findings.
3. In `unfailableRowNotices`, look up each brief's Status in its stream README (`Stream.Briefs`,
   keyed by the number `expectedBriefID` derives from the path). For a brief whose status is
   `done` or `verified`, do not emit per-row `gotest-run-vacuous` notices. Instead emit ONE
   NOTICE per run:
   `[gotest-run-vacuous] <R> Verify row(s) in <B> closed brief(s) carry an unasserted go test -run selector — closed records are not rewritten; the per-row notice covers open briefs only`.
   A brief with no README row counts as open. Every other rule is unchanged: keep this
   scoping to this tag.
4. Fixture root `gotest-run-vacuous/`: `brief-01-red.md` with exactly 6 red rows (a bare
   `-run TestX`; the `-run=TestX` form; an anchored `^TestX$` whose grep names a different
   test; a `! grep` assertion; a `|| true`-neutralised assertion; two named selectors chained
   with only one assertion), `brief-02-green.md` with the facts' shape, a group selector with
   a generic `--- PASS` grep (the statusgen/13 row 4 form), and a row with no `-run` at all.
   Add a `done` brief carrying two red rows, to prove the exemption and the summary count.
5. Add the `--- PASS` assertion to the literal-pipe green fixture (`statusgen/testdata/verifyrows/literal-pipe/docs/streams/literal-pipe/brief-02-green.md`) rows 1–2, keeping each
   selector a single token so that fixture still tests what it tested before.
6. Registry: one `lintRuleRegistry` entry, `StatusAdvisory`. Regenerate the author-brief
   enforcement block with `statusgen enforcement-status` piped through
   `go run ./tools/skillslint --sync`, as the block's header says.
7. `docs/brief-rules.md` rule 27: add the assertion half. Rule 27 already names `\|` and
   the `no tests to run` exit 0; add the anchored-selector + `--- PASS:` shape and the tag.
8. Fail-first: run Verify row 2 with the Task 2 check stubbed to return no findings and
   paste the red output (the fixture subtest failing on `fired on 0 rows, want 6`) into the
   PR body under `## Fail-first`.
