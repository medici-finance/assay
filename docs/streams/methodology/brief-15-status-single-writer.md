# Brief 15 — STATUS.md single-writer

## Context
files: tools/statusgen/main.go (+test); .github/workflows/statusgen.yml; new .github/workflows/status-regen.yml; CLAUDE.md (one convention line); docs/streams/methodology/README.md conventions
facts:
- Problem: STATUS.md is regenerated by every branch → it is the ONLY file that conflicts on merges (observed: PR #77), and byte-level `--check` fails whenever any other session regenerated first. Generated files must have exactly one writer.
- Design: (a) statusgen gains `--lint` — run ALL checks (streams, brief-v1, findings, links) with NO drift comparison and NO write; exit 1 on problems. (b) PR-side workflow: `go test`, `go vet`, `statusgen --lint`, PLUS a guard failing the PR if its diff touches STATUS.md (`git diff --name-only origin/main...HEAD | grep -qx STATUS.md && exit 1`). (c) New main-side workflow on push: run statusgen; if STATUS.md changed, commit it as a bot commit (message `chore(status): regenerate [skip-status-regen]`) — loop-guard by skipping when the head commit is the bot's own, and path-filter the workflow to NOT trigger on STATUS.md-only pushes.
- Convention (CLAUDE.md, one line — mind brief-14's diet): regenerate STATUS.md locally whenever you like for reading Next-up, but NEVER commit it on a branch; main's CI owns the committed copy.
- INTERIM recipe until this lands (also useful forever for local merges): on a STATUS.md conflict, take either side and `go run ./tools/statusgen` — never hand-merge a generated file.
- Workflow permissions: the regen workflow needs `contents: write`; keep it scoped to that single workflow.

Review verdict (model:opus, 2026-07-09): **PASS — closed to `done`.** Confirmed gate:model
with all-no risk in frontmatter (closeable by a model). Read both workflows and the statusgen
lint/check modes, and probed the two hazards the Review section names:
(1) **Loop guard** — `status-regen.yml` has BELT-AND-SUSPENDERS: `paths:` excludes `STATUS.md`
so the bot's STATUS.md-only regen commit cannot retrigger the workflow, AND the job carries
`if: !contains(head_commit.message, '[skip-status-regen]')`. Either alone would hold; both is
correct. `permissions.contents: write` is scoped to this single workflow.
(2) **Rename bypass** — the PR guard is `git diff --name-only --no-renames origin/main...HEAD |
grep -qx STATUS.md`. `--no-renames` is the right choice: a rename of STATUS.md surfaces as a
DELETE of the `STATUS.md` path (plus an add of the new name), so `grep -qx STATUS.md` still
fires — the guard cannot be dodged by renaming. The PR path correctly drops the byte `--check`
in favor of `--lint` (all source checks, no drift compare), so concurrent branch regens no
longer turn into CI failures — the exact problem the brief was filed to kill. `go test`+`go vet`
present on the PR side; regen is race-safe (reset + up-to-5-attempt retry, commit only on diff).
No defect.
