# Brief 05 — Offline two-pattern experiment on frozen fixtures

## Context
files: `statusgen/testdata/graph-execution/` (planned) (eight frozen fixture trees, one per case, each with a `case.yaml` naming pattern, declaration edit, and expected verdicts), `statusgen/experiment.go` (planned) (the `statusgen experiment` subcommand), `statusgen/experiment_test.go` (planned), `statusgen/experiment_baseline.go` (planned) (the scripted fixed procedure), `docs/streams/graph-execution/experiment-01-report.md` (planned), `docs/dependency-graph-design.md` (a short "executed, not rendered" note pointing at the report), `changelog/graph-execution-05-offline-experiment.md` (planned)
facts:
  - Harness form: a `statusgen experiment --root <fixture> [--json]` subcommand, NOT a bare Go test — so a reviewer and the later real-work trial run the same binary the fixtures were frozen against, and the report's table is regenerated by a command anyone can run (Verify row 5). The Go test wraps the subcommand over every fixture.
  - Inputs the harness reads, by name (2026-09-16 contracts from the sibling briefs): `statusgen --eligibility --json` (per brief `{id, verdict, holds:[{ref,type,reason,state}], notices:[...]}`; verdicts `eligible | held | eligible-with-notice`); `statusgen --coverage --json` (per claim `{claim, kind, result, revision, released, reason}`; results `pass | fail | missing | error | could-not-check | wrong-revision`); the drainloop `Effect` layer (`Key`, `Receipt`, `Apply`; journal kinds `EFFECT-INTENT`, `EFFECT-DONE`, `RECONCILE`).
  - The eight cases (spec §4), one fixture each, both patterns where applicable: (1) fan-out/join; (2) unmet hard prerequisite (`gates:` unsatisfied ⇒ `held`); (3) unavailable informational feather (`feathers:` could-not-check ⇒ `eligible-with-notice`, never `held`); (4) missing or wrong-revision evidence (`coverage` ⇒ not released); (5) denied effect (a node whose effect exceeds its role ⇒ refused by the 02 lint, never applied); (6) duplicate delivery (one `Apply`); (7) reviewed revision to pending work (a v2 pattern instance supersedes v1 mid-run; prior evidence retained); (8) lost-acknowledgment recovery (effect applied, `EFFECT-DONE` lost, resume ⇒ `RECONCILE`, one record).
  - Baseline: `experiment_baseline.go` (planned) scripts today's fixed procedure — `depends:`-only readiness from `statusgen --next-up`, no coverage rule, drainloop without the Effect layer — over the SAME fixtures, so each case has a baseline column. The baseline is expected to pass cases 1 and 6 and to fail or be silent on 2, 3, 4, 5, 7, 8; the report records what it actually did.
  - Three pass criteria, each a harness assertion, not prose: (a) ROUTING-DIFF — for cases 2 and 5 the fixture carries a one-line declaration edit (`case.yaml: edit:`); the harness applies it, re-runs, asserts the verdict changed, and asserts `git diff --stat -- statusgen/nextup.go statusgen/eligibility.go tools/desk/` is empty; (b) AUTHORITY — for every instance, the set of applied effect kinds ⊆ the pattern's declared `effects:`; (c) EVIDENCE — every evidence ref present in a fixture before the run is present in the run record after; case 8 additionally asserts one store record.
  - Public tree: every fixture names `example-org/*` repos and the roles from `topology.yaml` (`desk`, `reviewer`, `verifier`, `worker`); no adopter repo, number or measurement appears anywhere in the fixtures or the report.
  - Single-point-of-failure note: the ONE control is the harness's own assertions. Second, independent layer: Verify row 5 regenerates the report's table from the binary and diffs it against the committed report, so a hand-edited "pass" cannot survive; third: the sibling briefs' own tests (01–04) run unchanged in CI, so a harness that stubs one of them out still leaves that brief's contract proven elsewhere.

## Ground rules
- NEVER git push / trigger workflows / run mutating kubectl. Leave commits per the task instructions only.
- Offline only: the harness reads no network and no forge. A fixture that needs a token is a fixture defect.
- Do not edit the sibling briefs' code to make a case pass; a case that cannot pass is recorded as `fail` in the report with the reason, and the report is still the deliverable.
- Stop at `implemented` — you do not set verified/done.
- If anything is unclear or contradicts repo state: report NEEDS_CONTEXT, don't guess.

## Task
1. **Fixtures.** Create `statusgen/testdata/graph-execution/<NN>-<case>/` (planned) for the eight cases, each a minimal streams tree (README + briefs with brief-v2 frontmatter, the pattern instance, Evidence rows or witness files where the case needs them) plus `case.yaml`: `pattern:`, `edit:` (the one-line declaration change, cases 2 and 5), `expect:` (eligibility verdict, coverage released yes/no, effect count, journal kinds).
2. **Harness.** `statusgen experiment --root <fixture-dir> [--json]` (planned): runs the graph path (eligibility → pattern instantiation → coverage → drainloop with the Effect layer over an in-memory authoritative store) and the baseline path over the same fixture, evaluates the three criteria, and prints one row per case: `case | pattern | baseline outcome | graph outcome | criteria a/b/c | evidence refs`. Exit 0 only when every `expect:` matches; any could-not-check in an input is reported as such and fails the run (it is never rounded to pass).
3. **Go test.** `TestExperimentAllCases` (planned) iterates the eight fixtures; `TestExperimentRoutingDiffIsEmpty` (planned) pins criterion (a); `TestExperimentAuthorityNeverGrows` (planned) pins (b) by injecting an extra effect into an instance and expecting the harness to red; `TestExperimentBaselineIsNotGraph` (planned) asserts the baseline path never calls the eligibility or coverage readers (a baseline that secretly uses the new code proves nothing).
4. **Report.** `docs/streams/graph-execution/experiment-01-report.md` (planned): the per-case table exactly as the harness prints it, the statusgen version and fixture SHA it was produced at, what the baseline actually did per case, and the honest limits (offline, fixtures authored by the same stream, two patterns only, no cost or intervention numbers — those belong to a real-work trial). The table is GENERATED (`statusgen experiment --all --markdown` (planned)); the prose around it is authored.
5. **Docs + changelog.** One paragraph in `docs/dependency-graph-design.md` pointing at the report as the first executed (not rendered) run of the reserved edges; `changelog/graph-execution-05-offline-experiment.md` (planned).
