# Make a guard decide the same way as the tool that owns the rule

An author who lands the first brief for an approved plan changes its status to `routed`. On the baseline, reactivating that stream fails lint because the activation check requires the word `approved`. The lifecycle check already recognizes both stages. The practical cost is a choice between a red PR and recording the wrong lifecycle state. In issue #3802, this came up while reopening the cell-api stream. [Original report](https://github.com/medici-finance/assay/issues/3802) · [Lifecycle contract §8](../../../../spec/lifecycle-v1.md#8-spec-and-scoping-doc-lifecycle)

| Milestone | Change | How to see the improvement |
|---|---|---|
| 1. Reopen an already routed stream | The lifecycle-header owner supplies one predicate for whether the plan has crossed approval. Use it in the active-stream source gate and the independently enforced routing-destination check. Synchronize the fatal-rule description and desk instructions with the shipped readers. | Apply the differential lint to a newly active README. An approved or routed source passes. A draft, unreadable source, unknown status or missing pointer still produces a fatal problem. A routed document missing its destination still fails the lifecycle check. A routed document produces no additional authoring-owed issue. |
| 2. Qualify one more disagreement across two callers | Use the existing incident-class intake to choose the next recurrent guard with an identified owner and two real callers. Freeze examples before changing behavior. Include a valid case currently refused, a truly invalid case that must still be refused, and a case with insufficient evidence. The owner records the expected result for each. Invoke the same cases through both callers and compare actual outcome, severity and reason. | Publish the before/after table, both callers’ identities and the fixture inputs. Acceptance requires eliminating the observed disagreement for the allowed case while retaining every required refusal and accurately reporting the unreadable case. Existing work on the body scanner has a separate owner. [Incident-class intake](../../build-less-brittle/brief-04-intake-by-error-class.md) · [Existing scanner work](../../desk-tools/brief-61-benign-shape-registry.md) |
| 3. Verify the result through the adopter workflow | The rule owner and a separate reviewer replay both families on a clean consumer checkout with its pinned release. Then watch the next release interval using the same rule tags and intake register. Group repeat reports about the same incident; keep the total invocations, confirmed false refusals, genuine refusals, unresolved cases and overrides separate. | For each family, record a successful formerly blocked journey and an independently witnessed invalid case. Compare confirmed false refusals per invocation where both periods have a denominator. Report low or missing exposure explicitly and retain the original gate severity. [Rule-register and retirement owner](../../build-less-brittle/brief-07-rule-register-and-diet.md) · [Joined qualification](../brief-11-qualify-the-joined-tool-flow-and-prepare-consumer-by-consumer-retirement.md) |

The first increment is independently runnable from the checkout root with `go -C statusgen test -count=1 -run '^Test(StreamSource|RoutesToRequiredLint|LifecycleOwedNoticeIntegration|AuthoringOwedDerivation|EnforcementStatus)' .`. The contract states that “approved → routed” follows the PR landing the citing briefs. That transition establishes the reason for accepting routed plans at stream activation. Milestone 2 starts once the owners have an observed disagreement and can freeze both verdicts. [Lifecycle transitions](../../../../spec/lifecycle-v1.md#84-flip-rules)
