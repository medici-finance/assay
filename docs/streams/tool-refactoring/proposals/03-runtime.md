# A desk that works from a clean Kubernetes installation

A verifier should be able to open an admitted repository at the mount point its operator chooses and use the repository-relative witness recorded by another desk. On the current main baseline, the same file gets credit when named with an absolute host path and returns `could-not-check` when named from the checkout. Other reports describe the test host supplying a tool or Git setting the run never declared. These failures make a clean installation a materially different operating environment. [Witness path report](https://github.com/medici-finance/assay/issues/6580) · [Ambient test environment reports](https://github.com/medici-finance/assay/issues/6300)

This proposal extends the existing work on executable readiness, cell packaging and independent profile qualification. The existing tool contract identifies the repository, brief, source, author and attestation. The installation chooses where the checkout is mounted. The proposed change adds no profile format or command. From the repository root, the offline regression for milestone 1 is `go -C statusgen test -count=1 -run '^TestBracketCreditPortableWitnessPaths$' .`. The first remaining deployment dependency is a selected, authorized disposable Kubernetes profile. The recovery brief requires the operator to “select the disposable target, explicit credential configuration, expected server identity, authorized identities, image/profile versions, matched workload, capacity limits and recovery objectives.” Use that gate and its independent evidence before counting milestones 2 or 3.
