# Give each tool the same tracking and delivery coordinates

A verifier can execute the correct code and still be handed a command that publishes its outcome to the wrong repository. An operator then has to diagnose and correct a command generated by the dispatcher. A second repository, forge or checkout layout should add no manual routing step.

The implementation belongs to [tool-refactoring/01](../brief-01-bind-operation-subjects-to-explicit-tracking-delivery-and-evidence-repositories.md) and [/02](../brief-02-make-dispatch-planning-and-execution-consume-one-validated-operation-subject.md), with joined acceptance in [/11](../brief-11-qualify-the-joined-tool-flow-and-prepare-consumer-by-consumer-retirement.md). Keep their human start gates, approval-bound subject, fresh effect checks and last-consumer retirement. The shared subject belongs to `statusgen/domain` with `statusgen/workref`. The `deskkit` adapters observe the checkouts and resolve their forges. The first dependency is already visible at the command boundary. The verifier assignment passed the delivery repository to the outcome writer, while the publisher’s `admittedRunComplete` requires `b.Repo == fr.Slug()`. A version-2 attestation sets `Repo` to the tracking repository. The local change passes the verified tracking identity to the command generator and checks it against the admitted run before emitting a real prompt. Those two values differ for a valid split-repo brief. The existing [decision-target repair](https://github.com/medici-finance/assay/pull/6813) supplies a working comparison. Repository identity, the lookup root and the forge selected for the effect must travel together.

The milestone 2 fixture now sends the command emitted by `deskdispatch` to the Evidence writer after a real `statusgen verifyrun`. The decision and claim adapters use local Git refs. The fake forge serves an existing delivery PR and records the writer's two commits. In both layouts one passing row and one failed row produce Evidence and a `verify-fail` outcome on tracking main. The split fixture uses the same brief path and PR number in both repositories and records both original revisions. The writer refuses a missing root or a moved delivery revision before any further write. The publication command also works when the outcome directory contains spaces and an apostrophe.
