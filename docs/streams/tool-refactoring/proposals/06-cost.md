# Reduce the forge cost of one completed desk operation

Operators pay for each request against the desk role's provider quota. One roster invocation already lists the open changes for each configured repository. It then fetches those same changes individually to describe a worker's registered work. A prior operator reported 166–238 calls on a roster pass. That figure includes other reads; the increment below only claims the calls counted by its test. [Issue 3374](https://github.com/medici-finance/assay/issues/3374)

## Pickup and dependencies

The first increment is independent of the activation of a new forge backend. The observable duplication sits in the two existing reads in the roster's normal list entry point. The code uses the existing forge contract and repository-qualified identity. Extending reuse to another command requires its own completeness and authority checks. Any unconfirmed closure remains registered.

The desk-tools maintainer owns the matched fixture and caller migration. The deployment owner supplies the Kubernetes evidence. A regression in classification or pruning withdraws the affected consumer from reuse and keeps the previous per-item read available.
