# Brief 38 — Daily human-gate sign-off digest + age-at-gate metric

## Context
files:
- `../assay-toolkit/statusgen/verifyissues.go` — `verifyIssues` eligibility (mm/12: `gate: human` briefs
  awaiting sign-off, with a recorded model `**VERIFY: PASS**`); the per-brief issue emit
- a NEW digest emitter (extend verifyissues.go or a sibling) + test
- `../assay-toolkit/statusgen/awaitage.go` — `awaitingAges` / `renderAge` (age helpers already exist, mm/17)
- `.github/workflows/` — a scheduled digest workflow (mirror `daily-harvest.yml`'s cron +
  workflow_dispatch shape; the digest is main-CI-generated, single-writer)
- `docs/streams/methodology-metrics/README.md` — one convention line

facts:
- **Relationship to mm/12 (NOT a duplicate):** mm/12 (verified/done) opens/closes the PER-BRIEF
  sign-off surface and the human:<name>-only closer allowlist already guarantees only human:<name>'s close
  advances a brief. This brief adds a BATCH VIEW on top: ONE daily digest (a single issue or a
  checkpoint artifact) listing EVERY brief awaiting human:<name>'s sign-off, oldest-first, each with its
  recorded Evidence link — so he can clear the batch from one place. mm/12's per-brief machinery
  is unchanged; this is a roll-up, not a second closer.
- **Age-at-gate metric:** add a per-stream `oldest-implemented-age` (time since the brief entered
  its awaiting-human-gate state) to STATUS.md, computed from the mm/01 historian via the existing
  `awaitingAges` helper. Today only COUNTS are surfaced at the human gate, not AGES — this makes
  the human gate's queue as visible as the model gates'.
- Eligibility for the digest = exactly mm/12's set: `gate: human` briefs at `implemented|verified`
  with a recorded model `**VERIFY: PASS**` and no `human:<name>` close yet. Reuse
  `verifyIssues()`'s eligibility predicate — do NOT re-derive it (single source of truth).
- The digest is generated by main-CI on a daily cron (mirror daily-harvest.yml); the desk reads
  it, never regenerates. First step named in the intake — measure current per-brief verify-gate
  latency — is satisfied by the age-at-gate metric this brief adds (it makes the latency visible).
- Out of scope: changing the closer allowlist or the per-brief card body (mm/12 owns those);
  auto-closing anything (only human:<name>'s close advances — unchanged).
