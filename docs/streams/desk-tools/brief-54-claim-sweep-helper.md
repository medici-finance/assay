## Task
1. **Write `plugins/assay/scripts/claim-sweep.sh` (planned)** (bash plus POSIX awk; must run under bash 3.2 on macOS and under GNU tools; mode 100755). Interface:
   - `-e PATTERN` / `--pattern PATTERN`, repeatable; every argument after a bare `--` is also a pattern, so a pattern may begin with `-`. At least one pattern is required. Each pattern is a fixed string, not a regex, and is only ever compared as data: never evaluated, never passed to a shell or to `awk -v` unescaped.
   - `--tree DIR`, default the git top level of the current directory. DIR must BE a work tree's top level: when `git -C DIR rev-parse --show-prefix` prints anything (DIR is a subdirectory), the helper exits 2 with a reason naming the top level. The test is that prefix being empty, never a comparison of path strings (on macOS `/var` is a symlink, so one temporary directory has two spellings). A subdirectory is never silently widened or narrowed, because a partial sweep would read as "gone from the tree" and the rerun line sweeps `--tree .` from the root. Scans every tracked file (`git -C DIR ls-files -z`), reading the working-tree contents so an uncommitted fix is seen. It never follows a symlink, so it cannot read outside the tree: an entry that is a symlink, a submodule (gitlink) or anything else that is not a regular file is skipped and counted as non-regular. Binary files (NUL byte in the first 8 KiB) are skipped and counted.
   - `--pr-body FILE`, optional: also scans FILE; hits report as `pr-body:<line>`.
   - `--case-sensitive`; the default is case-insensitive.
   - `--trust-repo DIR`, optional: DIR is an Assay source checkout. Before sweeping, the helper reads the blob `refs/remotes/origin/main:plugins/assay/scripts/claim-sweep.sh` with `git -C DIR cat-file blob` and compares its sha256 with the sha256 of the script file that is running. On a mismatch, or when the ref or the blob cannot be read, it exits 2 (could-not-check) and prints no `rerun:` line, so no verdict can rest on it either way. `--trust-repo` is a defence-in-depth convenience, the second layer: it catches an accidental stale, unpushed or locally edited copy, never a hostile one, because a self-check run by the code being checked is not a control. The control is clause 8's pre-run hash of a private copy, done by the reviewer before that copy is executed; for the printed `helper-sha256:`, anyone holding an Assay checkout with `refs/remotes/origin/main` fetched can recompute it from that blob and compare.
   - Normalisation, applied to the scanned text and to each pattern the same way: per line, strip leading whitespace and then any leading comment or quote markers (`//`, `#`, `>`, `*`, `--`, `;`) and the whitespace after them; join the lines of a file with one space; collapse every run of whitespace to one space. Each match reports `<path>:<line>` of the ORIGINAL line where the match starts, `<path>` relative to the tree root, and which pattern matched. Every path and pattern the helper prints is escaped so it stays on its own output line: a newline is printed as `\n`, a tab as `\t`, a backslash as `\\` and any other control byte as `\xHH`, so a tracked file name can never forge a `trust:`, `helper-sha256:` or `rerun:` line. Known misses, stated in the usage text: a non-breaking space, a zero-width character, or emphasis markers (`*`, `_`, `` ` ``) inside the claim are not normalised, so a claim written with them is not matched. Exit 0 therefore means "no normalised match", never proof that the claim is gone.
   - Output: one `hit: <pattern> <path>:<line>` line per match; then `scanned: <N> files, skipped: <M> binary, <K> non-regular`; `trust: matches refs/remotes/origin/main` when `--trust-repo` passed, else `trust: unchecked`; `tree: <HEAD sha> (<clean or uncommitted changes>)`; `helper-sha256: <hex>`, the sha256 of the script file that actually ran, computed by the script over its own resolved path (`$0`, with `sha256sum`, else `shasum -a 256`); and a final `rerun: <command>` line. The helper never tries to name its copy by git commit or plugin version: the hash is the identity, and anyone holding an Assay checkout with `refs/remotes/origin/main` fetched can recompute it from that blob and compare. The rerun line is PORTABLE and carries no absolute path: it names the helper by its bundle-relative path through a required variable, `bash "${ASSAY_BUNDLE:?set to a bundle root whose scripts/claim-sweep.sh has the helper-sha256 above}/scripts/claim-sweep.sh"`, sweeps `--tree .` (it is run from the tree's root), carries `--trust-repo "${ASSAY_SOURCE:?set to an Assay checkout with refs/remotes/origin/main fetched}"` when the run used `--trust-repo`, quotes every value it prints in POSIX single quotes (each value wrapped in `'...'`, each embedded `'` written as `'\''`; never bash `printf %q`, which on bash 3.2 leaves a leading `~` unescaped), with the patterns printed after a bare `--` so a leading `-` is never read as a flag, and gives `--pr-body` as the body file's path relative to the tree root when it lies inside the tree, otherwise as its bare file name (the `pr-body:` summary line then says the body must be re-fetched to that name). Because every value is single-quoted, evaluating the line in sh, bash or zsh can never run or expand anything spelled inside a pattern (`$(...)`, a backtick, `;`, a leading `~` or `=`), whatever the claim text says. Pasted into bash from the tree root with `ASSAY_BUNDLE` set, it reruns the same sweep; with `ASSAY_BUNDLE` unset it fails loudly instead of running something else.
   - Exit codes: 0 = no pattern found anywhere; 1 = at least one hit; 2 = could-not-check (no pattern given, DIR is not a git work tree or is a subdirectory of one, the PR-body file cannot be read, zero files were scanned, neither `sha256sum` nor `shasum` is available to hash the helper, or `--trust-repo` was given and the hash does not match or the ref or blob cannot be read). Exit 2 prints a reason to stderr and never prints a `rerun:` line that would read as a clean result.
2. **Write `plugins/assay/scripts/claim-sweep.test.sh` (planned)** in the bundle's suite style (temporary git repos under `${TMPDIR:-/tmp}`, `--case <name>` to run one case, final `<N> passed, <M> failed`). It must include at least these 26 cases, by these names, every one of which Verify 1 checks: `wrapped-markdown-line`, `comment-continuation`, `blockquote-continuation`, `tabs-and-runs`, `case-insensitive-default`, `case-sensitive-flag`, `absent-claim-exits-0`, `uncommitted-fix-seen`, `pr-body-hit`, `two-patterns-reported-separately`, `binary-file-skipped-and-counted`, `newline-in-file-name-escaped` (a tracked file whose name contains a newline followed by `rerun: ` and `trust: ` text, and which holds the pattern: the output has exactly one `rerun:` line and one `trust:` line, and the hit line shows the name with `\n`), `symlink-and-non-regular-skipped` (a tracked symlink pointing at a file outside the tree that contains the pattern gives no hit and is counted as non-regular), `no-pattern-exits-2`, `not-a-git-tree-exits-2`, `subdirectory-tree-exits-2` (asserts the refusal by `git rev-parse --show-prefix` being non-empty, never by comparing path strings), `missing-pr-body-exits-2`, `helper-sha256-matches-file` (the printed `helper-sha256:` equals an independent sha256 of the script file, and a copy with one byte changed prints a different value), `rerun-line-reproduces` (evals the printed `rerun:` line from the tree root with `ASSAY_BUNDLE` set and compares its hits and exit code with the first run), `rerun-line-has-no-machine-path` (runs with an absolute `--tree` and an absolute `--pr-body` outside the tree and asserts the `rerun:` line contains neither path and no token beginning with `/`), `rerun-line-hostile-patterns-inert` (patterns containing `'`, `"`, `$(touch SENTINEL)`, a backtick, `;`, a backslash, a leading `-`, a leading `~` (`~root`) and a leading `=` (`=cmd`), each planted in the tree; evaluating the printed `rerun:` line never creates the sentinel file, and the rerun reproduces the same hits and exit code), `trust-match-proceeds` (with `--trust-repo` on a repo whose `refs/remotes/origin/main` holds a byte-identical copy, the sweep runs and prints `trust: matches refs/remotes/origin/main`), `trust-mismatch-exits-2` (the same repo, run from a copy with one extra byte: exit 2, no `rerun:` line), `trust-missing-blob-exits-2` (the ref exists but has no `plugins/assay/scripts/claim-sweep.sh` (planned): exit 2, no `rerun:` line), `trust-missing-ref-exits-2` (no `refs/remotes/origin/main`: exit 2, no `rerun:` line), `offline-no-forge-calls` (runs with a PATH whose `gh`, `curl` and `git-remote-https` stubs fail loudly if called).
3. **Amend review-kit clause 8** (`review-prompt.md`): add one bullet stating that a verdict asserting a claim is gone from the tree (a false claim fixed, a stale phrase removed, a rename completed) names its instrument and makes it reproducible. It runs `claim-sweep.sh` from a trusted copy, never the PR head's (so a PR cannot edit the instrument that judges it), and the clause carries the procedure below literally.
   - Source copy, in this order: (a) `$ASSAY_BUNDLE/scripts/claim-sweep.sh` when the variable is set; (b) the installed Assay plugin's `scripts/claim-sweep.sh` (planned), in the directory holding the plugin's `.claude-plugin/plugin.json`; (c) neither: the default branch's blob itself, `refs/remotes/origin/main:plugins/assay/scripts/claim-sweep.sh`, read from an Assay source checkout. No worktree is needed for (c): the helper is one self-contained file, so the procedure writes that blob straight into the private copy. (d) No Assay source checkout with `refs/remotes/origin/main` fetched: could-not-check, since there is nothing to hash against. `CLAUDE_PLUGIN_ROOT` is not set in dispatched agents and is not a locator. An installed plugin's version number proves nothing.
   - The control is a hash taken by the reviewer BEFORE anything is executed, over a private copy. The reviewer copies the source into a fresh directory under its own home (`$HOME`, not `/tmp`: common clause C2 says a `/tmp` scratch does not isolate a dispatched agent, and C7 names no fixed directory), hashes that private copy, and runs only that private copy. `mktemp -d` creates the directory mode 0700, so the file cannot be swapped between the hash and the run, which is the gap that hashing the original file and then running it would leave. Only when the private copy's hash equals the default branch blob's hash does the copy run. On a mismatch, an unreadable ref or blob, an empty hash on either side, or no hashing tool, the copy is never run, and the claim-gone assertion is could-not-check, with no verdict either way. The directory is removed whatever the helper's exit code (1 is the normal hit result). `SRC` is the (a) or (b) file and is unset for (c); `ASSAY_SOURCE` is the Assay checkout; `TREE` is the root of the tree under review; replace `PATTERN...` with the patterns, each in single quotes:

     ```bash
     rc=2; p=
     if command -v sha256sum >/dev/null 2>&1; then h() { sha256sum | cut -d' ' -f1; }; else h() { shasum -a 256 | cut -d' ' -f1; }; fi
     m=refs/remotes/origin/main:plugins/assay/scripts/claim-sweep.sh
     p=$(mktemp -d "$HOME/.claim-sweep.XXXXXX") && [ -n "$p" ] && mkdir "$p/scripts" &&
       git -C "$ASSAY_SOURCE" cat-file -e "$m" &&
       want=$(git -C "$ASSAY_SOURCE" cat-file blob "$m" | h) &&
       if [ -n "${SRC:-}" ]; then cp -- "$SRC" "$p/scripts/claim-sweep.sh"; else git -C "$ASSAY_SOURCE" cat-file blob "$m" > "$p/scripts/claim-sweep.sh"; fi &&
       have=$(h < "$p/scripts/claim-sweep.sh") &&
       test -n "$want" && test -n "$have" && test "$want" = "$have" &&
       { (cd "$TREE" && ASSAY_BUNDLE="$p" bash "$p/scripts/claim-sweep.sh" --trust-repo "$ASSAY_SOURCE" --tree . -- PATTERN...); rc=$?; }
     [ -n "$p" ] && rm -rf -- "$p"
     echo "claim-sweep exit: $rc"
     ```

   - `--trust-repo` inside the helper repeats the comparison as a second layer that catches an accidental stale copy; it is never the control, since a hostile copy could skip its own check.
   - The verdict pastes the exact `rerun:`, `tree:`, `scanned:` (with its skip counts), `helper-sha256:` and `trust:` lines and the `claim-sweep exit:` value; they carry no machine path by construction, so a public-repo post is not refused for them. The `rerun:` line is for pasting into bash from the tree root. Exit 0 means no normalised match was found, never proof that the claim is gone: the verdict says so, and a claim that could be written with a non-breaking space, a zero-width character or emphasis markers needs a pattern for that spelling too. Never eval a `rerun:` line pasted by another party (the PR author, a worker, another reviewer): rebuild it from its patterns, passed after `--` to your own private copy by the procedure above. A claim-gone assertion with no pasted command, or one resting on exit 2, is could-not-check under clause 5, never an approval. Pasting the result without the command does not meet the bar.
