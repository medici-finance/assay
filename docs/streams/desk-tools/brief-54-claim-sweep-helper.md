## Task
1. **Write `plugins/assay/scripts/claim-sweep.sh` (planned)** (bash plus POSIX awk; must run under bash 3.2 on macOS and under GNU tools; mode 100755). Interface:
   - `-e PATTERN` / `--pattern PATTERN`, repeatable; every argument after a bare `--` is also a pattern, so a pattern may begin with `-`. At least one pattern is required. Each pattern is a fixed string, not a regex, and is only ever compared as data: never evaluated, never passed to a shell or to `awk -v` unescaped.
   - `--tree DIR`, default the git top level of the current directory. DIR must BE a work tree's top level: when `git -C DIR rev-parse --show-prefix` prints anything (DIR is a subdirectory), the helper exits 2 with a reason naming the top level. The test is that prefix being empty, never a comparison of path strings (on macOS `/var` is a symlink, so one temporary directory has two spellings). A subdirectory is never silently widened or narrowed, because a partial sweep would read as "gone from the tree" and the rerun line sweeps `--tree .` from the root. Scans every tracked file (`git -C DIR ls-files -z`), reading the working-tree contents so an uncommitted fix is seen. It never follows a symlink, so it cannot read outside the tree: an entry that is a symlink, a submodule (gitlink) or anything else that is not a regular file is skipped and counted as non-regular. A tracked file deleted in the working tree has no contents to sweep: it is skipped and counted as non-regular too, and it makes the `tree:` line read uncommitted changes. Binary files (NUL byte in the first 8 KiB) are skipped and counted.
   - `--pr-body FILE`, optional: also scans FILE; hits report as `pr-body:<line>`.
   - `--case-sensitive`; the default is case-insensitive.
   - `--trust-repo DIR`, optional: DIR is an Assay source checkout. Before sweeping, the helper reads the blob `refs/remotes/origin/main:plugins/assay/scripts/claim-sweep.sh` with `git -C DIR cat-file blob` and compares its sha256 with the sha256 of the script file that is running. On a mismatch, or when the ref or the blob cannot be read, it exits 2 (could-not-check) and prints no `rerun:` line, so no verdict can rest on it either way. `--trust-repo` is a defence-in-depth convenience, the second layer: it catches an accidental stale, unpushed or locally edited copy, never a hostile one, because a self-check run by the code being checked is not a control. The control is clause 8's pre-run hash of a private copy, done by the reviewer before that copy is executed; for the printed `helper-sha256:`, anyone holding an Assay checkout with `refs/remotes/origin/main` fetched can recompute it from that blob and compare.
   - Normalisation, applied to the scanned text and to each pattern the same way: per line, strip leading whitespace and then any leading comment or quote markers (`//`, `#`, `>`, `*`, `--`, `;`) and the whitespace after them, repeating until none is left (so normalising an already normalised pattern changes nothing); join the lines of a file with one space; collapse every run of whitespace to one space. The bidirectional controls and the invisible code points listed below are deleted from the scanned text before matching, so a claim written with a zero-width space, a soft hyphen or a joiner inside it matches the plain pattern. Each match reports `<path>:<line>` of the ORIGINAL line where the match starts, `<path>` relative to the tree root, and which pattern matched. Every path the helper prints in a `hit:` line is escaped so it stays on its own output line: a newline is printed as `\n`, a tab as `\t`, a backslash as `\\` and any other control byte (0x00-0x1F, 0x7F) as `\xHH`, and any byte from 0x80 up that is not part of well-formed UTF-8 as `\xHH` too; the UTF-8 encodings of the display code points, which are the C1 controls U+0080-U+009F, the line and paragraph separators U+2028 and U+2029, the bidirectional controls U+061C, U+200E, U+200F, U+202A-U+202E and U+2066-U+2069, and the invisible code points U+00AD (soft hyphen), U+200B-U+200D (zero-width space, non-joiner and joiner), U+2060-U+2064 (word joiner and invisible operators), U+FEFF (zero-width no-break space) and the tag block U+E0000-U+E007F, print as `\uXXXX`, or, for the tag block, which lies beyond U+FFFF, as `\U` followed by eight hex digits (U+E0041 prints as `\U000e0041`), so a page that renders the output can neither draw them as line breaks, reorder or restyle a hit line, nor hide text inside one. Hex digits are lowercase. A tracked file name can therefore never forge a `trust:`, `helper-sha256:` or `rerun:` line. Every other non-ASCII character prints as itself. Patterns are never escaped. Instead, a pattern containing any control byte (0x00-0x1F or 0x7F, newline and tab included), any display code point listed above, or a byte sequence that is not well-formed UTF-8 is refused before anything is swept: exit 2, with a reason naming it by its index (`pattern 2`). A pattern that normalises to the empty string (only markers or whitespace, such as `--`, `#` or a space) is refused the same way, since an empty pattern matches everywhere or nowhere depending on the awk. The same refusal applies to the `--pr-body` name the rerun line would print. Every printed pattern is therefore already one line; write a wrapped claim with spaces, which normalisation matches across line breaks anyway. Every other well-formed UTF-8 character passes through as text. The display refusal is by code point, never by byte: refusing the bytes 0x80-0x9F would refuse every non-ASCII letter, since UTF-8 continuation bytes lie in that range. Refusing an invisible code point in a pattern costs no match: the sweep deletes them from the scanned text, so the same pattern written without them matches every spelling that carries them, including an emoji sequence joined by U+200D, a flag built from tag characters, and a word split by a soft hyphen. Known misses, stated in the usage text: a non-breaking space or emphasis markers (`*`, `_`, `` ` ``) inside the claim are not normalised, so a claim written with them is not matched. Exit 0 therefore means "no normalised match", never proof that the claim is gone.
   - Output: one `hit: <pattern> <path>:<line>` line per match; then `scanned: <N> files, skipped: <M> binary, <K> non-regular`; `trust: matches refs/remotes/origin/main` when `--trust-repo` passed, else `trust: unchecked`; `tree: <HEAD sha> (<clean or uncommitted changes>)`, where uncommitted changes means a tracked file differs from `HEAD`, a deleted tracked file included (untracked files are never swept and never counted); `helper-sha256: <hex>`, the sha256 of the script file that actually ran, computed by the script over its own resolved path (`$0`, with `sha256sum`, else `shasum -a 256`); and a final `rerun: <command>` line. The helper never tries to name its copy by git commit or plugin version: the hash is the identity, and anyone holding an Assay checkout with `refs/remotes/origin/main` fetched can recompute it from that blob and compare. The rerun line is PORTABLE and carries no absolute path: it names the helper by its bundle-relative path through a required variable, `bash "${ASSAY_BUNDLE:?set to a bundle root whose scripts/claim-sweep.sh has the helper-sha256 above}/scripts/claim-sweep.sh"`, sweeps `--tree .` (it is run from the tree's root), carries `--trust-repo "${ASSAY_SOURCE:?set to an Assay checkout with refs/remotes/origin/main fetched}"` when the run used `--trust-repo`, prints each pattern in its normalised form, and quotes every value it prints in POSIX single quotes with no other escaping (each value wrapped in `'...'`, each embedded `'` written as `'\''`; never bash `printf %q`, which on bash 3.2 leaves a leading `~` unescaped), with the patterns printed after a bare `--` so a leading `-` is never read as a flag, and gives `--pr-body` as the body file's path relative to the tree root when it lies inside the tree, otherwise as its bare file name (the `pr-body:` summary line then says the body must be re-fetched to that name). Because every value is single-quoted, evaluating the line in sh, bash or zsh can never run or expand anything spelled inside a pattern (`$(...)`, a backtick, `;`, a leading `~` or `=`), whatever the claim text says. Pasted into bash from the tree root with `ASSAY_BUNDLE` set, it reruns the same sweep; with `ASSAY_BUNDLE` unset it fails loudly instead of running something else.
   - Exit codes: 0 = no pattern found anywhere; 1 = at least one hit; 2 = could-not-check (no pattern given, a pattern or the printed `--pr-body` name contains a control byte, a display code point or malformed UTF-8, a pattern normalises to empty, DIR is not a git work tree or is a subdirectory of one, the PR-body file cannot be read, zero files were scanned, `helper-sha256` cannot be computed for any reason (neither `sha256sum` nor `shasum` is available, the tool fails, or its result is empty), or `--trust-repo` was given and the hash does not match or the ref or blob cannot be read). Exit 2 prints a reason to stderr and never prints a `rerun:` line that would read as a clean result.

It must include at least these 37 cases, by these names, every one of which Verify 1 checks: `wrapped-markdown-line`, `comment-continuation`, `blockquote-continuation`, `tabs-and-runs`, `case-insensitive-default`, `case-sensitive-flag`, `absent-claim-exits-0`, `uncommitted-fix-seen`, `pr-body-hit`, `two-patterns-reported-separately`, `binary-file-skipped-and-counted`, `newline-in-file-name-escaped` (a tracked file whose name contains a newline followed by `rerun: ` and `trust: ` text, and which holds the pattern: the output has exactly one `rerun:` line and one `trust:` line, and the hit line shows the name with `\n`), `symlink-and-non-regular-skipped` (a tracked symlink pointing at a file outside the tree that contains the pattern gives no hit and is counted as non-regular), `no-pattern-exits-2`, `not-a-git-tree-exits-2`, `subdirectory-tree-exits-2` (asserts the refusal by `git rev-parse --show-prefix` being non-empty, never by comparing path strings), `missing-pr-body-exits-2`, `helper-sha256-matches-file` (the printed `helper-sha256:` equals an independent sha256 of the script file, and a copy with one byte changed prints a different value), `rerun-line-reproduces` (evals the printed `rerun:` line from the tree root with `ASSAY_BUNDLE` set and compares its hits and exit code with the first run), `rerun-line-has-no-machine-path` (runs with an absolute `--tree` and an absolute `--pr-body` outside the tree and asserts the `rerun:` line contains neither path and no token beginning with `/`), `rerun-line-hostile-patterns-inert` (patterns containing `'`, `"`, `$(touch SENTINEL)`, a backtick, `;`, a backslash, a leading `-`, a leading `~` (`~root`) and a leading `=` (`=cmd`), each planted in the tree;
