## Task
1. **Write `plugins/assay/scripts/claim-sweep.sh` (planned)** (bash plus POSIX awk; must run under bash 3.2 on macOS and under GNU tools; mode 100755). Interface:
   - `-e PATTERN` / `--pattern PATTERN`, repeatable, at least one required. Each pattern is a fixed string, not a regex.
   - `--tree DIR`, default the git top level of the current directory. DIR must BE a work tree's top level: when `git -C DIR rev-parse --show-prefix` prints anything (DIR is a subdirectory), the helper exits 2 with a reason naming the top level. The test is that prefix being empty, never a comparison of path strings (on macOS `/var` is a symlink, so one temporary directory has two spellings). A subdirectory is never silently widened or narrowed, because a partial sweep would read as "gone from the tree" and the rerun line sweeps `--tree .` from the root. Scans every tracked file (`git -C DIR ls-files -z`), reading the working-tree contents so an uncommitted fix is seen. Binary files (NUL byte in the first 8 KiB) are skipped and counted.
   - `--pr-body FILE`, optional: also scans FILE; hits report as `pr-body:<line>`.
   - `--case-sensitive`; the default is case-insensitive.
   - Normalisation, applied to the scanned text and to each pattern the same way: per line, strip leading whitespace and then any leading comment or quote markers (`//`, `#`, `>`, `*`, `--`, `;`) and the whitespace after them; join the lines of a file with one space; collapse every run of whitespace to one space. Each match reports `<path>:<line>` of the ORIGINAL line where the match starts, and which pattern matched.
   - Output: one `hit: <pattern> <path>:<line>` line per match; then `scanned: <N> files, skipped: <M> binary`; `tree: <HEAD sha> (<clean or uncommitted changes>)`; `helper-sha256: <hex>`, the sha256 of the script file that actually ran, computed by the script over its own resolved path (`$0`, with `sha256sum`, else `shasum -a 256`); and a final `rerun: <command>` line. The helper never tries to name its copy by git commit or plugin version: the hash is the identity, and anyone can check it by hashing the `refs/remotes/origin/main` copy or a release's copy. The rerun line is PORTABLE and carries no absolute path: it names the helper by its bundle-relative path through a required variable, `bash "${ASSAY_BUNDLE:?set to a bundle root whose scripts/claim-sweep.sh has the helper-sha256 above}/scripts/claim-sweep.sh"`, sweeps `--tree .` (it is run from the tree's root), shell-quotes every pattern, and gives `--pr-body` as the body file's path relative to the tree root when it lies inside the tree, otherwise as its bare file name (the `pr-body:` summary line then says the body must be re-fetched to that name). Pasted from the tree root with `ASSAY_BUNDLE` set, it reruns the same sweep; with `ASSAY_BUNDLE` unset it fails loudly instead of running something else.
   - Exit codes: 0 = no pattern found anywhere; 1 = at least one hit; 2 = could-not-check (no pattern given, DIR is not a git work tree or is a subdirectory of one, the PR-body file cannot be read, zero files were scanned, or neither `sha256sum` nor `shasum` is available to hash the helper). Exit 2 prints a reason to stderr and never prints a `rerun:` line that would read as a clean result.
2. **Write `plugins/assay/scripts/claim-sweep.test.sh` (planned)** in the bundle's suite style (temporary git repos under `${TMPDIR:-/tmp}`, `--case <name>` to run one case, final `<N> passed, <M> failed`). It must include at least these 19 cases, by these names, every one of which Verify 1 checks: `wrapped-markdown-line`, `comment-continuation`, `blockquote-continuation`, `tabs-and-runs`, `case-insensitive-default`, `case-sensitive-flag`, `absent-claim-exits-0`, `uncommitted-fix-seen`, `pr-body-hit`, `two-patterns-reported-separately`, `binary-file-skipped-and-counted`, `no-pattern-exits-2`, `not-a-git-tree-exits-2`, `subdirectory-tree-exits-2` (asserts the refusal by `git rev-parse --show-prefix` being non-empty, never by comparing path strings), `missing-pr-body-exits-2`, `helper-sha256-matches-file` (the printed `helper-sha256:` equals an independent sha256 of the script file, and a copy with one byte changed prints a different value), `rerun-line-reproduces` (evals the printed `rerun:` line from the tree root with `ASSAY_BUNDLE` set and compares its hits and exit code with the first run), `rerun-line-has-no-machine-path` (runs with an absolute `--tree` and an absolute `--pr-body` outside the tree and asserts the `rerun:` line contains neither path and no token beginning with `/`), `offline-no-forge-calls` (runs with a PATH whose `gh`, `curl` and `git-remote-https` stubs fail loudly if called).
3. **Amend review-kit clause 8** (`review-prompt.md`): add one bullet stating that a verdict asserting a claim is gone from the tree (a false claim fixed, a stale phrase removed, a rename completed) names its instrument and makes it reproducible. It runs `claim-sweep.sh` from a trusted copy, never the PR head's (so a PR cannot edit the instrument that judges it). Trust order: (a) `$ASSAY_BUNDLE/scripts/claim-sweep.sh` when the variable is set; (b) the installed Assay plugin's `scripts/claim-sweep.sh` (planned), in the directory holding the plugin's `.claude-plugin/plugin.json`. Copy (a) or (b) is trusted ONLY when the `helper-sha256:` it prints equals the sha256 of the default branch's copy, `git show refs/remotes/origin/main:plugins/assay/scripts/claim-sweep.sh` hashed the same way. That closes the PR-head and unpushed-commit gap, and an installed plugin's version number proves nothing. (c) Otherwise, in an Assay source checkout, make a detached worktree of `refs/remotes/origin/main` in a fresh temporary directory (`d=$(mktemp -d)` then `git worktree add --detach "$d" refs/remotes/origin/main`), set `ASSAY_BUNDLE` to its `plugins/assay`, run the helper, and remove the worktree with `git worktree remove "$d"` afterwards. (d) No copy whose hash matches the default branch's, or no readable `refs/remotes/origin/main`: the claim-gone assertion is could-not-check. `CLAUDE_PLUGIN_ROOT` is not set in dispatched agents and is not a locator. The verdict pastes the exact `rerun:`, `tree:` and `helper-sha256:` lines; they carry no machine path by construction, so a public-repo post is not refused for them. A claim-gone assertion with no pasted command, or one resting on exit 2, is could-not-check under clause 5, never an approval. Pasting the result without the command does not meet the bar.
4. **Amend review-kit clause 9**: one sentence pointing the whole-diff and repository sweep at the same helper, with every phrasing of the claim the reviewer can name passed as a separate `-e`, and the patterns listed in the finding so the worker can reuse them.
5. **Amend both worker kits**: append to the `worker-prompt.md` §8 false-claim bullet, and add as a new bullet under `worker-prompt-objective.md` `### Scope and reporting`, the same sentence, byte-identical: before replying that a false-claim class is fixed, run the installed bundle's `claim-sweep.sh` with the reviewer's patterns (plus any phrasing you found) against your pushed tree, and paste its `rerun:` line in the finding reply; exit 1 means the class is not fixed yet, exit 2 means you could not check.
6. **Pin the kit text** with `tools/desk/cmd/deskdispatch/claimsweep_test.go` (planned), test `TestClaimSweepKitPin` (planned): for every lane in `reviewKitLanes()`, the rendered clause 8 body contains `claim-sweep.sh`, `rerun:`, `ASSAY_BUNDLE`, `helper-sha256:`, `refs/remotes/origin/main`, `git worktree remove`, the phrase `never the PR head` and the phrase `could-not-check`; the clause 9 body contains `claim-sweep.sh`; the worker sentence appears verbatim in both worker kits; and every flag the kit text names for the helper (`--pattern` or `-e`, `--tree`, `--pr-body`) is one the script's usage text names. Read the script from `../../../../plugins/assay/scripts/claim-sweep.sh` relative to the package directory.
7. **Changelog fragment** `changelog/desk-tools-54.md` (planned) describing the new helper and the clause 8 rule.
