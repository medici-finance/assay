# Assay CI and release performance

Repository CI baseline for November 17, 2026 UTC, measured against `bec90193ce916b2d5b11433f25970867a1b7ef95`. The release comparison covers October 19 through November 17 UTC. The three live workflow files were unchanged at review base `1a259b85f`.

The public repo spent **238.35 runner-hours in `ci.yml`**. The required `build-test` check finished last in all 138 successful PR runs. Batching two Go commands is the best verified way to reduce compute. Shortening the required check calls for a different change to its slowest shard. In the board workflow, check whether a PR changes findings before building the corroboration tool. For releases, isolate the bodycheck mutation sweep and diagnose the cache misses before spending more runner time on uploads. ## Compute changes, in reviewable order

1. **Batch the Windows test compilation.** The platform job launches `go test -c -o /dev/null` separately for every package. One invocation over the same verified, nonempty list compiled all 136 packages. Starting from two identical caches seeded by a successful Windows vet, serial took 91.67s wall and 237.88 CPU-seconds. Batch took 28.38s wall and 164.09 CPU-seconds. Packages with the same basename and packages without tests passed in both forms. A planted compile error still failed both with the same diagnostic, and test bodies stayed unexecuted. Keep the Windows and Darwin vet commands. The entire hosted compile-and-vet step occupied 19.56 hours. Only its Windows compile portion was benchmarked. [Workflow command](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/ci.yml#L167-L175)
2. **Batch the stamped executable builds.** CI starts a separate `go build` for each desk executable. The release workflow already builds the commands into an output directory in one invocation. With identical source and fresh timestamp stamps and two copies of the same initial cache, all **72 Linux/amd64 filenames and SHA-256 hashes matched**. Wall time went from 50.62s to 10.23s and CPU from 93.44s to 50.66s. Retain full module discovery, the other builds and the exact stamp flags. The hosted Unix step, which includes those other builds, occupied 10.96 hours. Both local Go experiments used Go 1.27.4 on macOS arm64. Neither auxiliary job was the last-finishing job on a successful PR that day. [CI build](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/ci.yml#L594-L614) · [Existing release build](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/release.yml#L1306)
3. **Check for a findings diff before installing Go and `gh` or compiling the guard.** All 288 successful corroboration attempts explicitly logged that no findings entries changed. Their three setup steps occupied **9,308 runner-seconds, or 2h35m08s**. The three failed attempts receive zero savings credit. Run the existing checked `HEAD^1..HEAD` path diff immediately after verifying the base. A diff read error still fails. A matching change still uses the trusted base build, checksum-verified tools, live base check, and the original guard. In a same-run replay, keeping sibling finish times fixed, median board PR feedback moved only from 166s to 165s because lint usually finished later. [Observed job](https://github.com/medici-finance/assay/actions/runs/43984115622/job/133707739190) · [Base check and guard](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/assay-statusgen.yml#L189-L280)

Derive or test the scope against the full local replacement set, compare NUL-delimited paths, and run the compile for empty or unreadable changes. ## Required-check feedback

The last dependency of `build-test` was the `rest` shard in **85 of 138** successful PR runs, `desk-3` in 35 and `desk-1` in 18. `rest` used 54.11 runner-hours and ran statusgen test/vet sequentially with the all-module sweep. A replay moved statusgen's skew-baseline fetch and full test/vet step into a separate required job, kept every other finish time and the aggregator delay fixed, and charged the new job the observed setup and cleanup time from that run. With simultaneous runner availability, median feedback fell from **14m10s to 12m56s**, and p90 from **17m38s to 14m59s**. Adding 90s of queue delay to the new job yielded a 13m17s median. Duplicated setup added 25m15s over the 138 PRs in the model. Cold-build costs and shared-runner contention require a hosted comparison before rollout. Add the job explicitly to the aggregator and leave the desk matrix cardinality alone, because it defines the desk partition count. [Rest shard](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/ci.yml#L177-L245) · [Example job](https://github.com/medici-finance/assay/actions/runs/43984115616/job/133707738662)

Refreshing the existing package weights is a smaller experiment. In six successful PRs spaced across the day, `internal/reviewtest` had a median reported runtime of 355.8s against its configured 50.6s. Weights trained on the first three runs reduced the maximum sum of package durations by 2.9%, 17.4% and 8.5% on the other three, preserving the 136-package partition. Go can execute packages concurrently, so these percentages describe balance and do not establish changes in runner time. ## Post-merge statusgen history

The public repo builds its own statusgen binary. A qualifying push renders the board, runs `--record` to append lifecycle transitions, and independently checks model auto-flips. Hourly reconciliation uses trailer-only `--apply`. There is no `reconcile --backfill` invocation on this path. Of 77 board push runs, 33 completed successfully, 43 were cancelled and one skipped. The cancelled runs had no allocated job with recorded steps in the dataset. The 33 successful regen jobs occupied **3h30m44s**, and their 33 auto-flip jobs occupied **57m17s**. [Push writer](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/assay-statusgen.yml#L326-L343) · [Hourly reconciliation](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/assay-statusgen.yml#L854-L866)

**Share board validation between the write and the historian.** At the inspected main commit the existing write took 89.95s locally, and the immediately following `--record` took another 77.49s. Every one of the write’s 3,934 native Git invocations recurred in the second command. A prototype performed the shared work once, wrote the views, and then invoked the original history and DORA functions. The full sequence fell from **167.44s to 83.02s**, CPU from **174.44s to 86.87s**, and Git invocations from **7,869 to 3,935**. Both variants exited successfully. The five compared file results and combined stdout matched, and duplicate diagnostic notices appeared once. Both variants changed `STATUS.md` and `FINDINGS.md` from their starting bytes. The current push publishes `STATUS.md` and lifecycle history. The equal-input replay fixed the clock and used the same six public approval and issue responses. Both variants reported the two DORA reads unavailable and produced no timing file. Existing tests for first history, a real transition and idempotence passed. A separate positive fixture ran the real CLI, recorded one restore episode and one PR lead time, and produced identical stdout and all seven files under both implementations. A repeat appended zero records. Before enabling this mode, exercise an actual main-advance retry, keep recording after successful output writes, and compare the hosted writer step. [Writer and recording sequence](https://github.com/medici-finance/assay/blob/bec90193/.github/workflows/assay-statusgen.yml#L326-L343) · [Recorder entry point](https://github.com/medici-finance/assay/blob/bec90193/statusgen/main.go#L1026-L1048)

**Keep the lifecycle historian and skip the public writer’s unpublished DORA collection.** All 33 regen logs showed at least one append to `.dora-timing.jsonl`. Across initial runs and retries, 37 appends reported 3,253 records and 27 passes found no new records. Those are append counts across temporary checkouts, not distinct observations. The 64 timed DORA passes occupied **29m35s** inside the recorder. DORA reads recent workflow runs and merged PRs, then requests commit details for unseen PRs. The public writer intentionally stages only `STATUS.md` and `.history.jsonl`. Add an explicit DORA-only opt-out on both the initial and retry paths, keep the default for adopters that publish timing history, and verify equivalent status history with zero DORA requests. ## Release CI

The release workflow ran 70 times from October 19 through November 17 UTC. All were dispatches. Six had a second attempt. Across all 76 attempts, **922 allocated jobs consumed 91.10 runner-hours**. The publication step confirmed 38 successful publishes, the dry-run stop confirmed 15 successful rehearsals, seven runs failed and ten were cancelled. Median dispatch-to-completion was **74m53s for a successful publish** and **51m32s for a successful rehearsal**. That elapsed time includes queueing, approval waits, and any rerun delay. [Release workflow](https://github.com/medici-finance/assay/blob/1a259b85f/.github/workflows/release.yml) · [Example publication](https://github.com/medici-finance/assay/actions/runs/44178215778)

For decisions about the current pipeline, I compared the 11 successful publications whose source contains the November 6 ARM64 artifact-compression change. The mutation job `test (muhar-light)` finished last among the test jobs in **10 of 11**. Its median duration was 23m21s. The sequential artifact-preparation job took 15m54s, native ARM64 qualification 2m25s, and the protected publisher 27m23s. A median **35m39s** elapsed between native ARM64 completion and publisher allocation. Actions job timestamps cannot divide that interval into approval and queue time. [Compression change](https://github.com/medici-finance/assay/commit/847d5cee6) · [Native qualification and protected publisher](https://github.com/medici-finance/assay/blob/1a259b85f/.github/workflows/release.yml#L1578-L1656)

1. **Split the bodycheck mutation sweep from the other `muhar-light` checks.** Bodycheck alone took a median 14m46s. On each release, I moved its measured time to a sibling starting alongside the existing job, charged the new job the original checkout, Go install, report upload and cleanup, then took the latest finish across both jobs, the other tests and the guard. The median improvement to artifact eligibility was **5m40s**. With downstream durations and waits fixed, the median dispatch-to-completion moved from **1h49m19s to 1h45m53s**. The extra job adds 2m31s of modeled setup across all 11 releases, before cold-cache or runner contention. This matrix split was previously bundled with a transport and runner migration that was reverted. Trial just the independent test leg on the current runner. Preserve baseline and positive controls, failure on surviving or unapplied mutations, report names and the evidence pack consumed by `artifacts`. The complete test matrix must still pass before publication. [Test matrix and bodycheck](https://github.com/medici-finance/assay/blob/1a259b85f/.github/workflows/release.yml#L512-L532) · [Mutation report gate](https://github.com/medici-finance/assay/blob/1a259b85f/.github/workflows/release.yml#L673-L695) · [Earlier revert](https://github.com/medici-finance/assay/commit/0ea3de716)
2. **Measure why the release Go cache never restored in that cohort.** All 11 artifact-job logs explicitly reported `cold build (Miss)`. All 11 successfully saved a new cache and recorded its receipt. Restore, pack and upload occupied **22m10s** across those jobs, including 15m03s spent on packing and uploading. Seven runs had a plausible earlier completed producer among the previous five successes with matching workflow and cache-reader source, ancestry and a recent save. That checks only part of the reader’s contract. The logs do not disclose which requirement rejected each candidate. Record aggregate counts by a fixed rejection category, without printing remote responses or credentials. Compare a validated warm restore with a cold build of the same source and toolchain, including transfer costs. Suspend saves if the transport remains slower than building cold. Preserve source, receipt, digest, expiry, inventory and extraction validation. Release already batches the desk builds. To reproduce the release baseline, enumerate `release.yml` runs created in the UTC window, retrieve the jobs for **every numbered attempt**, then sum `completed_at − started_at` only for assigned jobs with steps. Classify publish and dry-run from the actual final steps. Use run creation to final update for feedback and the job finish times to replay the prerequisites. This keeps cancelled work and time waiting for publication visible separately.
