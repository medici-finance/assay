# v1.0.0 — brief-v2 flag day + the bundle version boundary

v1.0.0 is the first MAJOR release. It ships the brief-v1 → brief-v2 schema flag
day and the tooling-bundle version boundary. The adopter-facing "what changed" is
the body of the migration that carries you across it —
`migrations/0001-v0.13.0-to-v1.0.0-derived-board.md`, reproduced here so the
release note and the migration never drift.

Preview it against your own tree before you consent:

    upgrade-assay --root . --to v1.0.0 --dry-run

---

## What changed

**v1.0.0 is the first MAJOR — the brief-v1 → brief-v2 flag day.** A hand-edited
surface (the lifecycle cell of every stream README's Briefs table) becomes a
*generated* surface. That is a contract-breaking change, so it is a major version
with a migration you can dry-run, not a release note you have to read and apply by
hand.

This migration does three things to your tree, idempotently:

1. **Rewrites every `schema: brief-v1` brief to `schema: brief-v2`.** Each brief's
   `brief:` id becomes the hierarchical `<cell>:<repo>:<stream>:<NN>` form,
   resolved against `docs/streams/graph-repos.yaml` — so **you must write that
   alias registry first**. A brief with no `version:` gets `version: 1`; a brief
   with no `id:` gets a freshly minted uuid v4 (minted ONCE, here — a uuid added
   later is a uuid with no history).

2. **Wraps each stream README's Briefs table** in the generated-region markers
   (`<!-- statusgen:briefs:begin -->` / `<!-- statusgen:briefs:end -->`) and adds
   `board: generated` to its frontmatter. From now on the table's authoring
   columns are regenerated by `statusgen regen --readmes`; a hand edit to the
   region is a `statusgen --lint` PROBLEM.

3. **Records the step** in `docs/UPGRADING.txt` — the append-only per-adopter log
   of applied migrations (created if absent). It is your local record of which
   migrations have run against this tree.

### The trailer you must now write

Under brief-v2 a PR's lifecycle cell is DERIVED, not asserted: statusgen reads it
back from the `Brief:` trailer on the PRs that touched each brief. Every PR that
implements a brief must carry a trailer naming it, e.g.:

    Brief: derived-board/06

`deskpr create` writes it for you; a hand-opened PR must add it, or the brief's
row cannot be reconciled from PR history.

### The reconcile step you must add to your board workflow

The generated table's LIFECYCLE columns (Status / Verified / Reviewed) are folded
in from PR history by `statusgen reconcile --backfill`, which needs a GitHub read.
Add it to the workflow that regenerates your board, AFTER `regen --readmes`:

    - name: Reconcile lifecycle cells from PR history
      run: statusgen reconcile --backfill --root .
      env:
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

It produces a drift report (`hand-said` vs `derived`, per row) for a human to read
before it lands. Until you add it, the authoring columns regenerate but the
lifecycle columns are only carried through, not reconciled.

### Version pinning

statusgen and desk-tools are cut together at v1.0.0. Pin BOTH to the same tag in
`.assay-versions` — `statusgen --lint` now PROBLEMs a pin file whose artifact tags
differ (one tag, one tree), and a brief-reading desk tool below v1.0.0 refuses a
brief-v2 tree outright, pointing you here.
