# v0.0.0-fixture — worked example for `--export-audit-pack`

This is not a real release. `v0.0.0-fixture` names no git tag, ships no binary, and is cited
by no changelog. It exists only so `statusgen --export-audit-pack --release v0.0.0-fixture`
has a small, self-contained, always-on-disk scope to demonstrate the release-keyed audit-pack
format against (sdlc/08's Task item 4 — "a worked example committed as a fixture").

Its scope is exactly the two entries above:

- `briefs: ["audit-pack-example/01"]` — the one fixture brief in
  [`docs/streams/audit-pack-example/`](../streams/audit-pack-example/README.md).
- `requirements: ["REQ-apfixture-ok", "REQ-apfixture-unresolved"]` — the fixture requirements
  in [`docs/streams/requirements/`](../streams/requirements/apfixture-ok.md), one of which
  resolves cleanly and one of which ([`apfixture-unresolved.md`](../streams/requirements/apfixture-unresolved.md))
  deliberately does not, so the pack's three-state handling has a real could-not-check chain
  to report without running a real release.

See [`docs/evidence-bundle.md`](../evidence-bundle.md)'s release-keyed section for the pack
format itself.
