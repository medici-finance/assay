## What changed

Since the brief-v1 → brief-v2 flag day, `statusgen --verify-issues` emits the
brief-v2 key form (`<org>:<alias>:<stream>:<NN>[a]`) in the `<!-- verify-gate: … -->`
marker it writes onto a verify-gate issue. An adopter's copy of
`verify-gate-close.yml` that still validates the marker against only the legacy
`<stream>/<NN>[a]` grammar rejects every human close of such an issue with "no
brief advanced" — the brief never reaches `done` (this repo's #804).

This release's `statusgen` treats both forms as one identity everywhere it reads
a brief id, but that does not reach the workflow: the workflow's own grammar
check runs BEFORE statusgen is ever invoked, as a defense-in-depth guard against
an untrusted issue body. So an adopter's copy of the workflow file must be
patched independently — statusgen alone does not fix this.

**This migration cannot patch the workflow for you.** The migration runner has
no file-patch operation (only `ensure-line` and `statusgen-regen` exist); a
workflow file is CI configuration, and no App or bot token can push to it (no
token here carries the `workflows` scope by design). So this step only records,
in `docs/UPGRADING.txt`, that the patch is owed, and prints this note as the
release note for the v1.0.6 → v1.0.7 span. Applying the patch itself is a
human-with-push-rights action.

### The patch to paste

Open your copy of `.github/workflows/verify-gate-close.yml` and find the block
that extracts `$brief` from the marker, the `if [ -z "$brief" ]; then … fi` empty
check, and the grammar check `if ! printf '%s' "$brief" | grep -qE '^[a-zA-Z0-9_-]+/[0-9]+[a-z]?$'; then`.
Insert this normalisation immediately after the empty check and before the
grammar check (adapt indentation to your file):

```sh
          # The marker may carry either grammar: the legacy <stream>/<NN>[a]
          # form (statusgen's brief name regexp), or the brief-v2 key
          # <org>:<alias>:<stream>:<NN>[a] that statusgen --verify-issues now
          # emits. Normalise the v2 form to the legacy one BEFORE the grammar
          # check below, so every use past this point sees exactly one shape
          # and the existing validation still runs against whatever ends up in
          # $brief, normalised or not.
          if printf '%s' "$brief" | grep -qE '^[a-zA-Z0-9_-]+:[a-zA-Z0-9_-]+:[a-zA-Z0-9_-]+:[0-9]+[a-z]?$'; then
            brief=$(printf '%s' "$brief" | awk -F: '{print $3 "/" $4}')
          fi
```

Also extend the rejection message's text to name both accepted forms, e.g.
"Extracted brief id is not a valid `<stream>/<NN>` id (nor the
`<org>:<alias>:<stream>:<NN>` brief-v2 form); no brief advanced."

### Proving the patch

If you also copy this repo's fixture test
(`.github/scripts/verify-gate-close-extract.test.sh`, which mirrors the
workflow's exact extraction + normalisation + grammar shell in one function),
run:

    bash .github/scripts/verify-gate-close-extract.test.sh

7 cases must pass: a legacy-form marker, two brief-v2-form markers (one from
this repo's own cards, one from a consumer alias), a legacy form with a letter
suffix, and three rejected payloads (path traversal, shell metacharacters, and
a malformed brief-v2 key missing its trailing segment).

### Caveats

1. **No App or bot token can push a workflow file.** Every write path this
   methodology uses for briefs, PRs and issues runs through a role token
   scoped away from `workflows` on purpose; only a human with that scope on
   their own account can land this patch, by hand or through a normal
   human-authored PR.
2. **A verify-gate close that already failed on the unpatched workflow must be
   re-driven, not just retried.** Once the patched workflow is on the default
   branch, reopen the affected verify-gate issue and close it again; closing
   is what triggers the workflow run that advances the brief. There is no
   step that repairs an already-failed run in place.
