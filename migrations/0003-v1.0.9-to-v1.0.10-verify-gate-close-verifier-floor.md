## What changed

A human `done` close on a `gate: human` brief now needs a **floor-tier re-verify
stamp** in the Verified cell first — the **two-stamp model**. The routine verify
drain may run at the local model tier and flip `implemented → verified` (first
stamp); before the human closes the sign-off card, ONE re-verify at a runner that
clears the methodology/19 verifier floor re-runs the table, appends its Evidence
rows, and re-stamps the Verified cell with that pass leading the cell (second
stamp). Model-gated briefs are unchanged.

The defect this closes: the close workflow (`verify-gate-close.yml`) grepped only
the README row and never checked the Verified cell's runner against the floor, so
a human close of a card whose cell (or whose Evidence, on the implemented→done
path that stamps the cell FROM the Evidence) named a below-floor runner landed a
`done` flip on `main` that the same release's `statusgen --lint` then reddened —
after the human had already signed (this repo's #1170).

This release's `statusgen --close-verify` makes the read itself: it applies the
same two floor predicates `--lint` applies at `done` to the cell it is about to
write and to the brief file's Evidence rows, and REFUSES (no write) with a line
that names the runner, the floor and the remedy, always carrying the literal
phrase `verifier floor`. That part reaches every adopter with the binary. What
does NOT reach you is the workflow's handling of that refusal: an unpatched copy
treats every first-attempt refusal the same way — one generic "statusgen refused
(it is not currently `verified` / `gate: human`)" comment and the card LEFT
CLOSED — so the human is told the wrong reason and has no card to close again
once the second stamp lands.

**This migration cannot patch the workflow for you.** As with migration 0002, the
migration runner has no file-patch operation and no App or bot token carries the
`workflows` scope; this step only records the owed patch in `docs/UPGRADING.txt`
and prints this note for the v1.0.9 → v1.0.10 span. Applying the patch is a
human-with-push-rights action.

### The patch to paste

Open your copy of `.github/workflows/verify-gate-close.yml` and find, inside the
`for attempt in 1 2 3 4 5; do` loop of the "Advance the brief to done and push"
step, the first-attempt refusal handler — the block that begins with the comment
`# First attempt refusal, not already-done: genuine bad state` and posts the
"Could not advance … statusgen refused" comment. Insert this branch immediately
BEFORE it, after the `if [ "$attempt" -gt 1 ]; then … fi` retry check (adapt
indentation to your file):

```sh
              # Verifier-floor refusal (two-stamp model): statusgen read the
              # Verified cell the done row would carry (README cell, or the cell
              # the implemented→done path stamps from the brief's Evidence) plus
              # the Evidence rows, and found a runner below the methodology/19
              # floor. Relay statusgen's own line (runner + floor + remedy) onto
              # the card, REOPEN it so the same human can close it again once
              # the floor-tier re-verify stamp has landed, and commit nothing.
              # $out is written to a body FILE via printf '%s', never
              # interpolated into a script line.
              if printf '%s' "$out" | grep -q 'verifier floor'; then
                body_file="${RUNNER_TEMP}/verify-gate-floor-refusal.md"
                {
                  printf '%s\n\n' "verify-gate close REFUSED for \`$brief\` — its Verified cell is below the verifier floor (methodology/19, two-stamp model). Reopened; no change committed."
                  printf '%s\n%s\n%s\n\n' '```' "$out" '```'
                  printf '%s\n' "Remedy: re-verify at a floor-tier runner (a strong-tier model or a confirmed human), append its Evidence rows, re-stamp the Verified cell \`YYYY-MM-DD <runner>\` with that pass leading the cell, then close this card again."
                } > "$body_file"
                gh issue reopen "$ISSUE" --repo "$REPO"
                gh issue comment "$ISSUE" --repo "$REPO" --body-file "$body_file"
                echo "::error::close-verify refused for $brief — Verified cell below the verifier floor; card reopened, nothing committed"
                exit 1
              fi
```

The enforce step (allowlisted human, bot close reopened) and the `status is
"done"` replay handling are unchanged; the floor branch only ever runs for a
close the enforce step already admitted. The workflow's default `GITHUB_TOKEN`
already carries `issues: write`, which is all `gh issue reopen` needs.

### Proving the patch

If you also copy this repo's fixture test
`.github/scripts/verify-gate-close-floor.test.sh` (it mirrors the workflow's
refusal classification — same `--close-verify` command, same greps, same order —
plus the enforce step's allowlist normalisation) together with the fixture tree
`statusgen/testdata/verifyfloor/`, run, with a Go toolchain on PATH:

    bash .github/scripts/verify-gate-close-floor.test.sh

4 cases must pass: an allowlisted human closing a card whose Verified cell is a
local-tier (below-floor) stamp is `floor-refused` (row untouched); the same close
after a floor-tier re-stamp leads the cell is `flipped` (row `done`); an
`implemented` card whose only recorded pass is below the floor is
`floor-refused`; a card whose cell clears but whose Evidence rows were only ever
run below the floor is `floor-refused`. Against a statusgen built from the
previous release the first, third and fourth cases report `flipped` — that is
the defect.

### Caveats

1. **No App or bot token can push a workflow file** — same as migration 0002;
   only a human with the `workflows` scope on their own account lands this.
2. **A card the unpatched workflow refused stays CLOSED with the wrong reason.**
   Once the patched workflow is on the default branch, land the floor-tier
   re-verify stamp on the brief, reopen the card by hand, and close it again;
   closing is what triggers the run that advances the brief.
3. **The floor read is in the binary, not the workflow.** An adopter on this
   release's `statusgen` with an UNPATCHED workflow already gets the refusal (no
   red `done` lands); what the patch adds is the correct comment and the reopen.
4. **The verifier floor still reads `verified` rows.** A local-tier first stamp
   landed on a risk-flagged brief is a `--lint` PROBLEM naming the same two-stamp
   remedy until the second stamp lands; the row is waiting, not wrong.
