## What changed

A GitLab adopter's `.gitlab-ci.yml` carries `statusgen/pushcred.sh` and
`statusgen/boardadd.sh` embedded verbatim, as the `.statusgen-pushcred` and
`.statusgen-boardadd` script anchors that `statusgen init --forge gitlab` wrote.
`statusgen init` never overwrites an existing file, and bumping the statusgen
pin changes only the binary, so every board-push fix shipped in `pushcred.sh`
since the scaffold (the http extraheader reset of #5012 among them) never
reached the pipeline. The board push kept going out as the CI job token and
GitLab refused it with a 403 (#5004).

`statusgen migrate gitlab-anchors` rewrites each embedded anchor that differs
from the pinned statusgen's copy, in place. The comment lines above each anchor,
every job and every other key in the file stay as they are. An anchor the file
no longer carries is left alone, and a file with neither anchor, or no
`.gitlab-ci.yml` at all, is a clean no-op. A second run changes nothing.

`statusgen --lint` and a re-run of `statusgen init` now name any embedded anchor
that differs from the running statusgen's copy, with this command, so the drift
cannot go unnoticed again.

## Upgrade steps

1. Install the new statusgen (the pinned release), then run
   `statusgen migrate gitlab-anchors --root . --dry-run` to see which anchors
   would change.
2. Run `statusgen migrate gitlab-anchors --root .`, review `git diff .gitlab-ci.yml`,
   and commit it. Only the two anchor blocks change.
